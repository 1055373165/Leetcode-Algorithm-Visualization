# 3. 无重复字符的最长子串

## 读者在面试中的解题思路

想象你坐在一家拉面店的传送带前。传送带上不断送来各种口味的小碟——抹茶、鳗鱼、三文鱼、抹茶……等等，又来了一碟抹茶？你面前的桌子只有一条长长的槽位，规则很简单：**槽位里绝对不允许出现两碟一模一样的东西**。每当传送带送来一碟新的，你就往槽右边放；一旦发现这碟和槽里某碟撞了，你就从槽的最左边开始清盘，一直清到把那碟"撞衫"的老家伙请走为止。在这个过程中，你随时留心你的槽里最多同时摆过几碟。这件事做完，答案就出来了。

这道经典面试题的核心直觉就藏在上面这个画面里：你永远不需要把整条槽清空重来。你只需要维护一个不断向右生长、偶尔从左边收缩的"窗口"——这就是滑动窗口。面试官问到这道题时，可以直接告诉他：我使用一个哈希表记录每个字符最后出现的位置，配合双指针维护一个无重复的滑动窗口。右指针不断右移来扩张窗口，每遇到重复字符内，左指针直接跳到上次出现位置的下一个，中间不做任何多余的遍历。整体时间复杂度 O(n)，空间复杂度 O(|Σ|)。

## 审题

题目要求在给定字符串 `s` 中，找出不含有重复字符的**最长子串**的长度。数据范围 $0 \le s.length \le 5 \times 10^4$，字符集包含英文字母、数字、符号和空格。

拿到这道题后，最先要关注的不是怎么做，而是"做不到的话会怎样"。如果暴力枚举所有子串再逐一检查是否有重复，三层循环下来是 $O(n^3)$，在 $5 \times 10^4$ 的量级下铁定超时。数据范围本身就是一条线索：它在暗示我们必须找到 $O(n)$ 级别的解法。再看"子串"二字——子串是连续的，不是子序列，这就为滑动窗口埋好了伏笔。

边界方面有几个容易忘的 case：空字符串返回 0；单字符返回 1；全部相同的字符（如 `"bbbbb"`）返回 1 而非 5。字符集虽然不限于 26 个字母，但可以用 ASCII 128 长度的数组或直接用哈希表来存，不影响整体复杂度。

## 暴力解法先行

在谈优化之前，我们先让暴力解法为我们"照亮问题的全貌"。最笨的思路就是固定一个起点 $i$，让终点 $j$ 从 $i$ 往右走，一边走一边把走过的字符扔进集合，碰到重复就停。然后换下一个起点 $i+1$，$j$ 又从这个新起点出发重头再来。每次检查子串内部是否有重复也要 $O(n)$，所以暴力的总复杂度是 $O(n^3)$。

暴力法的真正价值不在于代码本身，而在于它帮我们看到了浪费在哪里。比如字符串 `abcabcbb`，当 $i=0$ 时我们发现 `abc` 没有重复，到 `abca` 时出现了第二个 `a`。暴力法此时会把 $i$ 移到 1，$j$ 从 1 重新出发检查 `bc`……但这完全是多余的！因为 `bc` 本身就是上一轮窗口的子集，它必定没有重复。我们真正需要做的，仅仅是把左边那个 `a` 踢出去，保留 `bc`，然后让右边继续走就好了。

## 滑动窗口解法

一旦意识到"踢出左边重复字符"这个关键操作，两指针的思路就自然浮现了。我们维护一个窗口 $[left, right]$，配合一个哈希表 `pos` 记录每个字符最后一次出现的位置。右指针 `right` 一路往右走，每遇到一个字符，先查表看看这个字符有没有在当前窗口内出现过。如果出现过且位置 $\ge left$，就把 $left$ 直接跳到那个位置的下一位——这一步是这道题最精髓也最容易写错的地方。跳完之后更新该字符的最新位置，然后用 $right - left + 1$ 去和当前最优解比较，取大的那个。

为什么 $left$ 可以直接跳而不用一步步挪？因为哈希表帮我们记住了"那个重复字符上次出现的确切位置"。跳过去之后，窗口里就不存在任何和当前字符重复的元素了。这比一步一步左移要快得多，也是这道题和 209 题（最小长度子数组）的关键区别之一：209 题需要步步收缩来维护累加和，而这道题可以一步到位。

```go
func lengthOfLongestSubstring(s string) int {
	// pos 记录字符最后出现的位置
	// key: byte (ASCII), value: index
	pos := make(map[byte]int)

	var res int
	var left int

	for right, c := range []byte(s) {
		// 【核心】如果字符 c 在窗口内出现过 (idx >= left)
		// 左边界 left 直接跳到该字符上次出现位置的下一位
		if idx, ok := pos[c]; ok && idx >= left {
			left = idx + 1
		}

		// 更新字符位置
		pos[c] = right

		// 更新最大长度
		if w := right - left + 1; w > res {
			res = w
		}
	}

	return res
}
```

### 复杂度

- **时间复杂度**: $O(n)$。`right` 从头走到尾一次，`left` 只会往右跳不会回头，每个字符在哈希表中最多被读写各一次。
- **空间复杂度**: $O(|\Sigma|)$。其中 $|\Sigma|$ 是字符集大小。对 ASCII 来说最多 128 个键，可视为 $O(1)$。

### 易错点

第一个大坑是左边界更新条件。判断 `idx >= left` 不能省略。假设字符在位置 2 出现过一次，后来 `left` 已经推进到位置 5 了，这时在位置 8 又遇到同一个字符。如果不检查 `idx >= left`，你会把 `left` 从 5 倒退回 3——窗口往回缩是绝对不允许的，这会引入已经被排除的旧字符。第二个细节是窗口长度的计算公式是 `right - left + 1` 而不是 `right - left`。第三个是结果更新的位置：必须在每次右指针移动后就更新，不能等循环结束再取。

### 面试锦囊

面试官可能会追问："如果字符集很大或者包含 Unicode 怎么办？" Go 的 string 底层是 UTF-8 编码，可以把 `map[byte]int` 改为 `map[rune]int`，遍历时将 `s` 转换为 `[]rune` 来避免切分多字节字符导致乱码。如果面试官继续问能不能不用哈希表，可以回答：当字符集确定是 ASCII 时，用一个长度 128 的 `[128]int` 数组代替 map，既快又省。
