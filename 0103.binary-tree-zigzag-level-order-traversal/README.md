# 103. 二叉树的锯齿形层序遍历（Binary Tree Zigzag Level Order Traversal）

## 0. 面试解题思路

这道题本质就是 102 题（层序遍历）加了一个方向开关。面试官考的不是你会不会 BFS，而是你能不能把"遍历顺序"和"输出顺序"这两件事干净地分离开。我的做法是：队列始终按左子节点、右子节点的顺序入队，遍历顺序永远不变；锯齿效果完全在"往 level 数组的哪个位置写值"上解决。偶数层第 i 个节点写到 `level[i]`，奇数层第 i 个节点写到 `level[size-1-i]`。时间 O(n)，空间 O(n)，n 是节点总数。这样做的好处是不需要额外的反转操作，也不会因为改变入队顺序而搞乱下一层的节点排列。

## 1. 问题本质与结构特征

题目要求对二叉树做层序遍历，但偶数层从左到右、奇数层从右到左，交替进行，最终返回每一层的节点值列表。

这道题的结构特征有两个层面。第一层：它是一个标准的 BFS 层序遍历问题，逐层处理节点、逐层收集结果。第二层：它在每一层的输出上叠加了一个方向约束。关键在于，这两层是正交的——你不需要改变遍历逻辑来实现锯齿效果，只需要改变结果的排列方式。

很多人第一反应是"奇数层把子节点的入队顺序反过来"，这是一个危险的思路。入队顺序决定了下一层节点的处理顺序，改了入队顺序会连锁影响后续所有层的排列。正确的分离方式是：遍历永远标准 BFS，锯齿纯粹在输出层面解决。

## 2. 为什么是 BFS

题目按"层"定义输出格式，每一层是一个独立的列表，层与层之间方向交替。BFS 天然按层推进，每一轮处理完一层的所有节点后再进入下一层，和题目的输出结构完全对齐。

DFS 也能做——用递归遍历整棵树，用 level 参数决定把当前节点的值追加到哪一层的列表中，最后把奇数层的列表反转。但 DFS 的层级信息是隐式的（靠递归深度），而 BFS 的层级信息是显式的（靠每轮循环），对于"按层操作"的题目，BFS 的代码结构更直白，面试时更容易讲清楚。

不存在比 O(n) 更优的方案——每个节点至少要访问一次才能拿到它的值。所以这不是一道优化算法复杂度的题，而是一道考察你能否把 BFS 骨架写干净、把方向控制嵌入得不出错的题。

## 3. 暴力思路及其瓶颈

最直白的做法：先做一次标准的层序遍历（和 102 题完全一样），得到 `[][]int` 的结果，然后遍历结果列表，把下标为奇数的子列表原地反转。

```text
标准 BFS → [[3], [9,20], [15,7]]
反转奇数层 → [[3], [20,9], [15,7]]
```

这个做法完全正确，时间也是 O(n)。它的"瓶颈"不在性能——反转操作的总开销是 O(n)，和遍历本身同阶。瓶颈在于它暴露了一个设计问题：你做了一遍完整的 BFS，然后又做了一遍后处理。面试官会追问"能不能在 BFS 的过程中一步到位"，也就是问你能不能把方向控制嵌入遍历本身，避免两趟扫描。答案是可以的：在 BFS 内层循环中，根据当前层的方向决定写入位置，一趟完成。

## 4. 关键思维转折

**如果你没见过这道题，最容易想错的地方是什么？** 是试图用"改变入队顺序"来实现锯齿。直觉上，奇数层从右到左输出，那我把右子节点先入队不就行了？

这个思路的致命问题：入队顺序决定了下一层的处理顺序。如果你在第 1 层（奇数层）把右子节点先入队，第 2 层的节点处理顺序就被你篡改了，连锁反应会让后续每一层都乱掉。你必须在每一层都"补偿"上一层的入队顺序，代码会变成一团乱麻。

正确的转折是认识到：**BFS 的遍历顺序和输出顺序是两件独立的事**。队列永远保持"左子节点先于右子节点"的标准入队顺序，保证每一层的节点在队列中按从左到右排列。锯齿效果完全通过控制"第 i 个出队的节点把值写到 level 数组的哪个下标"来实现：

- 偶数层（左到右）：第 i 个节点 → `level[i]`
- 奇数层（右到左）：第 i 个节点 → `level[size-1-i]`

预先分配好 `level = make([]int, size)`，直接按下标写入，不需要反转。

## 5. 正确性论证

**遍历完备性**：队列初始化为根节点，每个节点出队时将其非空子节点入队。标准 BFS 保证每个节点恰好入队一次、出队一次，不遗漏不重复。

**层级正确性**：外层循环每轮开始时，`size = len(queue)` 锁定了当前层的节点数量。内层循环恰好处理 size 个节点，处理完毕后队列中剩余的全部是下一层节点。这是 BFS 分层处理的标准机制，和方向无关。

**方向正确性**：偶数层 `level[i] = node.Val`，节点按从左到右的出队顺序依次写入 level[0], level[1], ...，输出自然是左到右。奇数层 `level[size-1-i] = node.Val`，第 0 个出队的节点（最左边的）写到 level[size-1]（最右边的位置），第 1 个出队的写到 level[size-2]，以此类推，输出变成从右到左。方向翻转 `leftToRight = !leftToRight` 保证逐层交替。

**不影响下一层**：入队顺序始终是先左后右，不受方向标志影响。因此当前层的方向选择不会影响下一层节点在队列中的排列顺序。每一层的锯齿效果是局部的、封闭的。

## 6. 复杂度的真实来源

**时间复杂度：O(n)**，n 为节点总数。

每个节点入队一次、出队一次，每次出队时做一次数组写入。没有反转操作、没有排序、没有额外遍历。总操作次数严格等于 n。方向判断是 O(1) 的 if-else，不增加渐近开销。

**空间复杂度：O(n)**。

队列的最大长度取决于树的最宽层。对于完全二叉树，最后一层有约 n/2 个节点，因此队列峰值空间是 O(n)。结果数组也需要 O(n) 存储所有节点值。递归栈？没有递归，BFS 是纯迭代。

对比 DFS 方案：DFS 的递归栈深度是 O(h)（h 为树高），在最坏情况（链状树）下 h=n，也是 O(n)。加上结果数组仍然是 O(n)。所以 BFS 和 DFS 在空间上没有本质差异，但 BFS 不需要后处理反转。

## 7. 思路验证

**用例：[3, 9, 20, null, null, 15, 7]**

```text
树结构：
       3
      / \
     9   20
        /  \
       15    7
```

**第 0 层（偶数，左→右）**：queue = [3]，size = 1。
- i=0：出队 3，leftToRight=true，写入 level[0]=3。入队 9, 20。
- level = [3]，翻转方向。

**第 1 层（奇数，右→左）**：queue = [9, 20]，size = 2。
- i=0：出队 9（最左节点），leftToRight=false，写入 level[2-1-0]=level[1]=9。9 无子节点。
- i=1：出队 20，写入 level[2-1-1]=level[0]=20。入队 15, 7。
- level = [20, 9]，翻转方向。

关键点在这里：9 是队列中第一个出队的（最左节点），但因为是奇数层，它被写到了 level 的最后一个位置。20 是第二个出队的，被写到了 level 的第一个位置。结果 [20, 9] 就是从右到左的效果，但队列中 9 仍然排在 20 前面——入队顺序没有被破坏。

**第 2 层（偶数，左→右）**：queue = [15, 7]，size = 2。
- i=0：出队 15，leftToRight=true，写入 level[0]=15。
- i=1：出队 7，写入 level[1]=7。
- level = [15, 7]。

最终结果：[[3], [20, 9], [15, 7]]。✓

## 10. Go 代码

```go
func zigzagLevelOrder(root *TreeNode) [][]int {
	if root == nil {
		return nil
	}
	var ans [][]int
	queue := []*TreeNode{root}
	leftToRight := true
	for len(queue) > 0 {
		size := len(queue)
		level := make([]int, size)
		for i := 0; i < size; i++ {
			node := queue[0]
			queue = queue[1:]
			// 【核心】方向控制完全在写入位置上，不改入队顺序
			if leftToRight {
				level[i] = node.Val
			} else {
				level[size-1-i] = node.Val
			}
			if node.Left != nil {
				queue = append(queue, node.Left)
			}
			if node.Right != nil {
				queue = append(queue, node.Right)
			}
		}
		ans = append(ans, level)
		leftToRight = !leftToRight
	}
	return ans
}
```

## 解法二：双栈模拟（真正的 Z 字形遍历）

### 为什么面试官会追问这个解法

上面的 BFS+下标方案本质上是一个"假锯齿"——遍历顺序始终是左到右，锯齿只是输出层面的下标映射。面试官可能会追问：**能不能让遍历本身就按 Z 字形推进，节点的物理访问顺序就是锯齿的？** 这就引出了双栈模拟。

双栈方案的价值不在于性能（两者都是 O(n)），而在于它真正模拟了 Z 字形的遍历过程——每个节点被访问的时刻就是它在结果中出现的时刻，不需要任何下标映射或后处理。

### 核心机制

用两个栈 `curr` 和 `next` 交替工作：

- `curr` 存放当前层的节点，逐个弹出处理
- `next` 收集下一层的子节点
- 处理完当前层后，交换 `curr` 和 `next`

关键在于**子节点的压栈顺序随层级交替**：

- **偶数层（左→右弹出）**：先压左子、再压右子到 `next`。因为栈是 LIFO，下一层从 `next` 弹出时顺序是**右→左**——恰好是奇数层需要的方向。
- **奇数层（右→左弹出）**：先压右子、再压左子到 `next`。下一层弹出时顺序是**左→右**——恰好是偶数层需要的方向。

每一层的压栈顺序都在为下一层的弹出顺序"预埋"正确的方向。这就是双栈能自动维持锯齿的原因。

### 手推验证

```text
树结构：
       3
      / \
     9   20
        /  \
       15    7
```

**第 0 层（偶数，左→右）**：curr = [3]，next = []
- 弹出 3，收集 [3]。左→右压栈：压 9，压 20 到 next。next = [9, 20]
- 交换：curr = [9, 20]，next = []

**第 1 层（奇数，右→左）**：curr = [9, 20]，next = []
- 弹出 20（栈顶），收集 [20]。右→左压栈：压 7，压 15 到 next。next = [7, 15]
- 弹出 9（栈顶），收集 [20, 9]。9 无子节点。
- 交换：curr = [7, 15]，next = []

**第 2 层（偶数，左→右）**：curr = [7, 15]，next = []
- 弹出 15（栈顶），收集 [15]。15 无子节点。
- 弹出 7（栈顶），收集 [15, 7]。7 无子节点。
- 交换：curr = []，next = []

结果：[[3], [20, 9], [15, 7]] ✓

注意第 1 层的关键操作：弹出 20 时，先压右子 7 再压左子 15。这导致 next = [7, 15]，下一层弹出顺序是 15 → 7，恰好是左→右。**每一层的压栈顺序都是在为下一层服务。**

### 正确性论证

**方向正确性**：栈的 LIFO 特性天然反转顺序。偶数层按左→右弹出节点，压栈顺序左先右后，下一层弹出就是右先左后（奇数层的方向）。奇数层按右→左弹出节点，压栈顺序右先左后，下一层弹出就是左先右后（偶数层的方向）。两层交替形成闭环。

**完备性**：每个非空子节点恰好被压入 `next` 一次，后续恰好从 `curr` 弹出一次。没有遗漏，没有重复。

**层级正确性**：每轮外层循环处理完 `curr` 中所有节点后，`curr` 为空，`next` 恰好包含下一层的全部节点。交换后重新开始。层级边界由栈的清空天然界定。

### Go 代码（双栈）

```go
func zigzagLevelOrder(root *TreeNode) [][]int {
	if root == nil {
		return nil
	}
	var ans [][]int
	curr := []*TreeNode{root}
	leftToRight := true
	for len(curr) > 0 {
		var next []*TreeNode
		var level []int
		for len(curr) > 0 {
			// 栈：从尾部弹出
			node := curr[len(curr)-1]
			curr = curr[:len(curr)-1]
			level = append(level, node.Val)
			if leftToRight {
				// 偶数层：先压左再压右，下层弹出顺序为右→左
				if node.Left != nil {
					next = append(next, node.Left)
				}
				if node.Right != nil {
					next = append(next, node.Right)
				}
			} else {
				// 奇数层：先压右再压左，下层弹出顺序为左→右
				if node.Right != nil {
					next = append(next, node.Right)
				}
				if node.Left != nil {
					next = append(next, node.Left)
				}
			}
		}
		ans = append(ans, level)
		curr = next
		leftToRight = !leftToRight
	}
	return ans
}
```

### 双栈 vs BFS+下标：面试时怎么选

| 维度 | BFS + 下标映射 | 双栈模拟 |
|------|---------------|---------|
| 遍历顺序 | 始终左→右，锯齿在输出层 | 物理访问顺序就是锯齿 |
| 代码复杂度 | 更短，改动量小（102 基础上加一个 if） | 略长，需要理解压栈顺序的因果链 |
| 面试表达 | "我不改遍历，只改写入位置" | "我用两个栈真正模拟了 Z 字形路径" |
| 追问空间 | 面试官可能追问"能不能真正按 Z 字形访问" | 已经回答了这个追问 |
| 出错风险 | 下标算错（size-1-i）| 压栈方向搞反 |

**建议**：面试时先给 BFS+下标方案（快、稳、好讲），如果面试官追问"能不能真正按锯齿顺序遍历"，再切到双栈方案。两个都能讲清楚是加分项。

## 11. 最容易写错的地方

1. **试图改变入队顺序来实现锯齿**。奇数层先入队右子节点、再入队左子节点——这会破坏下一层的节点顺序，导致第 2 层开始全部错乱。正确做法是永远先左后右入队，锯齿只在写入位置上控制。

2. **奇数层的下标算错**。`level[size-1-i]` 中的 `size` 必须是当前层的节点数（循环开始前锁定的值），不是 `len(queue)` 的实时值。`len(queue)` 在内层循环中会因为子节点入队而不断变化。

3. **忘记预分配 level 数组**。如果用 `append` 而非下标写入，奇数层你没法直接写到 `level[size-1-i]`——要么越界要么需要初始化为零值。必须先 `make([]int, size)` 再按下标赋值。

4. **root 为 nil 时没有提前返回**。如果漏掉 nil 检查，`queue` 初始化为 `[nil]`，内层循环会对 nil 节点取值导致 panic。

5. **面试官追问**：如果树有上百万节点，你的 queue 用切片做 `queue[1:]` 会不会有性能问题？答案是 Go 的切片 `queue[1:]` 不会复制底层数组，只是移动指针，但底层数组不会被回收——长时间运行会造成内存泄漏。面试时可以提到这一点并说明可以用 `container/list` 或环形缓冲区替代，但在 LeetCode 场景下切片足够。

6. **（双栈）压栈方向搞反**。最常见的错误：偶数层和奇数层的子节点压栈顺序写反了。记忆方法——当前层的压栈顺序决定的是**下一层**的弹出顺序。偶数层左→右弹出，为了让下一层右→左弹出，你要先压左再压右（LIFO 反转）。口诀：**压栈顺序和当前层方向相同，弹出顺序就和当前层相反**。

7. **（双栈）用队列的思维写栈**。双栈方案中 `curr` 和 `next` 都是栈，必须从尾部弹出（`curr[len(curr)-1]`）。如果习惯性写成 `curr[0]` + `curr[1:]`，那就变成了队列，方向控制全部失效。

## 12. 相邻题迁移

**102. 二叉树的层序遍历**：本题的直接前置。骨架完全相同——BFS 逐层处理、size 锁定当前层、内层循环收集结果。唯一的区别是 102 没有方向控制，始终 `level[i] = node.Val`。从 102 迁移到 103，只需要加一个 `leftToRight` 布尔标志和 if-else 分支。如果你会 102，103 的增量知识量接近零。

**107. 二叉树的层序遍历 II**：要求从底层到顶层输出。BFS 骨架不变，区别在于结果收集完成后把 `ans` 整体反转，或者在收集时用头插法（`ans = append([][]int{level}, ans...)`）。和 103 的方向控制不同，107 的变化发生在"层的排列顺序"上而非"层内元素的排列顺序"上。两者可以组合：既锯齿又从底到顶。

**199. 二叉树的右视图**：同样是 BFS 分层，但每层只取最后一个节点。骨架不变，内层循环结束时不收集整个 level 数组，只收集 `level[size-1]`。从 103 迁移过来，把"收集整层"改为"收集最后一个"即可。核心修改在收集策略上，BFS 分层机制完全复用。
