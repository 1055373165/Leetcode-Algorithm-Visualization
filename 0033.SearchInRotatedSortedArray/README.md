# 33. 搜索旋转排序数组：混沌中的秩序

## 1. 审题（Problem）

### 1.1 约束解码
整数数组 `nums` 按升序排列，但在传递给函数之前，在某个未知下标 `k` 上进行了 **旋转**。
*   例如 `[0,1,2,4,5,6,7]` 旋转后可能变为 `[4,5,6,7,0,1,2]`。
*   给你旋转后的数组 `nums` 和一个整数 `target`，如果 `nums` 中存在这个目标值，则返回它的下标，否则返回 `-1`。
*   要求时间复杂度为 $O(\log n)$。

### 1.2 边界陷阱
*   数组未旋转（即旋转了 0 次）。
*   数组只剩一个元素。
*   `target` 位于旋转点附近。

### 1.3 问题归类
*   **数组 (Array)**。
*   **二分查找 (Binary Search)**。

## 2. 思维演化（Reasoning）

### 2.1 方案 A：暴力查找
直接遍历数组，找到 `target` 返回。
*   时间复杂度 $O(N)$。不符合 $O(\log n)$ 的要求。

### 2.2 方案 B：寻找旋转点 + 二分
先找到旋转点（最小值），把数组分为两个有序段。先判断 `target` 在哪一段，再在那一段里二分。
*   找旋转点本身也需要二分（$O(\log n)$）。
*   虽然可行，也可以写成 One-pass。

### 2.3 方案 C：直接二分（即使旋转了也可以）
旋转数组的一个重要特性：**将数组从中间切开，总有一半是有序的**。
1.  计算 `mid`。
2.  判断：哪一半是有序的？
    *   如果 `nums[left] <= nums[mid]`，说明 **左半边 `[left, mid]` 是有序的**。
    *   否则，说明 **右半边 `[mid, right]` 是有序的**。
3.  在有序的那一半里判断 `target` 是否存在。
    *   如果在有序区间内，就收缩边界到这一半。
    *   如果不在，就去另一半找。

## 3. 直觉培养（Intuition）

### 3.1 局部有序
想象一个被折断的梯子。虽然整体不再平滑上升，但如果不看折断的那部分，剩下的任意一半梯子，总有一部分是完好的（单调递增）。我们利用这完好的一部分来辅助定位。

**可视化重点**：
1.  **有序判定**：绿色下划线标记出当前被判定为“有序”的那一半。
2.  **范围检查**：检查 `target` 是否落在有序区间的数值范围内。
3.  **收缩**：根据检查结果，抛弃一半的数据。

## 4. 代码实现（Solution）

```go
func search(nums []int, target int) int {
	left, right := 0, len(nums)-1

	for left <= right {
		mid := left + (right-left)/2

		if nums[mid] == target {
			return mid
		}

		// 判断哪一半是有序的
		// 注意有 <= 号，因为 mid 可能等于 left（只剩两个元素时）
		if nums[left] <= nums[mid] {
			// 左半边有序 [left, mid]
			// 判断 target 是否在左半边的范围内
			if target >= nums[left] && target < nums[mid] {
				right = mid - 1 // 在左半边
			} else {
				left = mid + 1  // 去右半边
			}
		} else {
			// 右半边有序 [mid, right]
			// 判断 target 是否在右半边的范围内
			if target > nums[mid] && target <= nums[right] {
				left = mid + 1  // 在右半边
			} else {
				right = mid - 1 // 去左半边
			}
		}
	}

	return -1
}
```

### 4.2 复杂度分析
*   **时间复杂度**: $O(\log n)$。每次排除一半。
*   **空间复杂度**: $O(1)$。

### 5.2 核心口诀
**切两半，判有序，查范围，缩边界。**
只要有序，就能二分；哪怕局部有序，也能利用局部有序来二分。
