# 93. 复原 IP 地址：搜索树只有四层，真正决定生死的是你会不会提前关闸

## 读者在面试中的解题思路

这题最容易把人带偏的地方，是它长着一张“字符串题”的脸，实际上骨架却是很干净的固定段数回溯。你面前是一串纯数字，要硬生生插进三个点，切成四段，每段只能是 `0` 到 `255`，而且 `"0"` 合法，`"00"`、`"01"` 这些又统统不认。听上去像是在海量切法里找答案，但真把约束摊开看，局面一下子冷静下来：IP 就四段，每段最多三位，所以搜索树深度固定为 `4`，每层分支固定不超过 `3`，它根本不是一道靠大复杂度取胜的题。面试里我会直接这样讲：把“插入三个点”改写成“从左到右切出四段”，每次只尝试长度 `1` 到 `3` 的下一段；只要出现前导零、数值超过 `255`、或者剩余字符数已经不可能填满剩下的段数，就当场剪掉这条分支。等到恰好切出四段并且字符串正好耗尽，答案就出来了。整题的关键不是想出回溯，而是把三道约束闸门放在正确的位置上。

## 审题

题目给定一个只包含数字的字符串 `s`，要求返回所有可能的合法 IP 地址。合法 IPv4 地址必须恰好由四段组成，每段是十进制整数，范围在 `0` 到 `255` 之间，段与段之间用点分隔，而且不允许前导零，唯一的例外是单独的 `"0"`。题目原始约束写的是 `1 <= s.length <= 20`，但真正有用的不是这个大范围，而是 IPv4 的物理结构：四段、每段至少 `1` 位、至多 `3` 位，所以能产生答案的字符串长度只可能落在 `[4, 12]`。这一步如果不先看出来，后面的思路会一直带着噪音。

这题的边界陷阱非常集中，而且都不是“复杂算法”层面的坑，而是细节层面的绊脚石。第一类坑是长度，`len(s) < 4` 或 `len(s) > 12` 时必然无解，可以入口直接返回。第二类坑是前导零，`"0"` 可以单独成段，但 `"00"`、`"01"`、`"010"` 都必须立刻判死刑。第三类坑是上界，`255` 合法，`256` 不合法，而且一旦当前段已经大于 `255`，继续往右扩展只会更离谱，没有继续试的意义。第四类坑是终止条件，必须同时满足“已经切出四段”和“字符串已经恰好用完”，少任何一个条件都会把非法结果收进去。

从问题归类上看，这不是动态规划，不是贪心，也不是双指针。题目里出现了三个强信号：它要“返回所有方案”，它要求“把原串按顺序切成若干连续段”，它还有一组可以在局部立刻验证的合法性约束。这三件事叠在一起，几乎就是在点名“回溯搜索”，更准确地说，是“固定段数的序列分割回溯”。

## 2. 思维演化（Reasoning）

### 暴力基线

最直白的想法其实并不抽象，就是枚举三个点该插在哪里。既然最终一定要切成四段，那就等价于枚举三个切割点 `firstDot`、`secondDot`、`thirdDot`，把字符串拆成四个连续子串，再逐段检查它们是否合法。这个暴力法完全能写，也完全能过，因为经过长度过滤后，`n` 实际最多只有 `12`。

```go
for firstDot := 1; firstDot <= n-3; firstDot++ {
    for secondDot := firstDot + 1; secondDot <= n-2; secondDot++ {
        for thirdDot := secondDot + 1; thirdDot <= n-1; thirdDot++ {
            // 检查 s[:firstDot]、s[firstDot:secondDot]、
            // s[secondDot:thirdDot]、s[thirdDot:] 是否都合法
        }
    }
}
```

这段暴力基线的意义，不是说它有多优雅，而是它把题目本质钉死了：所有答案都来自“顺序切割”，而不是字符重排，也不是状态转移。你脑子里必须先有这个锚点，后面的优化才知道自己在优化什么。

### 你会卡在哪里

如果你没见过“固定段数回溯”这个模式，你大概率会卡在这里：三重循环明明已经能做，为什么还要递归？真正的症结不在时间，而在结构。三重循环把“恰好四段”硬编码成了三层嵌套，看似简单，实际上把约束处理挤成了一团。第一段一旦非法，你理论上应该直接放弃整棵后继搜索树；可在三重循环里，这件事只能靠一连串 `continue`、`break` 和条件套条件去拧出来，代码很快就会因为前导零、剩余长度和上界判断而变得别扭。

### 从插点到切段

真正的转折，是把“插三个点”换一种叙事方式：不是在全局思考三个点放哪，而是在局部思考“当前这一段切多长”。一旦这么改写，递归结构会自己长出来。设 `dfs(start, segmentIndex)` 表示：我们已经确定了前 `segmentIndex` 段，现在要从 `s[start]` 开始去切下一段。由于 IP 的每一段最多只有三位，所以这一层只需要尝试三种长度：`1`、`2`、`3`。如果切出的这一段合法，就递归去处理剩下的字符串；如果不合法，这一枝当场截断。

这一步看似只是把三重循环换成了回溯，但表达能力已经完全不同了。递归天然把“当前段合法才进入下一层”这件事嵌进了控制流，而不是让你在循环外面手工维护一堆过滤逻辑。更重要的是，它不再依赖“必须是四段”这个硬编码事实；你真正得到的是一个可迁移的模型：从当前位置出发，尝试所有合法前缀，然后递归处理剩余部分。

### 三道闸门同时落下

回溯写出来以后，真正决定代码质量的不是 DFS 本身，而是剪枝放得够不够准。第一道闸门是剩余字符数。假设当前已经切了 `segmentIndex` 段，剩余还需要 `4-segmentIndex` 段，那么未处理字符数如果小于这个值，说明连“一段一个字符”都凑不齐；如果大于它的三倍，说明即便后面每段都取满三位，也塞不完。这种分支没必要让它进入循环。第二道闸门是前导零。如果当前段的起点字符是 `'0'`，那这一段只能取单字符 `"0"`；一旦你已经尝试了长度大于 `1` 的形式，这一层后续所有更长的切法都必错，所以这里不是 `continue`，而是直接 `break`。第三道闸门是数值上界。当前值一旦超过 `255`，再往右拼只会更大，这一层也应该立即停止。

你会发现，这三道闸门的共同点不是“减少常数”，而是“让错误分支死在最靠近入口的位置”。这就是回溯题里最值钱的手感：不是把搜索写出来，而是让搜索只活在值得活的地方。

### 演化链收束

| 阶段 | 观察到的事实 | 技术动作 | 收获 |
|------|--------------|----------|------|
| 暴力枚举切割点 | 最终一定是按顺序切成四段 | 三重循环枚举三个点 | 能做，但结构僵硬 |
| 改写问题视角 | “插点”本质上就是“逐段切割” | 用 `dfs(start, segmentIndex)` 描述过程 | 约束可以自然嵌入递归 |
| 提前裁掉死路 | 非法段和不可能的剩余长度不必深入 | 剩余长度剪枝、前导零截断、`>255` 截断 | 搜索树被压到极小 |

这题很适合训练一个观念：并不是所有优化都体现在大 O 记号上。对这道题而言，复杂度几乎从一开始就被 IPv4 的常量结构锁死了，真正的优化是把解法从“能跑”打磨到“边界不漏、表达清楚、能迁移到同类题”。

## 3. 直觉培养（Intuition）

这题之所以应该让你立刻联想到回溯，不是因为它难，而是因为它的信号实在太典型了。题目说“返回所有可能结果”，说明它不是求最优值而是要枚举方案；题目说“按原顺序复原”，说明它不是组合重排而是连续切段；题目又给了“每段是否合法可以立刻判断”的局部约束，说明搜索树上的每一层都可以现场做过滤。这三个信号拼起来，和 131. 分割回文串、140. 单词拆分 II 属于同一个母题，只是这里的约束更机械：段数固定、长度固定、数值有上限。

| 题目信号 | 触发模式 | 真正含义 |
|----------|----------|----------|
| 返回所有答案 | 回溯/DFS | 你得把每条合法路径都走出来 |
| 顺序切成连续段 | 序列分割 | 每一步都在决定“下一段切多长” |
| 每段能立刻验合法性 | 剪枝 | 非法分支没必要递归到底 |
| 段数固定为 4 | 固定层数搜索 | 深度是常数，重点转向边界控制 |

如果非要找一个生活里的同构类比，它更像是把一卷连续标签纸切进四个抽屉里。每个抽屉至少放一格，最多放三格，而且每个抽屉里的数字还要满足额外规则。你每次做的不是“规划全局所有切口”，而只是决定当前抽屉该吃掉多长的一段纸。更关键的是，你只要看一眼剩余纸带长度和剩余抽屉数，就知道眼前这条装法是不是已经死了。回溯在这里不是玄学，它只是把这种“边切边验”的过程精确地翻译成代码。

真正容易卡住的人，通常不是不知道 DFS，而是不愿意把约束前移。他会先把路径走满四层，再在叶子节点统一检查合法性，结果写出来的代码看似也叫回溯，实质上还是“先生成，再过滤”。这题最重要的直觉不是“我会回溯”，而是“我知道哪些条件一旦失败，就该立刻停手”。

### 核心代码

```go
package main

import "strings"

func restoreIpAddresses(s string) []string {
	if len(s) < 4 || len(s) > 12 {
		return []string{}
	}

	var result []string
	var segments [4]string

	var dfs func(start, segmentIndex int)
	dfs = func(start, segmentIndex int) {
		if segmentIndex == 4 {
			if start == len(s) {
				result = append(result, strings.Join(segments[:], "."))
			}
			return
		}

		remainingChars := len(s) - start
		remainingSegments := 4 - segmentIndex
		// 【核心】剩余字符太少或太多时，后面无论怎么切都不可能拼成合法 IPv4
		if remainingChars < remainingSegments || remainingChars > remainingSegments*3 {
			return
		}

		value := 0
		for end := start; end < len(s) && end < start+3; end++ {
			// 【核心】多位段一旦以 0 开头，更长的候选只会继续非法，直接截断这一层
			if end > start && s[start] == '0' {
				break
			}

			value = value*10 + int(s[end]-'0')
			// 【核心】当前值已超过 255，再往右扩只会更大，没有继续尝试的必要
			if value > 255 {
				break
			}

			segments[segmentIndex] = s[start : end+1]
			dfs(end+1, segmentIndex+1)
		}
	}

	dfs(0, 0)
	return result
}
```

这份写法故意没有用 `strconv.Atoi` 去重复解析小子串，也没有用动态 `path` 去 `append` / `pop`，因为这题的段数是固定的，直接用一个长度为 `4` 的数组承接当前路径会更干净。你会发现代码里真正重要的地方不多，核心只有三处：剩余长度剪枝、前导零截断、`255` 上界截断。DFS 只是把它们串起来的骨架。

### 复杂度证明

- 时间：如果按回溯树去数，深度固定为 `4`，每层最多尝试 `3` 个分支，所以搜索节点规模上界是 `1 + 3 + 3² + 3³ + 3⁴`，也就是常数级；每个节点内部最多处理 `3` 个字符，所以搜索本身可以视为 `O(1)`。如果把输出拼接也算进去，总时间是 `O(答案数量)`，因为真正随输入变化的主要是你要吐出多少个合法 IP。
- 空间：辅助空间是 `O(1)`。`segments` 固定只有四个槽位，递归深度固定只有四层，没有任何跟输入长度线性增长的辅助结构。不计输出结果时，这题的额外空间就是常数。

### 易错点

- 前导零这里必须 `break`，不是 `continue`。一旦 `"01"` 非法，`"010"`、`"0109"` 这类更长候选也必然非法。
- `segmentIndex == 4` 时还要同时检查 `start == len(s)`，否则会把“段数够了但字符串没用完”的假答案收进去。
- 入口的长度过滤不要省。虽然递归里的剩余长度剪枝也能挡住这些情况，但入口直接过滤更清晰，也能少走一遍搜索。
- 当前段的数值要边扩边算，不要先把更长子串切出来再统一转整数；这题天然适合一边扫描一边累积数值。

### 核心洞察记忆

别把它理解成“在字符串里试着插三个点”，那样你会一直觉得自己在做组合枚举；这题真正的骨架是四层固定深度的连续切段，而真正拉开代码水准差距的地方，是能不能在进入下一层之前就把“剩余长度不匹配、前导零、数值越界”三类死路同时掐掉。

### 进阶：工业级极致实现

如果这段逻辑不是写在 LeetCode，而是放进高频协议解析器、日志清洗器或者边缘网关的热路径里，常规题解里那些“先切子串、再 `Join` 回去”的写法就显得不够狠了。工业级思路会把中间态彻底收紧：用 `[4]uint8` 直接存四段数值，回溯过程中只做字节级累积，不保留临时子串；命中答案时再用一个固定大小的 `[15]byte` 缓冲区原地拼出 IPv4 文本，最后一次性转成字符串。这样做的价值不是改掉大 O，而是把常量因子压到最低，把堆分配从“路径上到处都是”收缩成“只在最终输出时发生”。这一题本身不需要走到这一步，但这个意识值得记进武器库。

### 模板沉淀

```go
// 固定段数的序列分割回溯模板
func splitIntoFixedSegments(s string, totalSegments int) [][]string {
	var result [][]string
	path := make([]string, totalSegments)

	var isValid func(start, end int) bool
	isValid = func(start, end int) bool {
		// TODO: 根据题目补充合法性判断
		return true
	}

	var collect func() []string
	collect = func() []string {
		snapshot := make([]string, totalSegments)
		copy(snapshot, path)
		return snapshot
	}

	var dfs func(start, segmentIndex int)
	dfs = func(start, segmentIndex int) {
		if segmentIndex == totalSegments {
			if start == len(s) {
				result = append(result, collect())
			}
			return
		}

		remainingChars := len(s) - start
		remainingSegments := totalSegments - segmentIndex
		// TODO: 根据题目修改每段长度上下界
		if remainingChars < remainingSegments || remainingChars > remainingSegments*3 {
			return
		}

		for end := start; end < len(s); end++ {
			if !isValid(start, end) {
				continue
			}
			path[segmentIndex] = s[start : end+1]
			dfs(end+1, segmentIndex+1)
		}
	}

	dfs(0, 0)
	return result
}
```

这个模板的核心不是递归本身，而是两个固定位置：一是在进入循环前先做“剩余资源够不够”的全局剪枝，二是在每次扩展当前段时立刻做局部合法性判断。大部分序列分割题，换掉的只是 `isValid` 和每段长度边界，骨架几乎不动。

### 面试锦囊

- 面试官如果追问“还有别的写法吗”，你可以先承认三重循环暴力也能过，但它把四段结构写死了，可迁移性差，回溯更像通用模板。
- 面试官如果追问“这题复杂度怎么算”，别只说一个空洞的 `O(1)`，要把原因说出来：IPv4 的段数和每段长度上界都是常量，所以搜索树规模被协议本身锁死了。
- 面试官如果追问“为什么这里用 `break` 而不是 `continue`”，这正是这题最有含金量的细节，答出“更长候选只会更错”比背诵模板更有说服力。
