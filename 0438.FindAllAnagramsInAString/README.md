# 438. Find All Anagrams in a String：固定窗口的扫描仪

![Find All Anagrams Animation](animation.mp4)

## 1. 审题（Problem）

### 1.1 约束解码
题目要求在字符串 `s` 中找出所有是字符串 `p` 的**异位词（Anagram）**的子串。
*   **异位词**：字符种类和数量完全相同，但顺序可以不同。即 `s` 的子串必须与 `p` 的字符分布（Frequency Map）完全一致。
*   **连续子串**：题目找的是 substring，不是 subsequence，这意味着我们寻找的是一段连续的区间。
*   **数据范围**：`s` 和 `p` 仅包含小写字母，长度可达 $3 \times 10^4$。这提示我们需要 $O(N)$ 级别的算法，暴力 $O(N \cdot P)$ 可能勉强通过或超时（视具体常数而定）。

### 1.2 边界陷阱
*   `p` 的长度可能大于 `s`：此时不可能有解，直接返回空。
*   完全匹配：可能整个 `s` 就是 `p` 的异位词。
*   空字符串：题目约束通常非空，但防御性编程要考虑。

### 1.3 问题归类
寻找“**固定长度**”且满足“**某种统计特性**”的连续子串。
这属于典型的 **固定长度滑动窗口（Fixed-size Sliding Window）** 问题。

## 2. 思维演化（Reasoning）

### 2.1 暴力解法
遍历 `s` 的每一个位置 `i`，截取长度为 `p.length` 的子串 `sub = s[i : i+len(p)]`。
然后判断 `sub` 是否是 `p` 的异位词。判断方法通常是排序（$O(K \log K)$）或哈希计数（$O(K)$），其中 $K$ 是 `p` 的长度。
*   总复杂度：$O(N \cdot K)$。对于 $N=30000, K=30000$，这是 $10^9$ 级别，必然超时。

### 2.2 瓶颈分析
暴力法慢在：每次移动一步，都得重新统计通过整个新子串的字符频率。
其实，当你从 `s[i : i+k]` 移动到 `s[i+1 : i+k+1]` 时，只有**两个字符**发生了变化：
1.  **离开窗口**的字符 `s[i]`。
2.  **进入窗口**的字符 `s[i+k]`。
中间的 $k-1$ 个字符是完全没变的。我们不应该浪费时间去重复统计它们。

### 2.3 优化演化链
利用**滑动窗口**思想：维护一个实时的窗口计数器。
*   **初始化**：先统计 `p` 的字符计数 `targetCounts`，以及 `s` 中前 `k` 个字符的 `windowCounts`。
*   **滑动**：每次右移一格：
    *   `windowCounts[enteringChar]++`
    *   `windowCounts[leavingChar]--`
*   **检查**：比较 `windowCounts` 和 `targetCounts` 是否相等。这只需要 $O(26) \approx O(1)$ 的时间。
*   总复杂度：$O(N)$。

## 3. 直觉培养（Intuition）

### 3.1 扫描仪类比
想象你在一条长长的传送带（`s`）上工作，手里拿着一个这就好比拿着一个固定大小的**扫描框**（长度为 `p` 的长度）。
你需要把这个扫描框对准传送带上的货物。
每次扫描框往右挪一格，左边也就是“吐出”一个旧货物，右边“吃进”一个新货物。
你只需要关注这一进一出，就能时刻掌握框里有什么，而不需要每次都把框里的东西倒出来重新数一遍。

### 3.2 模式识别清单
看到以下关键词，优先考虑**滑动窗口**：
*   “子串”（Substring）、“子数组”（Subarray） -> 连续性。
*   “长度为 k”（Fixed constraints） -> 固定窗口。
*   “字符计数”、“异位词”、“排列” -> 哈希表/数组统计频率。

## 4. 代码实现（Solution）

### 4.1 核心代码（Go）

```go
func findAnagrams(s string, p string) []int {
    // 1. 边界检查与初始化
    sLen, pLen := len(s), len(p)
    if sLen < pLen {
        return nil
    }

    // 2. 统计 p 的字符频数和 s 第一个窗口的频数
    // 由于只包含小写字母，用数组代替哈希表性能更好
    var pCount [26]int
    var sCount [26]int

    for i := 0; i < pLen; i++ {
        pCount[p[i]-'a']++
        sCount[s[i]-'a']++
    }

    var result []int

    // 3. 检查第一个窗口
    if sCount == pCount {
        result = append(result, 0)
    }

    // 4. 滑动窗口 [i, i+pLen)
    // i 是即将进入窗口的字符索引
    // i-pLen 是即将离开窗口的字符索引
    for i := pLen; i < sLen; i++ {
        // 进一个
        sCount[s[i]-'a']++
        // 出一个
        sCount[s[i-pLen]-'a']--
        
        // 比较：数组可以直接判等（Go 语言特性）
        if sCount == pCount {
            result = append(result, i-pLen+1) // 起始索引是出窗口索引的下一位
        }
    }

    return result
}
```

### 4.2 复杂度分析
*   **时间复杂度**：$O(N)$。我们遍历了一次 `s`，每次循环内的操作（数组索引访问、比较）都是常数级的（$26$ 次比较）。
*   **空间复杂度**：$O(1)$。我们只用了固定大小为 26 的数组来存储计数，与输入规模无关。

### 4.3 易错点
*   **窗口起始索引**：当当前遍历到 `i` 时，窗口是 `[i-pLen+1, i]`。若匹配，起始索引是 `i-pLen+1`。
*   **数组比较**：在 C++/Java 中比较两个数组可能需要循环或库函数，但在 Go 中 `[26]int` 是值类型，可以直接用 `==` 比较，非常方便。
