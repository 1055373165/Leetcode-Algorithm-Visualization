# 160. 相交链表：命运的十字路口

## 1. 审题（Problem）

### 1.1 约束解码
给你两个单链表的头节点 `headA` 和 `headB`，请你找出并返回两个单链表相交的起始节点。如果两个链表不存在相交节点，返回 `null`。
*   **相交**：指两个链表的节点引用完全相同（内存地址相同），而不仅仅是值相同。
*   **结构**：链表相交后，后面的部分完全重合（呈 Y 字形，而不是 X 字形）。

### 1.2 边界陷阱
*   两个链表都不相交。
*   其中一个或两个链表为空。
*   两个链表完全重合。

### 1.3 问题归类
*   **链表 (Linked List)**。
*   **双指针 (Two Pointers)**。

## 2. 思维演化（Reasoning）

### 2.1 方案 A：哈希表
遍历链表 A，把所有节点存入 Set。然后遍历链表 B，逐个检查节点是否在 Set 中。
*   时间复杂度：$O(M+N)$。
*   空间复杂度：$O(M)$ 或 $O(N)$。题目要求 $O(1)$ 空间，此法不完美。

### 2.2 方案 B：长度对齐
只要让两个指针从距离末尾同等长度的位置开始走，它们就一定会同时到达相交点。
1.  计算 A 的长度 $L_A$ 和 B 的长度 $L_B$。
2.  让较长的链表的指针先走 $|L_A - L_B|$ 步。
3.  然后两个指针同时走，相遇点即为交点。

### 2.3 方案 C：双指针走完彼此的路（最浪漫解法）
设 A 的非公共部分长为 $a$，B 的非公共部分长为 $b$，公共部分长为 $c$。
*   指针 pA 走的路径：$a + c + b$。
*   指针 pB 走的路径：$b + c + a$。
*   $a + c + b = b + c + a$。
只要 pA 走完 A 后去走 B，pB 走完 B 后去走 A，它们最终会在交点相遇，或者同时到达 null（如果不相交）。

## 3. 直觉培养（Intuition）

### 3.1 你的名字
想象两个人走在不同的路上。
*   如果他们走完自己的路，立刻去走对方走过的路。
*   那么无论他们的起始点相距多远，只要他们速度相同，最终一定会相遇在“命运的路口”。

![相交链表动画](animation.mp4)

**可视化重点**：
1.  **路径**：pA 先走蓝色路径 A，再走绿色路径 B。pB 先走绿色路径 B，再走蓝色路径 A。
2.  **切换**：当指针到达 null 时，瞬间跳到另一个链表的头部。
3.  **相遇**：最终在黄色节点（交点）重合。

## 4. 代码实现（Solution）

```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func getIntersectionNode(headA, headB *ListNode) *ListNode {
    if headA == nil || headB == nil {
        return nil
    }
    
    pA, pB := headA, headB
    
    // 当 pA == pB 时退出循环（要么找到交点，要么都是 nil）
    for pA != pB {
        // 如果 pA 走到头，转到 headB；否则前进一步
        if pA == nil {
            pA = headB
        } else {
            pA = pA.Next
        }
        
        // 如果 pB 走到头，转到 headA；否则前进一步
        if pB == nil {
            pB = headA
        } else {
            pB = pB.Next
        }
    }
    
    return pA
}
```

### 4.2 复杂度分析
*   **时间复杂度**: $O(M+N)$。最坏情况指针遍历两个链表各一次。
*   **空间复杂度**: $O(1)$。只用了两个指针。
