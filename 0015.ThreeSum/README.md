# 15. 三数之和：排序降维 + 对撞指针批量排除，把 O(n³) 压到 O(n²) 的经典范式

## 读者在面试中的解题思路

一个有意思的事实：三数之和为零，本质上是在找 `a + b = -c`。也就是说，如果你固定了其中一个数，剩下的问题就退化成了"两数之和"——而两数之和在有序数组上，对撞双指针可以 O(n) 搞定。这意味着，只要你舍得花 O(n log n) 排一次序，整个问题就从三重循环的 O(n³) 降到了"外层枚举一个数 O(n) × 内层双指针 O(n)"的 O(n²)。排序不仅加速了搜索，还顺带解决了去重——相同的数字挨在一起，跳过重复变得极其简单。真正的难点不在于想到双指针，而在于把去重逻辑写对：外层枚举时跳过与前一个相同的 `nums[i]`，内层找到一组解后同时跳过 `left` 和 `right` 的重复值。漏掉任何一处去重，要么答案里出现重复三元组，要么直接死循环。

---

## 审题

给定一个整数数组 `nums`，找出所有满足 `nums[i] + nums[j] + nums[k] == 0` 且 `i ≠ j ≠ k` 的不重复三元组，返回所有这样的三元组列表。

约束条件是 `3 ≤ nums.length ≤ 3000`，`-10⁵ ≤ nums[i] ≤ 10⁵`。`n ≤ 3000` 意味着 O(n²) 约 9 × 10⁶ 次运算完全可以接受，但 O(n³) 约 2.7 × 10¹⁰ 就会超时。所以我们的目标复杂度是 O(n²)。

题目的隐含难点在于"不重复"这三个字。三元组 `[-1, 0, 1]` 和 `[0, -1, 1]` 算同一个，不能重复出现。这意味着我们不能简单地用三个嵌套循环找到所有和为零的三元组然后去重——去重本身的开销可能和搜索一样大。理想的方案是在搜索过程中就避免产生重复。

边界陷阱方面需要注意：数组可能包含大量重复元素（如 `[0,0,0,0,0]`），此时只应返回一个 `[0,0,0]`；数组可能全正或全负，此时无解；排序后如果 `nums[i] > 0`，则三个正数不可能和为零，可以提前终止外层循环。

问题归类：这道题的信号特征是"三数之和"+"排列组合去重"，指向 **排序 + 双指针** 的组合模式。排序消除无序性并使去重变得廉价，双指针在有序区间上高效搜索目标和。

## 思维演化（Reasoning）

### 暴力解法

最朴素的思路是三重循环枚举所有 `(i, j, k)` 组合，检查和是否为零。为了避免重复，可以将每个三元组排序后放入 HashSet 去重。时间复杂度 O(n³)，加上 HashSet 操作的常数开销，在 `n = 3000` 时大约需要 270 亿次运算——完全不可接受。

```go
// 暴力解法（仅用于理解题意，会超时）
func threeSum(nums []int) [][]int {
    n := len(nums)
    seen := map[[3]int]bool{}
    var result [][]int
    for i := 0; i < n; i++ {
        for j := i + 1; j < n; j++ {
            for k := j + 1; k < n; k++ {
                if nums[i]+nums[j]+nums[k] == 0 {
                    tri := [3]int{nums[i], nums[j], nums[k]}
                    sort.Ints(tri[:])
                    if !seen[tri] {
                        seen[tri] = true
                        result = append(result, []int{tri[0], tri[1], tri[2]})
                    }
                }
            }
        }
    }
    return result
}
```

### 瓶颈分析

暴力解慢在两个地方。第一个是**无效遍历**：当 `nums[i] + nums[j]` 已经确定时，寻找 `nums[k] = -(nums[i] + nums[j])` 本质上是一个查找问题，不需要线性扫描。第二个是**去重开销**：用 HashSet 去重需要对每个三元组排序并做哈希操作，这是在搜索之后补救，而不是在搜索过程中避免。

这两个瓶颈指向同一个优化方向：**先排序**。排序之后，查找可以用双指针在 O(n) 内完成，去重可以通过跳过相同元素在 O(1) 内完成。一次 O(n log n) 的排序，同时消除了两个瓶颈。

### 优化演化链

**第一步观察：降维。** 三数之和 `a + b + c = 0` 可以改写为 `b + c = -a`。如果我们固定 `a = nums[i]`，问题变成在 `nums[i+1:]` 中找所有和为 `-nums[i]` 的两数对。这是经典的 Two Sum 问题。

**第二步观察：排序使 Two Sum 可以用双指针。** 在无序数组上，Two Sum 需要哈希表，时间 O(n) 空间 O(n)。但在有序数组上，对撞双指针可以做到时间 O(n) 空间 O(1)——`left` 和 `right` 从两端出发，和太大就 `right--`，和太小就 `left++`，和刚好就记录答案。

**卡点**：如果你到这一步，你会发现找到一组解后不知道怎么继续——是停下来还是接着找？以及如何避免 `[-1, 0, 1]` 被找到两次？

**第三步观察：去重靠跳过。** 排序后相同的数字相邻。外层循环中，如果 `nums[i] == nums[i-1]`，跳过当前 `i`——因为以 `nums[i-1]` 为第一个数的所有三元组已经在上一轮被找过了。内层双指针找到一组解后，`left` 跳过所有与当前 `nums[left]` 相同的值，`right` 同理。这样在搜索过程中就原生避免了重复。

复杂度从 O(n³) → O(n² + n log n) = O(n²)。

## 直觉培养（Intuition）

题目中的"三数之和"直接命中信号表里的"两数/三数之和 → 哈希/排序+双指针"模式。更深一层的信号是"不重复"这个约束——它强烈暗示排序，因为排序是使去重操作降为 O(1) 的最廉价方式。

这道题的结构与"在有序数组中找目标和"这个经典模型同构。区别仅在于多了一层外循环和一层去重。如果你做过 167 题（两数之和 II），会发现三数之和就是在外面包了一层枚举，内层完全复用 Two Sum II 的对撞双指针。

如果你不知道这个技巧，你可能会尝试用三层循环+哈希表去重，或者用两层循环+哈希表查找第三个数。前者 O(n³) 超时，后者 O(n²) 时间但去重逻辑极其复杂——你需要处理哈希表中的数是否被当前 pair 已经使用、三元组排列顺序等一堆细节，很容易写错。排序+双指针是唯一一种能同时解决"高效搜索"和"原生去重"的方案。

类比：想象你在一堆散乱的扑克牌中找三张点数之和为零的牌（假设牌有负数）。如果牌是乱的，你只能一张张试。但如果你先把牌从小到大排好，再固定一张牌，剩下的两张可以从两端往中间夹——太大了就把右边的牌换小一点的，太小了就把左边的换大一点的。而且排好序之后，相同点数的牌挨在一起，只要看一眼"和前一张一样就跳过"，就不会选重。

## 代码实现（Solution）

### ASCII 状态图示

以 `nums = [-1, 0, 1, 2, -1, -4]` 为例，排序后：`[-4, -1, -1, 0, 1, 2]`

```
i=0, nums[i]=-4, target=4
  [-4  -1  -1   0   1   2]
   i    ↑                ↑
       left            right    sum = -1+2 = 1 < 4 → left++
   i         ↑          ↑
            left       right    sum = -1+2 = 1 < 4 → left++
   ...  所有 sum < 4，无解

i=1, nums[i]=-1, target=1
  [-4  -1  -1   0   1   2]
        i   ↑            ↑
           left        right    sum = -1+2 = 1 == target → 找到 [-1,-1,2]!
                                left 跳过重复, right 跳过重复
        i        ↑   ↑
                left right      sum = 0+1 = 1 == target → 找到 [-1,0,1]!
                                left++, right--, left >= right → 结束

i=2, nums[i]=-1, 与 nums[1] 相同 → 跳过（去重）

i=3, nums[i]=0 > 0 时还需检查，但 target=0，left=4(1), right=5(2), sum=3 > 0 → 无解
i=4, nums[i]=1 > 0，三个非负数之和不可能为零 → 提前终止
```

最终结果：`[[-1,-1,2], [-1,0,1]]` ✅

### 核心代码

```go
func threeSum(nums []int) [][]int {
	sort.Ints(nums)
	n := len(nums)
	var result [][]int

	for i := 0; i < n-2; i++ {
		// 【核心】排序后，若 nums[i] > 0，后面全是正数，三数之和不可能为零
		if nums[i] > 0 {
			break
		}
		// 【核心】外层去重：跳过与前一个相同的数，避免产生重复三元组
		if i > 0 && nums[i] == nums[i-1] {
			continue
		}

		left, right := i+1, n-1
		target := -nums[i]

		for left < right {
			sum := nums[left] + nums[right]
			if sum < target {
				left++
			} else if sum > target {
				right--
			} else {
				result = append(result, []int{nums[i], nums[left], nums[right]})
				// 【核心】内层去重：找到一组解后，跳过 left 和 right 的重复值
				for left < right && nums[left] == nums[left+1] {
					left++
				}
				for left < right && nums[right] == nums[right-1] {
					right--
				}
				left++
				right--
			}
		}
	}

	return result
}
```

### 复杂度证明

**时间复杂度 O(n²)**：排序 O(n log n)。外层循环枚举 `i`，共 n 次。每次内层双指针 `left` 和 `right` 从两端出发，合计最多走 n 步（每步 `left++` 或 `right--`，不回退）。因此内层总工作量为 O(n)，外层 × 内层 = O(n) × O(n) = O(n²)。排序的 O(n log n) 被 O(n²) 支配，总复杂度 O(n²)。

**空间复杂度 O(log n)**：排序的栈空间。结果数组不计入辅助空间。没有使用哈希表或其他额外数据结构。（Go 的 `sort.Ints` 使用 pdqsort，最坏空间 O(log n)。）

### 易错点

| 场景 | 陷阱 | 正确处理 |
|------|------|----------|
| 外层去重 | 写成 `nums[i] == nums[i+1]` 而非 `nums[i] == nums[i-1]` | 应与**前一个**比较；与后一个比较会跳过合法的首次使用 |
| 内层去重 | 找到解后忘记跳过重复值，或只跳了 `left` 没跳 `right` | `left` 和 `right` 都必须跳过重复，然后各自再移动一步 |
| 内层去重后忘记移动 | 跳过重复值后没有 `left++; right--` | 跳过重复只是走到最后一个相同值，还需再走一步到新值 |
| 提前终止条件 | 忘记 `nums[i] > 0` 剪枝 | 不影响正确性但影响性能；三个正数之和不可能为零 |
| `i` 的范围 | 写成 `i < n` 而非 `i < n-2` | 至少需要 3 个数，`left` 和 `right` 需要各占一个位置 |
| 全零数组 `[0,0,0,0]` | 去重逻辑可能跳过所有 0 导致漏解 | 外层去重是 `i > 0 && nums[i] == nums[i-1]`，第一个 0 不会被跳过 |

### 核心洞察记忆

三数之和的全部精髓在于一次排序解两个问题：排序让对撞双指针在有序区间上 O(n) 搜索成为可能，同时让重复元素相邻从而使得 O(1) 去重成为可能——这是"排序不只是排序，而是信息结构化"的典型案例。外层枚举 + 内层双指针将 k-Sum 问题的复杂度从 O(nᵏ) 压到 O(nᵏ⁻¹)，这个递归降维结构可以推广到任意 k 值。去重的核心不变量是"每个位置只用一次代表值"：外层跳过 `nums[i] == nums[i-1]`，内层跳过 `nums[left]` 和 `nums[right]` 的重复——漏掉任何一层去重，结果要么有重复要么死循环。

## 融会贯通（Mastery）

### 变体题群

| 题目 | 变化点 | 解法调整 |
|------|--------|----------|
| **1. 两数之和** | k=2，无序数组，返回索引 | 不能排序（会丢失原始索引），用哈希表 O(n) |
| **167. 两数之和 II** | k=2，有序数组，返回索引 | 直接对撞双指针，是三数之和的内层子问题 |
| **16. 最接近的三数之和** | 不要求恰好为零，而是最接近 target | 双指针框架不变，但每步用 `abs(sum - target)` 更新最优值，不需要去重 |
| **18. 四数之和** | k=4，找四元组 | 外层再套一层枚举，递归降维：4Sum → 3Sum → 2Sum，O(n³) |
| **259. 较小的三数之和** | 统计 `sum < target` 的三元组个数 | 双指针找到 `sum < target` 时，`right - left` 个配对都满足，一次性计数 |

### 模板沉淀

k-Sum 的通用递归模板（适用于任意 k ≥ 2）：

```go
func kSum(nums []int, target int, k int) [][]int {
	sort.Ints(nums)
	return kSumHelper(nums, target, k, 0)
}

func kSumHelper(nums []int, target int, k int, start int) [][]int {
	var result [][]int
	n := len(nums)

	if k == 2 {
		// TODO: 根据题目修改——基础情况：对撞双指针
		left, right := start, n-1
		for left < right {
			sum := nums[left] + nums[right]
			if sum < target {
				left++
			} else if sum > target {
				right--
			} else {
				result = append(result, []int{nums[left], nums[right]})
				for left < right && nums[left] == nums[left+1] { left++ }
				for left < right && nums[right] == nums[right-1] { right-- }
				left++
				right--
			}
		}
		return result
	}

	// TODO: 根据题目修改——递归情况：枚举一个数，降维到 (k-1)-Sum
	for i := start; i < n-k+1; i++ {
		if i > start && nums[i] == nums[i-1] { continue } // 去重
		// 剪枝：最小 k 个数之和 > target 或最大 k 个数之和 < target
		if nums[i]*k > target { break }
		subResults := kSumHelper(nums, target-nums[i], k-1, i+1)
		for _, sub := range subResults {
			result = append(result, append([]int{nums[i]}, sub...))
		}
	}
	return result
}
```

### 面试锦囊

**"还有其他解法吗？"** → 可以用哈希表替代双指针：外层枚举 `i`，中层枚举 `j`，用 Set 查找 `-(nums[i]+nums[j])`。时间 O(n²) 但去重逻辑更复杂，空间 O(n)。面试中优先推荐排序+双指针方案，因为去重逻辑更清晰、空间更优。

**"如果条件变了呢？"** → 如果改为"找最接近 target 的三数之和"（第 16 题），框架完全不变，仅把 `== 0` 的判断改为用绝对差更新最优值，且不需要去重。如果改为"四数之和"（第 18 题），在外层再加一层循环即可，或直接使用上面的 k-Sum 模板。

**"时间不够怎么办？"** → 先排序，然后写出三重循环但限定 `j = i+1, k = n-1` 的双指针框架。即使去重逻辑来不及写完，拿到的分数也比暴力高得多。去重可以先口述策略："外层跳过相同的 i，内层找到解后跳过相同的 left 和 right。"
