# 48. 旋转图像：矩阵的华尔兹

## 1. 审题（Problem）

### 1.1 约束解码
给定一个 `n × n` 的二维矩阵 `matrix` 表示一个图像。请你将图像顺时针旋转 90 度。
*   你必须在 **原地** 旋转图像，这意味着你需要直接修改输入的二维矩阵。
*   **请不要** 使用另一个矩阵来旋转图像（空间复杂度 $O(1)$）。

### 1.2 边界陷阱
*   `n = 1`（旋转后不变）。
*   非方阵（题目保证是 `n x n`）。

### 1.3 问题归类
*   **数组 (Array)**。
*   **矩阵 (Matrix)**。
*   **数学 (Math)**。

## 2. 思维演化（Reasoning）

### 2.1 方案 A：辅助矩阵
创建一个新的 `n x n` 矩阵。
`new_matrix[col][n-1-row] = matrix[row][col]`。
简单直观，但空间复杂度 $O(N^2)$，不符合题意。

### 2.2 方案 B：由外向内旋转（洋葱剥皮）
一圈一圈地转。
对于每一圈，把上边的移到右边，右边的移到下边，下边的移到左边，左边的移到上边。
需要暂存一个元素，然后像“贪吃蛇”一样替换。
逻辑稍微有点绕，容易写错下标。

### 2.3 方案 C：先转置，再翻转（线性代数魔法）
顺时针旋转 90 度可以通过两步简单的几何变换实现：
1.  **转置 (Transpose)**：沿主对角线翻转。`matrix[i][j]` <-> `matrix[j][i]`。
2.  **水平镜像 (Reflect)**：左右翻转。`matrix[i][j]` <-> `matrix[i][n-1-j]`。

这是一个非常通用的技巧：
*   顺时针 90 = 转置 + 左右翻转
*   逆时针 90 = 转置 + 上下翻转
*   旋转 180 = 上下翻转 + 左右翻转

## 3. 直觉培养（Intuition）

### 3.1 纸片折叠
拿一张纸，画个矩阵。
1.  沿着对角线（左上到右下）折叠，把纸上的数字印到对称位置（转置）。
2.  沿着中轴线（竖直）折叠，把左边的数字印到右边（镜像）。
打开纸一看，神奇的事情发生了，图像顺时针转了 90 度！

## 4. 代码实现（Solution）

```go
func rotate(matrix [][]int) {
	n := len(matrix)

	// 1. 转置 (Transpose)
	// 只需要遍历对角线及其“上方”的元素
	for i := 0; i < n; i++ {
		for j := i + 1; j < n; j++ { // j 从 i+1 开始，避免重复交换和自己交换
			matrix[i][j], matrix[j][i] = matrix[j][i], matrix[i][j]
		}
	}

	// 2. 水平翻转 (Reflect)
	// 每一行都要翻转
	for i := 0; i < n; i++ {
		for j := 0; j < n/2; j++ { // 只遍历左半边
			matrix[i][j], matrix[i][n-1-j] = matrix[i][n-1-j], matrix[i][j]
		}
	}
}
```

### 4.2 复杂度分析
*   **时间复杂度**: $O(N^2)$。每个元素被访问两次（转置一次，翻转一次）。
*   **空间复杂度**: $O(1)$。原地修改。

## 5. 融会贯通（Mastery）

### 5.1 图像处理基础
这道题不仅是算法题，也是图形学和图像处理的基础。在 GPU 中，矩阵变换（旋转、缩放、平移）是核心操作。虽然 GPU 是并发处理，但理解底层的数学变换原理（线性代数）对程序员至关重要。

### 5.2 为什么从外向内容易错？
由外向内旋转（方案 B）涉及 4 个位置的坐标变换：`(i, j) -> (j, n-1-i) -> (n-1-i, n-1-j) -> (n-1-j, i)`。
写代码时很容易把 `i` 和 `j` 搞混，或者边界条件（`n-1`）算错。
而 **转置+翻转** 方案，每一步都只涉及两个位置的简单交换，逻辑解耦，不易出错。
