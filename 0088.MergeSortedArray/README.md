# 88. 合并两个有序数组：逆向思维的胜利

## 1. 审题（Problem）

### 1.1 约束解码
给定两个有序整数数组 `nums1` and `nums2`，将 `nums2` 合并入 `nums1` 中，使 `nums1` 成为一个有序数组。
*   `nums1` 的初始长度为 `m + n`，其中前 `m` 个元素是有效的，后 `n` 个元素是 `0`（预留空间）。
*   **硬性要求**：原地修改 `nums1`。

### 1.2 边界陷阱
*   `m=0`：`nums1`全是0，直接把 `nums2` 拷过来。
*   `n=0`：`nums2`为空，啥也不用做。
*   `nums2` 还有剩但 `nums1` 用完了：要把 `nums2` 剩下的拷进 `nums1` 头部（例如 `nums1=[7,8,0,0], nums2=[1,2]`）。

### 1.3 问题归类
*   **数组合并**。
*   **双指针 (Two Pointers)**。

## 2. 思维演化（Reasoning）

### 2.1 方案 A：直接合并再排序
把 `nums2` 插到 `nums1` 末尾，然后调用 `sort`。
复杂度：$O((m+n)\log(m+n))$。太慢，浪费了“原本有序”这个条件。

### 2.2 方案 B：正向双指针（需要额外空间）
搞一个新数组 `copy`。比较 `nums1[0]` 和 `nums2[0]`，小的放进 `copy`。
复杂度：时间 $O(m+n)$，空间 $O(m)$。题目要求原地，这个方案也不完美。

### 2.3 方案 C：正向双指针（原地？）
如果我们直接在 `nums1` 上操作：
比较 `nums1[0]` 和 `nums2[0]`。假设 `nums2[0]` 小，插到 `nums1[0]`。
**问题来了**：原来的 `nums1[0]` 去哪？它被覆盖了！我们需要把 `nums1` 所有元素往后挪一位。这就变成了 $O(m \cdot n)$。

### 2.4 方案 D：逆向双指针（完美解）
既然正向操作会覆盖“未处理的元素”，那我们看看哪里是“安全的”。
`nums1` 的**末尾**（`index = m+n-1`）是空的（0），而且是最大的数应该待的地方。
只要我们从后往前填，填充的速度肯定慢于（或等于）读取的速度，绝不会覆盖到还没读取的 `nums1` 元素。

## 3. 直觉培养（Intuition）

### 3.1 填坑游戏
想象我们在玩俄罗斯方块的填坑。
*   `p1` 指向 `nums1` 有效数据的队尾。
*   `p2` 指向 `nums2` 的队尾。
*   `p` 指向 `nums1` 的最末端（当前要填的坑）。
*   **规则**：谁大谁填坑。
例如 `nums1=[1,3,0,0], nums2=[2,4]`。
1.  比较 `3` 和 `4`。4大。填入 `nums1[3]`。`nums2` 指针左移。
2.  比较 `3` 和 `2`。3大。填入 `nums1[2]`。`nums1` 指针左移。
3.  ...

## 4. 代码实现（Solution）

```go
func merge(nums1 []int, m int, nums2 []int, n int) {
	// 三指针初始化
	p1 := m - 1      // nums1 有效末尾
	p2 := n - 1      // nums2 末尾
	p := m + n - 1   // 合并后 nums1 的末尾 (填坑位置)

	// 只要 p2 还没干完（如果 p1 先干完，剩下的 p2 直接拷贝；如果 p2 先干完，p1 原地不动即可）
	for p2 >= 0 {
		if p1 >= 0 && nums1[p1] > nums2[p2] {
			// nums1 的数更大，放进坑里
			nums1[p] = nums1[p1]
			p1--
		} else {
			// nums2 的数更大（或相等，或 p1 已经耗尽），放进坑里
			nums1[p] = nums2[p2]
			p2--
		}
		p-- // 坑位前移
	}
}
```

### 4.2 复杂度证明
*   **时间复杂度**: $O(m+n)$。每个元素最多被读和写一次。
*   **空间复杂度**: $O(1)$。原地修改，只用了 3 个指针变量。

### 4.3 易错点清单
1.  **循环条件**：为什么是 `while p2 >= 0`？
    *   因为如果 `p2` 先走完（`nums2` 全是大的，都填后面了），剩下的 `nums1` 都在原位，不用动，合并结束。
    *   但如果 `p1` 先走完（`nums1` 全是大的），`nums2` 还有剩，必须把剩下的 `nums2` 拷进 `nums1` 的头部。我们的循环条件覆盖了这种情况（此时 `p1 < 0`，进入 `else` 分支，持续搬运 `nums2`）。

### 5.2 模式识别
当遇到：
1.  **原地 (In-place)** 操作数组
2.  **有序** 数组合并或移动
3.  **正向操作** 会导致数据覆盖或大量移动
