# 4. 寻找两个正序数组的中位数

> 两个**已经升序排列**的数组 `nums1`、`nums2`（长度 m 和 n），返回 m+n 个数合并后的中位数。**要求时间复杂度 O(log(m+n))**。

---

## 1. 30 秒面试回答

这题属于**"在两个有序结构上做分割式二分"** 的模板。核心做法是把"找中位数"变形成"找一刀，让两数组左半合起来恰好 (m+n+1)/2 个元素，且左半最大值 ≤ 右半最小值"。`i1` 一旦给定，`i2 = (m+n+1)/2 - i1` 自动确定——两刀塌缩成一刀。再在**较短数组**上二分 `i1`，每轮用一次跨数组比较判定方向。时间 O(log(min(m,n)))，空间 O(1)。正确性来自单调性：`i1` 增大时 `l1` 单调不减、`r2` 单调不增，所以合法切口唯一。

---

## 2. 我第一眼应该先想到什么

**信号词识别**：

- "两个有序数组" + "中位数 / 第 k 大" → 几乎必然是**切割式二分**
- "log(m+n)" 出现在题面 → 排除任何 O(m+n) 解法，必须对**位置**或**值**做二分
- "正序"（已排序）是关键前提——一旦没有这条，二分立刻崩塌

**最自然的暴力起点**：归并两个数组成一个 O(m+n) 的有序数组，按下标取中。这是**所有人**最早能想到的方案。

**暴力慢在哪里**：它在"生成左半的具体内容"——你逐元素地把中位数前面那一长串数字摆出来，但你**根本不需要看见它们**，你只需要知道中位数那一格里站着谁。一旦放弃"看见全部"换成"只看见切口附近的四个值"，O(log) 就有了入口。

---

## 3. 核心洞察

**最关键的不变量**：合法切口的充要条件是 `l1 ≤ r2 && l2 ≤ r1`（左半最大 ≤ 右半最小）。数组内有序使 `l1 ≤ r1` 与 `l2 ≤ r2` 自动成立，只需两次**跨数组**比较。

**状态定义**：`i1` ∈ [0, m] 表示从 `nums1` 拿多少个元素归入左半。`i2 = halfLeft - i1`，其中 `halfLeft = (m+n+1)/2`。`+1` 不是数学小技巧，是把奇偶情况统一到同一段代码的根本手段——奇数时左半多一个（中位数 = `max(l1, l2)`），偶数时左右等分（中位数 = `(max(l1,l2)+min(r1,r2))/2`）。

**为什么这是命门**：放弃了"看见所有元素"，只看四个边界值。这是把"线性扫描"换成"对数定位"的根本理由。

**为什么不会漏解**：合法切口必存在且唯一（合并后中位数本身存在）。单调性保证二分方向永远正确：`l1 > r2` ⇔ `i1` 偏大；`l2 > r1` ⇔ `i1` 偏小。两种失败模式与两种二分方向**精确对应**，不存在第三种情况。

**容易误判成的相邻题型**：

- 误判成"归并到中点 O(m+n)" → 没看到题目要求的 log 复杂度
- 误判成"对值域二分（找第 k 小套路）" → 这套路在矩阵题有用，但此题"对位置二分"更直接、常数更小
- 误判成"双指针走到中点" → 仍然是线性

---

## 4. 最优解怎么一步步长出来

**起点**（暴力）：归并 O(m+n) 时间 + O(m+n) 空间。

**第一次降维**：不用真合并，两指针各走一步，到中点就停。时间 O((m+n)/2)，空间 O(1)。常数减半，渐近不变。

**瓶颈**：这两种方案都在**生成合并数组的前缀**。代价是 Θ(m+n)，因为你坚持要"逐元素看见"中位数前的内容。

**关键观察（最容易想错的思维岔路）**：

> 大多数人卡在"如何更快地走到中点"，企图用跳跃式步进或采样加速归并。**这条路走不通**——只要你坚持要看见左半的具体内容，你就被锁在 Θ(m+n) 里。真正的跳跃是**放弃看见左半**，只看见切口附近的四个值。

观察到的规律链：

1. 中位数只依赖切口附近的四个边界值
2. 固定左半总数为 `halfLeft = (m+n+1)/2`，则两刀位置塌缩成一刀（`i2 = halfLeft - i1`）
3. 合法切口的判据只需两次跨数组比较 `l1 ≤ r2 && l2 ≤ r1`
4. `i1` 增大时 `l1` 单调不减、`r2` 单调不增——具备二分基础
5. 在较短数组上二分，搜索空间从 `O(m)` 压到 `O(min(m,n))`，并保证 `i2 ∈ [0, n]` 永不越界（这是**正确性前提**而非性能优化）

最终算法：在较短数组上二分 `i1`，每轮用两次比较决定收缩方向。O(log(min(m,n)))。

## 5. 手推一个关键样例

样例：`nums1 = [1, 3]`, `nums2 = [2, 4, 5]`。`m=2, n=3, halfLeft = (2+3+1)/2 = 3`。`i1` ∈ [0, 2]。

| 轮 | lo | hi | i1 | i2 | l1 | r1 | l2 | r2 | 判定 | 动作 |
|:--:|:--:|:--:|:--:|:--:|:--:|:--:|:--:|:--:|:----:|:----:|
| 1 | 0 | 2 | 1 | 2 | 1 | 3 | 4 | 5 | l1≤r2 ✓ / l2≤r1 ✗ (4>3) | i1 太小，lo=2 |
| 2 | 2 | 2 | 2 | 1 | 3 | +∞ | 2 | 4 | l1≤r2 ✓ / l2≤r1 ✓ | 合法，奇数 → median = max(3,2) = 3 |

**关键转折点在第 1 轮**：左半收了 `{1, 2, 4}`，但 4 比右半的 3 还大——这就是切口非法的真正含义。算法不会试图"修复"这个混乱，而是基于"`l2 > r1` ⇔ `i1` 切得太靠左"的单调性直接跳到下一个 `i1`。这是二分的核心姿态：**不修补错误，跳到必然正确的方向**。

第 2 轮 `r1 = +∞` 是因为 `i1 = m = 2`，`nums1` 全部进左半，右半没有 `nums1` 的代表。哨兵让这种边界情况**走同一段判定代码**，无需特殊分支。

## 7. 最优解视频生成方案

**视频目标**：让观众一眼看出"两个数组的切口被一根隐形横线绑死，i1 移动时 i2 自动反向移动，合法判据只是两次跨数组比较"。

**视觉映射**：

- `nums1` 横向排列在上方，`nums2` 横向排列在下方，方格化
- 切口用**竖线**贯穿，颜色随合法性变化（红=非法、绿=合法、黄=待判定）
- 左半元素淡蓝底，右半元素淡红底
- 四个边界值 `l1 r1 l2 r2` 在数组下方独立面板，越界时显示 `-∞` / `+∞`
- 两条判定 `l1≤r2`、`l2≤r1` 各打 ✓ / ✗
- 二分区间 `[lo, hi]` 在 `nums1` 上方画窄条带

**镜头拆分**（5 帧关键镜头）：

1. **Init**：展示两个输入数组与 `halfLeft` 的计算
2. **Pick i1**：在 `[lo, hi]` 中取中点，竖线落在 `nums1` 上，`i2` 同时落在 `nums2` 上
3. **Check**：放大四个边界值，依次打勾打叉
4. **Shrink**：失败时区间收缩，竖线移动到新位置
5. **Found**：合法切口高亮，奇偶分支给出中位数公式

**step 数据字段**：`nums1, nums2, i1, i2, lo, hi, l1, r1, l2, r2, l1LeR2, l2LeR1, status, median, reason`。`l1/r1/l2/r2` 用 `null` 编码 `±∞`（JSON-safe）；`status` 是 `'init'|'pick'|'check'|'shrink-left'|'shrink-right'|'found'`。

**节奏建议**：8 步 × 2.5 秒 = 20 秒。`Check` 帧放慢到 3 秒，让两次比较结果有时间被读出。`Shrink` 帧用平滑过渡（spring 缓动），让"竖线滑过"而非瞬移。

## 8. Go 代码

```go
import "math"

func findMedianSortedArrays(nums1 []int, nums2 []int) float64 {
	// 【关键决策】在较短数组上二分。一是把搜索空间压到 log(min(m,n))，
	// 二是保证 i2 = halfLeft - i1 不越出 [0, n]——这是正确性前提，不是优化。
	if len(nums1) > len(nums2) {
		nums1, nums2 = nums2, nums1
	}
	m, n := len(nums1), len(nums2)
	halfLeft := (m + n + 1) / 2 // +1 让奇偶共用同一段代码

	lo, hi := 0, m
	for lo <= hi {
		i1 := (lo + hi) / 2
		i2 := halfLeft - i1

		// 越界用 ±∞ 哨兵，避免一堆边界 if
		l1, r1 := math.MinInt, math.MaxInt
		l2, r2 := math.MinInt, math.MaxInt
		if i1 > 0 {
			l1 = nums1[i1-1]
		}
		if i1 < m {
			r1 = nums1[i1]
		}
		if i2 > 0 {
			l2 = nums2[i2-1]
		}
		if i2 < n {
			r2 = nums2[i2]
		}

		// 【核心判据】仅需两次跨数组比较
		if l1 <= r2 && l2 <= r1 {
			if (m+n)%2 == 1 {
				return float64(max(l1, l2))
			}
			return float64(max(l1, l2)+min(r1, r2)) / 2.0
		}
		// l1 > r2: i1 偏右；否则 i1 偏左
		if l1 > r2 {
			hi = i1 - 1
		} else {
			lo = i1 + 1
		}
	}
	return 0 // 不可达
}
```

代码总共 30 行左右，白板可写。`math.MinInt/MaxInt` 是 Go 1.17+ 内建常量；`max/min` 是 Go 1.21+ 内建。LeetCode 当前 Go 评测环境（≥1.21）直接可用，不要自己手写。

**为什么不推第 k 小通用模板版本**：通用版要写一个 `findKth(a,b,k)` 然后用 `findKth(a,b,(m+n+1)/2)` 和 `findKth(a,b,(m+n+2)/2)` 取均值，思路更"对称"但代码更长、有两次二分调用、且 `lo/hi` 初始范围要写成 `[max(0,k-n), min(k,m)]` 容易出错。**白板优先这版直接二分**，模板版放在 §10 迁移时再展开。

## 9. 最容易写错的地方

- **没交换较短数组**：直接对长数组二分，`i2` 在某些 `i1` 下变成负数，`nums2[i2-1]` panic。这是本题最常见的崩溃点。
- **`/ 2` 写成整数除法**：偶数情况 `(max(l1,l2)+min(r1,r2))/2` 必须用浮点除（`/2.0` 或先转 `float64` 再除）。整数除法会把 `2.5` 误算成 `2`。
- **忘记哨兵**：`i1=0` 或 `i1=m` 时如果用 0 而非 `MinInt/MaxInt`，对负数输入或边界切口立刻翻车。
- **二分边界 off-by-one**：`for lo <= hi` 必须用闭区间，因为 `i1` 的合法取值是 `[0, m]` **闭**区间。写成 `lo < hi` 会错过 `i1 = m` 的合法切口。
- **奇偶分支条件**：`(m+n)%2 == 1` 是 `m+n` 的奇偶判定，**不是** `m%2` 或 `n%2`。这是面试官最常追问的细节——"为什么用 `(m+n+1)/2` 而不是 `(m+n)/2`？"，答案必须能讲清"+1 把奇偶统一"。

## 10. 相邻题迁移

**LC 374 / 二分模板系列**（找第一个/最后一个满足条件的位置）：

- **共用骨架**：在单调性上做二分 + 跨结构验证
- **关键不同**：本题在**两个**数组上同时切，374 只在一个上找位置
- **修改层**：只改"如何用 mid 验证可行性"那一层——本题验证靠跨数组比较，374 靠单值比较

**LC 378. 有序矩阵中第 K 小的元素**：

- **共用骨架**：把"找第 k 大"翻译成"找一条线让左侧恰好 k 个"
- **关键不同**：矩阵只是行列各自有序，整体无序，因此**不能对位置二分**，要**对值域二分**——猜一个值 `mid`，用 `countLE(mid)` 计算 `≤mid` 的元素数
- **修改层**：把"二分位置 i1"换成"二分值域 `[matrix[0][0], matrix[n-1][n-1]]`"，验证函数从"四值比较"换成"双指针/二分统计"

**LC 719. 找出第 K 小的距离对**：

- **共用骨架**：同样"对答案二分 + 单调验证"
- **关键不同**：搜索空间是**距离值域**（0 到 max-min），验证函数是"距离 ≤ mid 的对数 ≤ k 吗"
- **修改层**：值域计算 + 验证函数（双指针扫一遍排序后的数组）

通用模板（"在两个有序数组中找第 k 小"）：

```go
// k 从 1 开始；当 k = (m+n+1)/2 时退化为本题中位数
func findKth(a, b []int, k int) int {
	if len(a) > len(b) {
		a, b = b, a
	}
	m, n := len(a), len(b)
	lo, hi := max(0, k-n), min(k, m) // TODO: i1 的有效范围比 [0,m] 更窄
	for lo <= hi {
		i1 := (lo + hi) / 2
		i2 := k - i1
		l1, r1 := math.MinInt, math.MaxInt
		l2, r2 := math.MinInt, math.MaxInt
		if i1 > 0 { l1 = a[i1-1] }
		if i1 < m { r1 = a[i1]   }
		if i2 > 0 { l2 = b[i2-1] }
		if i2 < n { r2 = b[i2]   }
		if l1 <= r2 && l2 <= r1 {
			return max(l1, l2)
		}
		if l1 > r2 { hi = i1 - 1 } else { lo = i1 + 1 }
	}
	return 0
}
```

## 11. 闭卷自测

1. 为什么这题不能用"双指针走到中点"解决，明明也是线性？（答：线性 ≠ 对数。题目要求 O(log(m+n))，任何 Θ(m+n) 解法都不满足。）
2. 核心不变量是什么？为什么这两次跨数组比较 `l1≤r2 && l2≤r1` 就足以判定合法？（答：数组内有序使数组内的两条不等式自动成立，只剩跨数组两条要验。）
3. 为什么必须在**较短**数组上二分？仅仅是性能优化吗？（答：不是。是正确性前提——保证 `i2 = halfLeft - i1 ∈ [0, n]`，否则索引越界。）
4. 如果题目去掉"输入数组各自有序"这个条件，原方法会先坏在哪里？（答：单调性消失，二分方向无法决定；同时"l1 ≤ r1"不再自动成立，判据要从 2 个条件变成 4 个。整个算法不成立。）
5. 一句话口诀：**"切两刀塌成一刀，两次跨数组比较定胜负。"**
