# 199. 二叉树的右视图 (Binary Tree Right Side View)

## 1. 30 秒面试回答

这题是 **BFS 层序遍历**的经典变体。从右侧观察二叉树，每层只能看到最右边的节点。核心做法：BFS 逐层遍历，每层取最后一个节点加入结果。时间 O(n)，空间 O(w)（w 为最大层宽度）。成立原因：BFS 保证同层节点按从左到右顺序处理，最后一个就是右视图节点。

## 2. 我第一眼应该先想到什么

**信号词**：「右侧观察」「每层最右边」——涉及**层**的概念，直接想到 BFS 层序遍历。

**暴力起点**：DFS 前序遍历，记录每个节点的深度，用 map 存每层最右节点。需要保证同一层右边覆盖左边。

**暴力慢在哪**：DFS 本身不慢（也是 O(n)），但需要额外的 map 追踪每层状态，不如 BFS 自然。

**最容易想错的岔路**：以为「一路走右子树」就行了。反例：右子树比左子树浅时，深层的右视图节点来自左子树。

```
    1
   / \
  2   3
   \
    5
```
右视图是 `[1, 3, 5]`——第三层的 5 来自左子树！

## 3. 核心洞察

### 面试官想考什么

面试官想看你能不能**灵活运用 BFS 层序遍历解决"每层取特定位置节点"类问题**。这和 102 层序遍历、103 锯齿遍历是同一族题目。

### 两种解法分析

快速稳妥解和面试官期望解**是同一个**：BFS 层序遍历取每层最后节点。DFS 写法也 O(n)，但 BFS 更自然、更不容易出错。

**标注：最优解**（BFS 层序遍历）

### 关键不变量

每层处理时，`queue` 恰好存放当前层的所有节点。遍历到 `i == layerSize - 1` 时，该节点就是这层的右视图节点。

### 为什么不会漏解

BFS 保证每一层的每个节点都被访问，且按从左到右入队。最后一个弹出的必然是最右节点。即使右子树为空，左子树的节点也会被正确处理。

### 为什么容易误判

容易和「DFS 只走右子树」混淆。右视图 ≠ 右子树。右视图是每层最右，当右子树比左子树浅时，深层右视图来自左子树。

## 4. 最优解怎么一步步长出来

1. **暴力起点**：DFS 遍历所有节点，用 `map[depth]` 记录每层最右值
2. **瓶颈**：DFS 需要额外逻辑判断"是否比当前记录更右"
3. **观察**：问题本质是"每层的最后一个节点"，而 BFS 天然按层组织
4. **最优解**：BFS + 层大小计数，每层处理完 `layerSize` 个节点后，最后一个就是答案

**最容易想错的思维岔路**：用 DFS 先序遍历（根→左→右），以为最后访问的就是最右。实际上 DFS 的访问顺序是深度优先，不是层级优先——同一层的节点可能在不同递归分支中被访问，无法保证顺序。

## 5. 手推关键样例

```
       1
      / \
     2   3
    / \   \
   4   5   7
```

BFS 过程：

| 步骤 | Queue | 弹出 | 层内位置 | 是最右？ | result |
|------|-------|------|----------|---------|--------|
| 初始 | [1] | — | — | — | [] |
| Layer 0, size=1 | [] | 1 | 0/1 | YES | [1] |
| 入队 2,3 | [2,3] | — | — | — | [1] |
| Layer 1, size=2 | [3] | 2 | 0/2 | no | [1] |
| | [] | 3 | 1/2 | YES | [1,3] |
| 入队 4,5,7 | [4,5,7] | — | — | — | [1,3] |
| Layer 2, size=3 | [5,7] | 4 | 0/3 | no | [1,3] |
| | [7] | 5 | 1/3 | no | [1,3] |
| | [] | 7 | 2/3 | YES | [1,3,7] |

**关键转折**：Layer 2 中虽然 7 在右子树、4 和 5 在左子树，但 BFS 不关心来源——只看层内顺序的最后一个。

## 8. Go 代码

```go
// 最优解：BFS 层序遍历
func rightSideView(root *TreeNode) []int {
    if root == nil {
        return nil
    }
    var result []int
    queue := []*TreeNode{root}

    for len(queue) > 0 {
        size := len(queue) // 当前层节点数
        for i := 0; i < size; i++ {
            node := queue[0]
            queue = queue[1:]
            if i == size-1 { // 每层最后一个 = 右视图
                result = append(result, node.Val)
            }
            if node.Left != nil {
                queue = append(queue, node.Left)
            }
            if node.Right != nil {
                queue = append(queue, node.Right)
            }
        }
    }
    return result
}
```

**DFS 写法**（备用，面试被追问时用）：

```go
func rightSideView(root *TreeNode) []int {
    var result []int
    var dfs func(node *TreeNode, depth int)
    dfs = func(node *TreeNode, depth int) {
        if node == nil {
            return
        }
        if depth == len(result) { // 这层还没收集过 → 第一个到达的就是最右
            result = append(result, node.Val)
        }
        dfs(node.Right, depth+1) // 先右再左！
        dfs(node.Left, depth+1)
    }
    dfs(root, 0)
    return result
}
```

DFS 关键：**先递归右子树再递归左子树**，保证每层第一个被访问的就是最右节点。用 `depth == len(result)` 判断该层是否已收集。

## 9. 最容易写错的地方

1. **BFS 忘记记录 `size`**：如果在循环内动态用 `len(queue)` 作为条件，队列长度会随入队变化，导致层界混乱。必须在循环前 `size := len(queue)` 固定。
2. **DFS 先左后右**：如果先递归左子树，收集到的是左视图而不是右视图。先右后左是关键。
3. **以为只走右子树就行**：`root.Right` 为空时还要看 `root.Left`。右视图不等于右子树。
4. **空树没特判**：`root == nil` 时应返回 `[]int{}`（空切片），而不是 `nil`（虽然 Go 中两者在 LeetCode 都能过，但面试要说清楚）。
5. **面试官追问**："如果改成左视图呢？" BFS 取 `i == 0`；DFS 先左后右。一行改动。
