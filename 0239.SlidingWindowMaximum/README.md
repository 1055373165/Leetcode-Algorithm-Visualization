# 239. 滑动窗口最大值（Sliding Window Maximum）

## 1. 30 秒面试回答

这题是**单调双端队列（Monotonic Deque）**经典题。维护一个递减的双端队列，存的是下标。每次右移窗口：①从队头移除过期下标；②从队尾移除所有值 ≤ 当前元素的下标（它们永远不可能成为最大值）；③当前下标入队尾；④队头就是当前窗口的最大值。每个元素最多入队一次、出队一次，总时间 **O(n)**，空间 **O(k)**。核心不变量：队列中的元素始终单调递减，队头永远是当前窗口的最大值。

---

## 2. 我第一眼应该先想到什么

- **信号词**："滑动窗口"+"最大值" → 窗口内需要高效维护极值
- **结构特征**：窗口大小固定为 k，每次右移一格，要求每个位置的窗口最大值
- **暴力起点**：每个窗口位置扫一遍 k 个元素取 max → O(n×k)
- **暴力慢在哪**：窗口只移了一格，k-1 个元素重复计算。每次从头扫 max 没有利用"上一个窗口的信息"

**最容易想错的岔路**：想用大顶堆（优先队列）。堆能 O(log k) 取 max，但删除离开窗口的元素需要 O(k) 查找——除非用惰性删除，代码复杂度飙升。面试中不推荐。

---

## 3. 核心洞察

- **关键不变量**：双端队列从队头到队尾严格递减（存下标）。队头下标对应的值就是当前窗口 max
- **命门**：为什么从队尾移除比当前值小的元素？因为它们**下标更老、值更小**——在当前元素存活期间，它们永远不可能成为最大值，属于"被永久淘汰"的候选人
- **不会漏解**：每个元素入队一次，真正的最大值永远不会被提前淘汰（只有更大的值才能淘汰它，而更大的值本身就是更好的答案）
- **容易误判**：
  - 不要和普通滑动窗口（双指针）混淆——那是窗口大小可变的场景
  - 不要和单调栈混淆——单调栈解决的是"下一个更大元素"，这里需要的是"窗口内最大"
  - 和 739. 每日温度的区别：739 是单调栈只需要单端操作，239 需要双端操作（前端也要删除过期元素）

---

## 4. 最优解怎么一步步长出来

1. **暴力**：每个窗口扫 k 个元素取 max，O(n×k)
2. **瓶颈**：窗口滑动一格，只有 1 个元素加入、1 个元素离开，但暴力重新扫了所有 k 个
3. **关键观察**：如果窗口内存在 `i < j` 且 `nums[i] ≤ nums[j]`，那么 `i` 永远不可能是 max（`j` 比它大且比它晚过期）。所以只需要保留一个"从旧到新递减"的候选序列
4. **最优解**：用双端队列维护这个递减序列。队尾入、队尾淘汰小值、队头淘汰过期值、队头取 max

**最容易想错的思维岔路**：用堆。堆能取 max 但不能高效删除任意元素。或者想用"记录窗口内 max 和次 max"——当 max 滑出窗口时，次 max 不一定正确（可能也过期了）。

## 5. 手推关键样例

`nums = [1, 3, -1, -3, 5, 3, 6, 7]`, `k = 3`

```
i=0: deque=[] → push 0. deque=[0(1)]. 窗口未满。
i=1: nums[0]=1 ≤ nums[1]=3 → 移除 0. push 1. deque=[1(3)]. 窗口未满。
i=2: nums[1]=3 > nums[2]=-1 → 保留. push 2. deque=[1(3), 2(-1)]. 
     ★ 窗口 [0,2] 满 → max = nums[1] = 3

i=3: nums[2]=-1 > nums[3]=-3 → 保留. push 3. deque=[1(3), 2(-1), 3(-3)].
     窗口 [1,3] → max = nums[1] = 3

i=4: deque 前端 1 仍在窗口 [2,4] 内? 1 < 2 → 移除 1!
     ★ 关键转折：旧的 max(3) 过期了
     然后 nums[3]=-3 ≤ 5 → 移除. nums[2]=-1 ≤ 5 → 移除.
     push 4. deque=[4(5)]. max = 5

i=5: nums[4]=5 > nums[5]=3 → 保留. push 5. deque=[4(5), 5(3)].
     窗口 [3,5] → max = 5

i=6: deque 前端 4 仍在窗口 [4,6]? 是. 
     nums[5]=3 ≤ 6 → 移除. nums[4]=5 ≤ 6 → 移除.
     push 6. deque=[6(6)]. max = 6

i=7: deque 前端 6 仍在窗口 [5,7]? 是.
     nums[6]=6 ≤ 7 → 移除.
     push 7. deque=[7(7)]. max = 7

result = [3, 3, 5, 5, 6, 7]
```

**关键转折在 i=4**：队头的 3 是之前的 max，但它的下标 1 已经出了窗口 [2,4]。这就是双端队列需要从前端也能删除的原因——单调栈做不到这一点。

## 8. Go 代码

```go
func maxSlidingWindow(nums []int, k int) []int {
	n := len(nums)
	result := make([]int, 0, n-k+1)
	deque := make([]int, 0, k) // 存下标，单调递减

	for i := 0; i < n; i++ {
		// 1. 队头过期：下标已出窗口
		if len(deque) > 0 && deque[0] < i-k+1 {
			deque = deque[1:]
		}
		// 2. 队尾淘汰：值 ≤ 当前元素的下标永远不可能是 max
		for len(deque) > 0 && nums[deque[len(deque)-1]] <= nums[i] {
			deque = deque[:len(deque)-1]
		}
		// 3. 当前下标入队
		deque = append(deque, i)
		// 4. 窗口满了，收集队头
		if i >= k-1 {
			result = append(result, nums[deque[0]])
		}
	}
	return result
}
```

**设计要点**：
- 队列存**下标**而非值——因为需要判断"是否过期"
- 淘汰条件是 `<=` 不是 `<`——相等的旧元素也该淘汰（下标更老，先过期，且不会比当前元素更优）
- 队头过期只需要 if 不需要 while——每轮最多只有一个元素过期（窗口只滑一格）
- 收集条件 `i >= k-1`——前 k-1 个元素窗口还没满

---

## 9. 最容易写错的地方

1. **队列存值而非存下标**：如果存值，无法判断队头是否已过期出窗。必须存下标
2. **淘汰条件写成 `<` 而非 `<=`**：相等时也应淘汰旧元素。旧的相等元素下标更小、更早过期，留着没意义。写成 `<` 不影响正确性但浪费队列空间
3. **队头过期判断写成 `while` 循环**：每轮窗口只滑一格，只有一个元素可能过期，用 `if` 足够。写 `while` 不会错但暴露你对机制理解不透彻
4. **收集时机错误**：在 `i < k-1` 时就开始收集，结果多出前几个不完整窗口的值
5. **面试追问：为什么不用堆？** 堆能 O(log n) 取 max，但删除滑出元素需要 O(n) 查找（或惰性删除加复杂度），总体 O(n log n) > O(n)。单调队列每个元素恰好进出一次，严格 O(n)
