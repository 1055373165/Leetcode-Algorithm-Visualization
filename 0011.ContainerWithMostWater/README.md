# 11. 盛最多水的容器：双指针的博弈

## 1. 审题（Problem）

### 1.1 约束解码
题目给定一个长度为 `n` 的整数数组 `height`。有 `n` 条垂线，第 `i` 条线的两个端点是 `(i, 0)` 和 `(i, height[i])`。
我们要找出两条线，使得它们与 $x$ 轴共同构成的容器可以容纳最多的水。
*   容量计算公式：$Area = \min(h[i], h[j]) \times (j - i)$
*   数据范围：$2 \le n \le 10^5$，这意味着 $O(n^2)$ 会超时，必须使用 $O(n)$ 或 $O(n \log n)$ 的解法。

### 1.2 边界陷阱
*   **数组长度**：最小为 2，无需处理空数组。
*   **高度差异**：高度可能为 0，虽然题意隐含由高度构成的容器，但在极值计算时要注意 0 的影响（面积为 0）。

### 1.3 问题归类
这是一个典型的 **双指针（Two Pointers）** 问题，同时蕴含了 **贪心（Greedy）** 的思想。我们需要在 $O(n)$ 时间内找到全局最优解，意味着我们每一步决策都必须排除掉一部分“绝对不可能成为最优解”的候选集。

## 2. 思维演化（Reasoning）

### 2.1 暴力解法：遍历所有组合
最直观的方法是计算所有可能的 $(i, j)$ 组合的面积，取最大值。
复杂度：$O(n^2)$。对于 $10^5$ 的数据量，计算次数高达 $5 \times 10^9$，绝对超时。

### 2.2 瓶颈分析：如何安全地缩小搜索空间？
面积由两个因素决定：**宽度** $(j - i)$ 和 **短板高度** $\min(h[i], h[j])$。
如果我们从两端开始，宽度是最大的。
此时，如果我们想让面积变大，唯一的希望是 **增加短板高度**。
*   如果移动长板：宽度减小，短板高度不可能增加（受限于另一端的短板）。面积一定变小。
*   如果移动短板：宽度减小，但新遇到的板子可能更高，从而让短板高度增加。面积 **有可能** 变大。

### 2.3 贪心策略
基于上述分析，我们的策略出来了：
1.  初始化左右指针 `left = 0`, `right = n - 1`。
2.  计算当前面积，更新最大值。
3.  **谁短谁动**：移动高度较小的那根指针，试图找到更高的板子。
4.  重复直到指针相遇。
这个策略保证了我们不会错过潜在的最大值，因为被舍弃的那一步（移动长板）产生的结果，一定不如当前结果。

## 3. 直觉培养（Intuition）

### 3.1 为什么移动短板？一图胜千言
想象你在和对手博弈。你的目标是围出最大的地盘。
现在的宽度已经是极限了。你的短板（比如左边）限制了你的蓄水量。
如果你保留这个短板，去移动另一边的长板（右边），你的蓄水量上限永远被左边这个短板锁死，而且宽度还在缩水。这完全是自杀行为。
唯一的求生之路，就是狠心抛弃这个短板，去赌一把，看看里面有没有更高的板子。

## 4. 代码实现（Solution）

```go
func maxArea(height []int) int {
	left, right := 0, len(height)-1
	var res int

	for left < right {
		// 计算当前宽度
		w := right - left
		
		// 计算当前高度（短板）
		// 并且谁短谁往中间移动
		var h int
		if height[left] < height[right] {
			h = height[left]
			left++
		} else {
			h = height[right]
			right--
		}

		// 更新最大面积
		if area := w * h; area > res {
			res = area
		}
	}

	return res
}
```

### 4.2 复杂度证明
*   **时间复杂度**: $O(n)$。双指针一左一右往中间走，每个元素只被访问一次。
*   **空间复杂度**: $O(1)$。只用了几个变量。

### 4.3 易错点清单
1.  **移动逻辑**：必须是 `if height[left] < height[right]` 移动左指针，否则移动右指针。如果相等，移动任意一个都可以（或者同时移动，但在代码里没必要特殊处理）。
2.  **宽高计算顺序**：先算宽度和高度，更新面积，**然后再** 移动指针。如果在移动指针后再算面积，宽度计算会出错（少 1），或者高度取错了索引。

### 5.2 核心思想沉淀
双指针法的核心在于 **“缩减搜索空间”**。我们不是漫无目的地移动，而是基于贪心逻辑，通过每一次比较，$O(1)$ 地排除掉一整行或一整列的无效解（那些以当前短板为边界，且宽度更小的组合）。这是一个将 $O(n^2)$ 空间剪枝成 $O(n)$ 的过程。
