# 11. 盛最多水的容器：双指针夹击下的贪心剪枝

## 1. 审题（Problem）

题目给定一个长度为 $n$ 的正整数数组 `height`，数组中的每个元素代表一条垂直的线段（端点为 $(i, 0)$ 和 $(i, height[i])$）。我们的目标是找出两条垂直线，使它们与 $X$ 轴共同构成的容器能够容纳下体积最大的“水”。这道题并没有考察水本身的物理流动，而是纯粹的几何面积计算：$Area = \min(h[i], h[j]) \times (j - i)$。

拿到这道题，我们首先注视它的数据范围：$2 \le n \le 10^5$。这个范围直接终结了所有形式的穷举：如果用两层循环去枚举所有可能的木板组合计算面积，时间复杂度会是 $O(n^2)$，计算操作将接近惊人的 $5 \times 10^9$ 次，在任何现代 OJ 平台上都必然会触发 Time Limit Exceeded。这种极具压迫感的数据规模是命题人强烈的暗示——我们在寻找一个 $O(n \log n)$ 甚至 $O(n)$ 的降维解法。

再来看边界陷阱：首先，题目保证了 $n \ge 2$，所以我们彻底省去了处理空数组或单元素这种极端用例的烦恼。其次，数组里的高度存在为 0 的可能性。虽然我们在直觉上觉得高度为 0 构不成“容器”，但在数学公式 $\min(0, h) \times width = 0$ 中，它的逻辑是自洽的，并不需要我们引入额外的边界判断或者防御性代码。

将“求极值（最多水）”、“数组/连续空间”以及对 $O(n)$ 时间复杂度的渴望组合在一起，这个特征轮廓已经完美吻合了 **双指针（Two Pointers）** 的画像。由于这道题还需要在每一步做出放弃某块木板的决断，它本质上也是披着双指针外衣的 **贪心（Greedy）** 算法。

## 2. 思维演化（Reasoning）

如果我们要驯服这道题，必须先从最蠢笨的思想起点出发。**暴力解法**：我们用两个嵌套的循环 $i$ 和 $j$，无差别地计算这 $n$ 根柱子两两配对所能围成的所有矩形面积，然后用一个变量记录并不断刷新历史最大值。这就是朴实无华的 $O(n^2)$ 逻辑。

这个解法的瓶颈极其明显——**状态爆炸与无效遍历**。我们对搜索空间的挖掘毫无章法，明知道有些组合连瞎子都能看出来“不可能更大”，却依然要用 CPU 周期去生吞活剥地计算它。

要打破瓶颈，我们就得沿着“缩减搜索空间”的降级路径深入挖掘。面积的决定权掌握在两个变量手里：底边的宽度 $(j - i)$ 和作为容器短板的最小高度 $\min(h[i], h[j])$。为了让面积最大化，我们的本能肯定是希望“又宽又高”。

那么，我们何不直接把宽度拉到物理极限？提出**假设**：我们把左指针 `left` 按在 $0$，右指针 `right` 按在 $n-1$。此时容器拥有举世无双的宽度极限。接下来，为了继续寻找有没有可能存在面积更大的容器，我们就必须逼迫这两个指针向内收缩。

此时遇到了真正的**卡点**：宽度是一定在不可逆转地减小的，如果我们还想让总面积变大，我们唯一的生机就全押在“高度必须变得非常高”上。
既然如此，我们到底该移动那根长板，还是那根短板？
如果你没有这种逻辑推演的习惯，你可能会被直觉欺骗，想着“保留两端高度的总和最大”。但这在短板效应（木桶原理）面前是徒劳的：
- **如果移动长板**：新出现的板子无论多高，容器的盛水高度永远被原先没动的那根短板死死压制。高度不仅无法增加，宽度还减小了，最后的面积**必定变小**。这完全是毫无意义的慢性自杀。
- **如果移动短板**：由于短板被我们抛弃了，新遇到的板子**有可能**比原来的短板高，从而一举打破高度的封锁线。即便宽度变小了，但如果高度的增幅足够猛烈，总面积是**可能变大**的。

基于上述验证，我们确定了不容置疑的**贪心剪枝策略**：每次都无情地抛弃当前两端中较短的那根板子，向内推进。每一次舍弃短板，我们都在 $O(1)$ 的时间内，排除了 $n-1$ 种绝对不如当前面积的劣质组合，将漫天的 $O(n^2)$ 搜索网撕开了一个巨大的口子，最终逼近了 $O(n)$ 的完美境界。

## 3. 直觉培养（Intuition）

你为什么能在考场上第一时间嗅到这种由两侧向内夹击的双指针气息？
因为“求面积极值”结合着公式 `Area = min(h[L], h[R]) * (R - L)`。这个公式里有两个博弈变量，而在一个未排序的数组中同时控制两个变量是令人绝望的。降维打击的精髓就在于：**利用极端状态固定一个变量，然后通过单调性来推演另一个变量。** 既然跨度极大化是确定无疑的优势，我们就从两端极点开局（固定了距离最大的优势），然后只剩下高度博弈。这种模型与“搜索矩阵/杨辉三角”的排除法是完全同构的。

我们可以用**职场谈判**来建立这个类比心智模型。
你手上有两张底牌准备和公司谈薪：你的“业务能力”（短板高度）和“吹牛画饼能拿到的上限”（长板高度）。公司卡你的薪资只看你的短板（业务能力不行，吹再多也白搭）。
为了让最终的薪水（面积）突破上限，你死抱着长板（吹大牛）继续深造有意义吗？没有。你必须忍痛抛弃现在业务能力的现状（移动短板指针），去寻找下一个能提升你硬实力的机会。只有把短板拔高了，长板的意义才能被释放。

## 4. 代码实现（Solution）

```
   ↑                               ↑
 left                            right      height: (1 < 7) → area = 1 * 8 = 8

Step 2: 1 太矮了，被无情抛弃，left 推进寻找高点
 [ 1,  8,  6,  2,  5,  4,  8,  3,  7 ]
       ↑                           ↑
     left                        right      height: (8 > 7) → area = 7 * 7 = 49

Step 3: 这次 7 成为了新的短板，right 收缩让路
 [ 1,  8,  6,  2,  5,  4,  8,  3,  7 ]
       ↑                       ↑
     left                    right          height: (8 = 3) → area = 3 * 6 = 18
```

### 核心代码

遵循 **Idiomatic Go** 的极简美学。在这里，我们用 `left`, `right` 作为指针的完美命名，用 `maxArea` 表达状态的核心累加器。

```go
func maxArea(height []int) int {
	left, right := 0, len(height)-1
	var maxArea int

	for left < right {
		// 计算此刻的物理宽度与木桶效应下的短板高度
		currentWidth := right - left
		var currentHeight int

		// 【核心】贪心博弈：无情抛弃当前较短的板子，向内求生
		if height[left] < height[right] {
			currentHeight = height[left]
			left++ // 抛弃左边短板
		} else {
			currentHeight = height[right]
			right-- // 抛弃右边短板 (就算高度相等，抛弃任意一边都一样)
		}

		// 用最新的体积冲击历史最高记录
		if area := currentWidth * currentHeight; area > maxArea {
			maxArea = area
		}
	}

	return maxArea
}
```

### 复杂度证明

- **时间复杂度**: $O(n)$。在这段干净的 `while(left < right)` 结构中，两个指针从数组的两端拉开阵势，每次循环必定有一个指针向中心逼近一步，直到它们相撞。整个数组 `height` 被不重不漏地扫描了一次，没有任何回溯或嵌套循环。
- **空间复杂度**: $O(1)$。我们仅仅声明了 `left`、`right`、`maxArea` 和少量的局部变量，分配的空间是常数级别的，没有借用任何哈希表、栈或其他耗费内存的高级结构。辅助空间消耗极为冷酷。

### 易错点与边界处理

- **高度相等的权衡**：如果 `height[left] == height[right]` 怎么办？这个时候移动哪边结果都是一样的。因为即使有一边内部有通天神柱，它的面积也会被我们没移动的这根板子死死压制。所以在 `if...else` 中用 `<=` 还是 `<` 并不影响正确性，直接抛弃其中一根即可。代码实现中归拢到了 `else` 分支直接右移，保证了代码的简洁度。
- **提前计算高度的逻辑陷阱**：在循环体内，必须要**先存下指针移动前的高度** (`currentHeight = height[left]`)，然后再将指针 `left++` 进行物理位移。如果你把代码写成了先位移再计算 `currentWidth * height[left]`，那么你计算的实际是“新木板”的体积，整个逻辑将土崩瓦解。

### S.8 核心洞察记忆（一句话总结）

**Top 1% 专家版示例（盛最多水的容器）**：舍弃盲目的二维穷举，将木桶原理转化为“控制最大宽度、单向猎取高度”的降维博弈；从物理极限的两极夹击，利用贪心定律无情剔除短板，每一次短板的内收都是在 $O(1)$ 时间内对 $O(n)$ 级别无效劣质组合的精准降维抹杀。

### 模板沉淀

遇到“数组两端”、“双重博弈约束”（例如这里的长与高）时，这套向心博弈的双指针模板是绝对的万能法则：

```go
func twoPointersGreedyTemplate(nums []int) int {
	left, right := 0, len(nums)-1
	bestResult := 0 // 依题意赋予极值初始态

	for left < right {
		// 1. 在变动前锁定当前的推演状态
		// current_state := evaluate(nums[left], nums[right])
		
		// 2. 将当前状态与最优解打擂台
		// bestResult = max(bestResult, current_state)

		// 3. 裁判进场：依据贪心法则寻找劣势方并无情淘汰
		if /* 左边是促使整体收益无法破局的短板/劣势方 */ {
			left++
		} else {
			right--
		}
	}
	
	return bestResult
}
```

### 面试锦囊

- **被问到“这难道不会错过最大值吗？凭什么移动短板就能跳过那么多检查？”**  
  这正是贪心正确性证明的关键。你可以非常坚定地反问："假设最优解在被我们忽略的组合中，这意味着保留原本的长板、移动短板会更好。但木桶的短板已经锁死了这根长板的贡献上限，无论长板如何内收去匹配什么神仙高度，由于宽度的永久性损耗，最后算出的面积绝对不可能超越刚才那一次。我们丢弃的不是希望，而是一定会失败的废料。"
- **如果追问“在计算宽度 $w$ 和高度 $h$ 后，能不能先过滤掉一些明显没用的柱子再进循环？”**  
  当然可以。在 `left++` 或 `right--` 后，可以通过内嵌的 `while` 循环快速跳过那些比当前短板还要矮的废柴柱子（`for height[left] <= currentHeight { left++ }`），因为它们绝无可能撑起更大的面积。这种极客级别的微操能极大地减少外层大循环中长宽乘法操作的指令数量。
