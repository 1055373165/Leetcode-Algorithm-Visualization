# 131. 分割回文串（Palindrome Partitioning）

## 0. 面试解题思路

这道题要求把一个字符串切成若干段，使得每一段都是回文串，并返回所有合法的切法。我拿到这道题之后，首先看数据范围——字符串长度最多 16，这个数字直接放行了指数级算法。然后看题目要求"返回所有方案"而非"最少切几刀"或"方案有多少种"，这意味着我必须实际枚举每一种合法分割，DP 求最值或计数的路子在这里行不通，回溯搜索是唯一合理的选择。

具体做法是：我从字符串的第 0 个位置出发，依次尝试切出长度为 1、2、...、n 的前缀，如果这段前缀是回文，就把它加入当前路径，然后对剩余部分递归处理；如果不是回文，这条分支直接跳过，不做无用功。当起始位置到达字符串末尾时，说明当前路径覆盖了整个字符串，是一个合法方案，收集起来。

为了加速每次"这段子串是不是回文"的判断，我会先用一个 $O(n^2)$ 的区间 DP 预处理一张回文表，这样每次查询就是 O(1) 而不是 O(n)。整体时间复杂度是 $O(n \cdot 2^n)$，空间复杂度是 $O(n^2)$，在 n=16 的约束下完全可行。

## 1. 问题本质

题目表面上在问"怎么切一个字符串使得每段都是回文"，但本质上这是一个**带约束的序列分割穷举问题**。一个长度为 n 的字符串有 n-1 个可以下刀的位置，每个位置切或不切，所以理论上的分割方式有 $2^{n-1}$ 种。题目的约束是"每段必须是回文"，而题目的目标是"列出所有满足约束的分割"。

这道题最关键的结构特征有两个。第一，它要的是"所有方案"而非"最优方案"或"方案数量"——这直接决定了算法范式必须是搜索而非 DP。第二，约束的判定（某段是否回文）具有**前缀独立性**：前面的切法是否合法，完全不影响后面某段子串是不是回文。这意味着我们可以在搜索过程中逐段验证、即时剪枝，而不需要等到切完整个字符串再回头检查。

## 2. 为什么是回溯而非其他方向

$n \le 16$，查复杂度约束表，$O(2^n) = 65536$，甚至 $O(n \cdot 2^n) \approx 10^6$，都在安全范围内。这个数据范围几乎是在喊"用指数级搜索"。

"返回所有方案"这个要求封死了纯 DP 的路。DP 的强项是计数和求极值，它通过合并等价状态来消除冗余，但合并的代价就是丢失了具体方案的细节。如果你试图用 DP 做这道题（比如 dp[i] 存"s[0..i] 的所有合法分割方案"），你会发现状态转移时需要拼接路径列表，时间和空间开销并不比回溯好，反而更难写。

贪心更不可能——不存在一个局部最优策略能保证生成所有合法方案。

所以方向非常明确：回溯搜索，以字符串的起始位置为递归参数，在每一层尝试所有可能的"第一刀"位置，用回文约束做剪枝。

## 3. 暴力思路与它的瓶颈

最暴力的做法是枚举 $2^{n-1}$ 种切法（n-1 个间隙，每个独立选择切或不切），然后对每种切法检查所有段是否都是回文。枚举量 $O(2^n)$，每种切法最多 n 段、每段回文检查 O(n)，总共 $O(n^2 \cdot 2^n)$。

这个暴力法的瓶颈不是算不完——n=16 时 $n^2 \cdot 2^n \approx 1.7 \times 10^7$ 其实还凑合——真正的问题在于它的思维模型是**先生成后过滤**：先把所有切法列出来，再逐一检验。这导致了大量"注定失败"的切法也被完整生成。比如你第一刀切出了 "ba" 这个非回文段，但暴力法不管这些，继续枚举后面的 $2^{n-3}$ 种切法，然后在验证阶段全部扔掉。这些工作量完全是浪费。

瓶颈类型是**无效遍历**：搜索空间中的大量分支在第一步就已经违反约束，却没有被提前终止。

## 4. 关键思维转折

**如果你没见过回溯剪枝的思路，你会卡在哪里？** 你会把"枚举切法"和"验证合法性"看成两个独立的阶段，先做完前者再做后者。打破这个思维惯性的关键在于意识到：验证可以嵌入到枚举过程中。

转折点在于观察到一个结构性质：一种分割方案合法，当且仅当它的**每一段**都是回文。这意味着如果第一段就不是回文，无论后面怎么切都不可能产生合法方案。于是我们可以把"枚举所有切法"转化为一棵搜索树——树的每一层代表从当前位置出发的一次切割选择，只有切出的那段是回文时才继续往下走。这就是从"生成-过滤"到"生成-验证-剪枝"的范式转换。

第二个转折是回文判断的优化。在搜索过程中，同一个子串可能在不同路径中被反复检查。比如 s[2..4] 这个子串可能在"第一刀切在 2、第二刀切在 4"和"第一刀切在 0、第二刀切在 2、第三刀切在 4"等多条路径中都被查一遍。预处理一张 `isPalin[i][j]` 的二维表，用区间 DP 在 $O(n^2)$ 时间内填好，每次查询从 O(n) 降为 O(1)。这是经典的"用空间换时间"，也是"消除重复计算"降级路径的体现。

## 5. 正确性论证

回溯的起点是 start=0，表示"从第 0 个字符开始，还没有做任何切割"。在每一层递归中，我们让 i 从 start 遍历到 n-1，尝试切出 s[start..i] 作为当前段。这个遍历覆盖了所有可能的"第一刀位置"，所以不会遗漏任何切法。

只有当 s[start..i] 是回文时才递归进入下一层，否则跳过。被跳过的分支中，s[start..i] 本身就不是回文，所以无论后续怎么切，整体方案都不可能合法。因此剪枝不会导致漏解。

当 start 到达 n 时，说明从位置 0 到 n-1 的所有字符都被某些段覆盖了，且每一段都通过了回文检查，所以当前路径必然是合法方案。

不会重复计算的原因在于：搜索树的每条从根到叶的路径对应一种唯一的切法。不同路径之间的切割位置序列一定不同（因为 i 在每一层是严格递增遍历的），所以不会生成重复方案。

## 6. 复杂度的真实来源

**时间复杂度：$O(n \cdot 2^n)$。** 预处理回文表是 $O(n^2)$，在 $n \le 16$ 的场景下被搜索部分主导。搜索树的最坏情况出现在全相同字符的输入（如 "aaaa...a"），此时每一段子串都是回文，搜索树的叶节点数等于 $2^{n-1}$（每个间隙都可以切也可以不切）。每个叶节点对应的路径长度最多为 n，收集答案时需要 O(n) 的拷贝操作。搜索树的内部节点数不超过叶节点数的常数倍（因为这是一棵多叉树，每个内部节点至少有一个子节点）。所以搜索部分的总代价为 $O(n \cdot 2^n)$。

**空间复杂度：$O(n^2)$（不计输出）。** 回文预处理表是 $n \times n$ 的布尔数组，占 $O(n^2)$。递归栈深度最多 n（每层至少消耗一个字符）。path 数组最多 n 个元素。这三者中 $O(n^2)$ 是主导。如果计入输出空间，最坏情况下合法方案数量本身就是 $O(2^n)$ 级别，每个方案平均长度 $O(n)$，总输出空间 $O(n \cdot 2^n)$。

## 7. 思路验证

用 s = "aab" 推演。

首先预处理回文表。单字符 isPalin[0][0]='a'=true，isPalin[1][1]='a'=true，isPalin[2][2]='b'=true。长度为 2 的：isPalin[0][1]，s[0]='a'==s[1]='a' 且 j-i==1，所以 true；isPalin[1][2]，s[1]='a'!=s[2]='b'，false。长度为 3：isPalin[0][2]，s[0]='a'!=s[2]='b'，false。回文表填完。

进入回溯，backtrack(0)，path 为空。

i=0：切出 s[0..0]="a"，isPalin[0][0]=true，path 变为 ["a"]，进入 backtrack(1)。在 backtrack(1) 中，i=1：切出 s[1..1]="a"，isPalin[1][1]=true，path 变为 ["a","a"]，进入 backtrack(2)。在 backtrack(2) 中，i=2：切出 s[2..2]="b"，isPalin[2][2]=true，path 变为 ["a","a","b"]，进入 backtrack(3)。start==3==n，收集 ["a","a","b"]。回溯：path 恢复为 ["a","a"]，再恢复为 ["a"]。回到 backtrack(1)，i=2：切出 s[1..2]="ab"，isPalin[1][2]=false，**跳过**。这一步是关键的剪枝——"ab" 不是回文，整条分支直接砍掉。回溯到 backtrack(0)。

i=1：切出 s[0..1]="aa"，isPalin[0][1]=true，path 变为 ["aa"]，进入 backtrack(2)。i=2：切出 "b"，回文，收集 ["aa","b"]。

i=2：切出 s[0..2]="aab"，isPalin[0][2]=false，跳过。

最终结果：[["a","a","b"], ["aa","b"]]。整个过程中只有两条路径走到了叶节点，"ab" 和 "aab" 两个非回文前缀被即时剪掉，避免了无效递归。

## 8. 易错点与边界

**区间 DP 的填表方向**是最常见的 bug 来源。计算 isPalin[i][j] 依赖 isPalin[i+1][j-1]，如果 i 从 0 向 n-1 遍历，当你算 isPalin[0][2] 时需要 isPalin[1][1]，这恰好已经算过（对角线先初始化了）。但如果 i 从 0 正序、j 也从 i+1 正序，当 j-i≥3 时 isPalin[i+1][j-1] 中 i+1 > i，在 i 正序遍历下 isPalin[i+1][*] 还没算到。所以 i 必须从 n-1 倒序遍历，或者改用"按区间长度从短到长"遍历。

**长度为 2 的子串需要特判**。isPalin[i][j] 的转移公式 `s[i]==s[j] && isPalin[i+1][j-1]` 在 j==i+1 时，i+1 > j-1=i，即 isPalin[i+1][i] 并不是一个有意义的子串。正确的处理是加一个短路条件 `j-i==1`，即长度为 2 的子串只需两端相等就够了。

**收集答案时必须深拷贝 path**。Go 的 slice 是引用类型，如果直接 `result = append(result, path)`，后续回溯修改 path 时会污染已收集的结果。必须 make 一个新 slice 并 copy。

**回溯时恢复现场**。`path = path[:len(path)-1]` 必须在递归返回后立即执行。这是回溯模式的基本纪律，但在 if 分支嵌套较深时容易遗漏。

## 代码实现

```go
func partition(s string) [][]string {
	n := len(s)

	// 区间 DP 预处理回文表
	isPalin := make([][]bool, n)
	for i := range isPalin {
		isPalin[i] = make([]bool, n)
		isPalin[i][i] = true
	}
	// 【核心】i 必须倒序，保证 isPalin[i+1][j-1] 已就绪
	for i := n - 1; i >= 0; i-- {
		for j := i + 1; j < n; j++ {
			isPalin[i][j] = s[i] == s[j] && (j-i == 1 || isPalin[i+1][j-1])
		}
	}

	var result [][]string
	var path []string

	var backtrack func(start int)
	backtrack = func(start int) {
		if start == n {
			tmp := make([]string, len(path))
			copy(tmp, path)
			result = append(result, tmp)
			return
		}
		for i := start; i < n; i++ {
			if isPalin[start][i] {
				path = append(path, s[start:i+1])
				backtrack(i + 1)
				path = path[:len(path)-1]
			}
		}
	}

	backtrack(0)
	return result
}
```

## 9. 方法论迁移

这道题的回溯框架——"从某个位置出发，尝试所有合法前缀，递归处理剩余部分"——是一类序列分割问题的通用结构。迁移时保留框架骨架，替换的只是"什么叫合法"这一个判断条件：

在 **93. 复原 IP 地址** 中，"合法"变成了"数值在 0-255 之间、无前导零、最多 4 段"，回溯框架完全不变，只是 isValid 函数换了，并且多了一个"最多切 3 刀"的剪枝条件。

在 **140. 单词拆分 II** 中，"合法"变成了"前缀在字典中"，回溯框架不变，isPalin 替换为字典查找。由于字典通常用 HashSet 存储，查找本身就是 O(1)，不需要预处理表。

在 **132. 分割回文串 II** 中，目标从"所有方案"变成了"最少切几刀"。这时回溯就不是最优选择了——因为只需要一个数值而非所有具体方案，DP 成为更好的工具：`dp[i]` 表示 s[0..i] 的最少分割数，转移方程为 `dp[i] = min(dp[j-1] + 1)`（对所有满足 isPalin[j][i] 的 j）。回文预处理表可以完全复用，但搜索框架被替换为一维 DP。

这个对比本身就很有教学价值：同一个问题的不同目标（列举所有方案 vs 求最优值）决定了截然不同的算法范式选择。回溯适合穷举，DP 适合求极值，两者的分水岭就在于"题目要的是什么"。
