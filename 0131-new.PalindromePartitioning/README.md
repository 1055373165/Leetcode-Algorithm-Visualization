# 131. 分割回文串：回溯搜索的剪枝与预计算

## 面试解题思路

一个长度为 n 的字符串，相邻字符之间有 n-1 个"间隙"，每个间隙要么切、要么不切——所以理论上最多有 $2^{n-1}$ 种切法。这道题要你找出所有合法的切法，使得每一段都是回文串。直觉上你会想枚举所有切法然后逐一验证，但仔细一想，大量切法在刚切出第一段的时候就已经不合法了——第一段都不是回文，后面切得再好也没用。这意味着我们不需要把 $2^{n-1}$ 种切法全部穷举完再过滤，而是可以在搜索树上尽早剪掉不合法的分支。这就是回溯的核心价值：在生成答案的过程中同步验证约束，而不是生成完再验证。

更进一步，回溯过程中每次判断一个子串是否是回文需要 O(n) 时间，而同一个子串可能在不同的搜索路径中被反复检查。如果我们用一张 $n \times n$ 的 DP 表预先算好所有子串的回文性，就能把每次判断压到 O(1)。

面试时可以这样说：这道题本质是在字符串的 n-1 个间隙上做子集枚举，但附带"每段必须是回文"的约束。我使用回溯法在每个位置尝试所有可能的切割长度，只有当前切出的子串是回文时才递归处理剩余部分。为了避免重复的回文判断，我先用区间 DP 预处理出一张 $O(n^2)$ 的回文表，使得每次判断为 O(1)。时间复杂度为 $O(n \cdot 2^n)$，空间复杂度为 $O(n^2)$。

## 审题

题目给定一个字符串 s，要求返回 s 所有可能的回文分割方案，其中每种方案是一个字符串数组，数组中的每个元素都是回文串，且它们按顺序拼接起来恰好等于 s。约束条件 $1 \le s.length \le 16$，字符仅包含小写英文字母。

n ≤ 16 这个数据范围非常关键。查约束解码表，$n \le 20$ 对应 $O(2^n)$ 级别的算法，这直接告诉我们：指数级复杂度是可以接受的，不需要追求多项式解法。题目要求返回"所有"方案而非计数或最优值，这进一步锁定了搜索类算法——你无法用 DP 直接输出所有具体方案（DP 擅长计数和求最值，不擅长枚举具体组合）。

"分割"意味着选择切割点，"回文"是对每一段的约束条件。这两个关键词组合在一起，指向的就是带约束的回溯搜索：在每个位置尝试不同长度的切割，用回文约束做剪枝。

边界方面：单字符一定是回文，所以最坏情况下把每个字符单独切出来一定是一个合法方案；空串不会出现因为 n ≥ 1；全相同字符（如 "aaa"）会产生较多的合法分割方案，是验证正确性时的好用例。

## 思维演化

最朴素的思路是先枚举所有 $2^{n-1}$ 种切法（每个间隙切或不切），然后对每种切法逐段检查是否都是回文。枚举切法 $O(2^n)$，每种切法最多 n 段，每段检查回文 O(n)，总复杂度 $O(n^2 \cdot 2^n)$。对于 n=16 来说大约 $1.7 \times 10^{10}$，已经偏慢了。但更核心的问题不是常数，而是这种"先生成后验证"的模式做了大量无用功：如果第一刀切出的子串就不是回文，后面无论怎么切都是废的，但暴力法依然会把后面的 $2^{n-2}$ 种切法全部穷举一遍。

瓶颈定位很清楚：**无效遍历**。大量搜索路径在第一步就已经违反约束，却没有被及时终止。

**如果你没见过回溯剪枝这个技巧，你会卡在哪里？** 你会试图在枚举完所有切法之后再过滤，而不是在枚举过程中就做约束检查。这两种思路的区别看似微小，但效率差异巨大——前者是"生成-过滤"范式，后者是"生成-验证-剪枝"范式。

关键的思维转折在于：把"选择切割点"这个组合问题转化为一棵搜索树。树的每一层对应字符串的一个起始位置 start，该层的分支对应从 start 开始、长度从 1 到 n-start 的所有可能切割。只有当切出的子串 s[start..i] 是回文时，才递归处理 s[i+1..] 这个子问题。当 start 到达字符串末尾时，当前路径就是一个合法方案。

这棵搜索树的规模在最坏情况下仍然是 $O(2^n)$（比如全 'a' 的字符串），但在大多数实际输入中，非回文的剪枝会砍掉大量分支。

第二个优化点：回溯过程中，对 s[start..i] 的回文判断会被反复调用。比如处理 "aab" 时，子串 "a" 会在不同的递归路径中被多次检查。我们可以预处理一张二维布尔表 `isPalin[i][j]`，表示 s[i..j] 是否是回文。这张表用区间 DP 在 $O(n^2)$ 时间内填好：单字符一定是回文，双字符看两端是否相等，更长的子串 `isPalin[i][j] = (s[i] == s[j]) && isPalin[i+1][j-1]`。填表之后，每次回文判断从 O(n) 降为 O(1)。

**正确性论证**：回溯搜索以 start 为起点，尝试所有可能的"第一刀"位置 i（start ≤ i < n），这保证了不会遗漏任何合法方案。每条从根到叶的路径恰好对应一种分割方式，且路径上的子串首尾相连覆盖整个字符串，所以不会多算也不会少算。回文约束的剪枝只跳过了"当前段不是回文"的分支，而这些分支无论如何都不可能产生合法方案，所以不会漏解。

## 代码实现

```go
func partition(s string) [][]string {
	n := len(s)
	// 预处理回文表：isPalin[i][j] 表示 s[i..j] 是否为回文
	isPalin := make([][]bool, n)
	for i := range isPalin {
		isPalin[i] = make([]bool, n)
		isPalin[i][i] = true // 单字符必为回文
	}
	// 【核心】区间 DP 填表，从短到长
	// 先处理长度为 2 的，再处理更长的
	for i := n - 1; i >= 0; i-- {
		for j := i + 1; j < n; j++ {
			if s[i] == s[j] {
				// 长度为 2 或者去掉两端后仍是回文
				isPalin[i][j] = (j-i == 1) || isPalin[i+1][j-1]
			}
		}
	}

	var result [][]string
	var path []string

	var backtrack func(start int)
	backtrack = func(start int) {
		if start == n {
			// 到达末尾，当前路径是一个合法分割
			tmp := make([]string, len(path))
			copy(tmp, path)
			result = append(result, tmp)
			return
		}
		for i := start; i < n; i++ {
			// 【核心】只有当 s[start..i] 是回文时才切这一刀
			if isPalin[start][i] {
				path = append(path, s[start:i+1])
				backtrack(i + 1)
				path = path[:len(path)-1] // 回溯
			}
		}
	}

	backtrack(0)
	return result
}
```

## 复杂度分析

**时间复杂度：$O(n \cdot 2^n)$**

回文预处理表的填表是 $O(n^2)$，这不是主导项。回溯搜索的时间取决于搜索树的节点数。最坏情况下（如 "aaaa...a" 全相同字符），每个间隙都可以切也可以不切，搜索树的叶节点数为 $2^{n-1}$。每个叶节点对应一条从根到叶的路径，路径长度最多为 n，收集答案时需要 O(n) 复制。所以搜索部分的总代价是 $O(n \cdot 2^n)$。在实际输入中，非回文的剪枝会大幅减少实际搜索量，但最坏情况仍是指数级。

**空间复杂度：$O(n^2)$**

回文预处理表占用 $O(n^2)$。递归栈深度最多 n 层，占用 O(n)。path 数组最多 n 个元素。不计输出空间的话，辅助空间主导项是 $O(n^2)$ 的预处理表。如果计入输出空间，最坏情况下答案数量本身就是 $O(2^n)$ 级别。

## 思路验证

用 s = "aab" 手动推演。

回溯从 start=0 开始。第一轮尝试切 s[0..0]="a"，查表 isPalin[0][0]=true，进入递归 backtrack(1)。在 backtrack(1) 中，先尝试切 s[1..1]="a"，isPalin[1][1]=true，进入 backtrack(2)。在 backtrack(2) 中，切 s[2..2]="b"，isPalin[2][2]=true，进入 backtrack(3)。start==3==n，收集 ["a","a","b"]。回溯到 backtrack(2) 没有更多选择，回溯到 backtrack(1)。尝试切 s[1..2]="ab"，isPalin[1][2]=false（'a'!='b'），**剪枝跳过**——这是整个搜索过程中最关键的一刀：如果没有回文判断，这里会白白递归下去。回溯到 backtrack(0)。

第二轮尝试切 s[0..1]="aa"，isPalin[0][1]=true（两端相等且长度为 2），进入 backtrack(2)。切 s[2..2]="b"，进入 backtrack(3)，收集 ["aa","b"]。

第三轮尝试切 s[0..2]="aab"，isPalin[0][2]=false（'a'!='b'），剪枝跳过。

搜索结束，结果 [["a","a","b"], ["aa","b"]]，与预期一致。注意整个过程中 "ab" 和 "aab" 两个非回文子串被直接跳过，分别避免了 1 次和 0 次无效递归——在更长的字符串上这种剪枝的收益会显著放大。

## 易错点与边界

**回文表的填表顺序**：区间 DP 要求在计算 isPalin[i][j] 时，isPalin[i+1][j-1] 已经算好。如果外层循环 i 从小到大遍历就会出错，必须 i 从大到小（或者按区间长度从短到长遍历）。这是这道题最常见的实现 bug。

**收集答案时必须深拷贝**：path 是复用的切片，直接 append 到 result 中会导致后续回溯修改 path 时连带修改已收集的答案。必须用 `copy` 或重新分配。

**回溯的"恢复现场"**：`path = path[:len(path)-1]` 必须在递归返回后立即执行，且只在进入递归之前 append 过的情况下才执行。在 Go 中这个模式很直接，但在某些语言中容易遗漏。

**isPalin[i][j] 中 j-i==1 的特判**：长度为 2 的子串不存在"去掉两端后的子串"（空串），需要单独判断。如果漏掉这个条件，isPalin[i+1][j-1] 会访问 isPalin[i+1][i]（i+1 > i 时数组越界或语义错误）。实现中通过 `(j-i == 1) || isPalin[i+1][j-1]` 短路求值来处理。

## 核心洞察

"枚举所有分割方案"本质上等价于在 n-1 个间隙上做子集选择，但回文约束使得大量子集非法。回溯法的价值在于将"子集枚举"转化为"前缀驱动的深度搜索"：每一层只尝试以当前位置为起点的回文前缀，非回文前缀被即时剪掉，使搜索树的实际规模远小于 $2^{n-1}$。预处理回文表则是用 $O(n^2)$ 的一次性空间换取搜索过程中每次 O(1) 的回文判断，这个 trade-off 在 n ≤ 16 的约束下几乎没有代价。
