# 5. 最长回文子串：中心开花的对称美学

## 1. 审题（Problem）

给定一个字符串 `s`，找到 `s` 中最长的回文子串。数据范围：$1 \le n \le 1000$。

先做约束解码。$n = 1000$ 意味着 $n^2 = 10^6$，完全在安全区；而 $n^3 = 10^9$，已经踩在超时的边缘线上。题目在暗示我们：至少需要一个 $O(n^2)$ 的解法，$O(n^3)$ 可能勉强过但绝非面试官想看到的答案。问题类型上，"最长子串"容易让人联想到动态规划或滑动窗口，但回文天生的**对称性质**又打开了另一条路——中心扩散。这道题处在字符串处理与动态规划的交叉地带，两种范式都能解，但最终的胜者是利用结构特征的那个。

边界陷阱方面需要格外留意。单字符串直接返回自身，因为长度为 1 就是回文。全相同字符如 `"aaaaa"` 整个串就是答案，代码必须能处理"扩散到头"的情况而不越界。最容易忽略的是**偶数长度回文**：`"abba"` 的对称中心不在任何一个字符上，而是落在 `b` 和 `b` 之间的间隙里。如果你的解法只考虑了以单个字符为中心的扩散，`"abba"` 就会被漏掉——这是本题最经典的坑。

## 2. 思维演化（Reasoning）

### 暴力基线

最朴素的思路是什么？枚举所有可能的子串，逐个检查是否为回文。子串有 $O(n^2)$ 个，每次检查需要 $O(n)$ 的扫描，总复杂度 $O(n^3)$。

```go
// 暴力解：O(n³)，正确但慢
func longestPalindromeBrute(s string) string {
    n := len(s)
    res := s[:1]
    for i := 0; i < n; i++ {
        for j := i + 1; j <= n; j++ {
            if isPalin(s[i:j]) && j-i > len(res) {
                res = s[i:j]
            }
        }
    }
    return res
}

func isPalin(s string) bool {
    for l, r := 0, len(s)-1; l < r; l, r = l+1, r-1 {
        if s[l] != s[r] {
            return false
        }
    }
    return true
}
```

虽然笨拙，但暴力解锚定了我们的理解：目标是在所有子串中找到最长的那个回文。

### 瓶颈定位

暴力解为什么慢？想象你已经验证了 `"aba"` 是回文，接下来检查 `"xabax"` 时，又从头到尾逐字符扫描了一遍。你完全浪费了 "aba 是回文"这个已知信息。这是典型的**重复计算**瓶颈——相同子问题被反复求解。瓶颈的定位指向了优化方向：消除重复计算。

### 优化演化链

**第一步：DP 消除重复计算（$O(n^3) \to O(n^2)$ 时间，但空间变为 $O(n^2)$）**

沿着"消除重复计算"这条降级路径，我们自然想到动态规划。定义 $dp[i][j]$ 表示子串 $s[i..j]$ 是否为回文。一个子串是回文当且仅当两端字符相同、且去掉两端后的内部子串也是回文：

$$dp[i][j] = (s[i] == s[j]) \text{ and } dp[i+1][j-1]$$

这样每次判断只需 $O(1)$ 查表，总时间 $O(n^2)$。但代价是一个 $n \times n$ 的布尔数组——$n = 1000$ 时需要百万级的存储。能不能把空间也降下来？

**这里是卡点。** 如果你停留在 DP 的思维框架里，你会尝试用滚动数组压缩空间。但 $dp[i][j]$ 依赖 $dp[i+1][j-1]$，这是对角线方向的依赖，滚动数组压缩并不直接适用，实现起来容易出错。你可能折腾半天，空间也只能从 $O(n^2)$ 降到 $O(n)$，还额外增加了代码复杂度。

**第二步：中心扩散，利用问题结构（$O(n^2)$ 时间，$O(1)$ 空间）**

要突破这个卡点，需要一次视角转换。DP 和暴力法有一个共同的思维定式：**枚举子串的两个端点 $(i, j)$**。但回文有一个天然的结构特征——对称性。每个回文串都有一个中心，从中心向两侧展开，字符完全镜像。与其"枚举端点再检查内部"，不如**枚举中心向外扩散**。

一个长度为 $n$ 的字符串有多少个可能的回文中心？奇数长度的回文中心落在某个字符上，有 $n$ 个；偶数长度的回文中心落在两个相邻字符之间，有 $n - 1$ 个；总计 $2n - 1$ 个中心。对每个中心向两侧扩散，当字符匹配时继续推进，不匹配时停止，就能找到以该点为中心的最长回文。整个过程只需要几个变量记录当前最优，不需要任何额外的数组。

用复杂度降级分类法总结这条完整的演化链：

| 解法 | 降级路径 | 时间 | 空间 |
|:-----|:---------|:----:|:----:|
| 暴力枚举 | — | $O(n^3)$ | $O(1)$ |
| 动态规划 | 消除重复计算 | $O(n^2)$ | $O(n^2)$ |
| 中心扩散 | 利用问题结构（对称性） | $O(n^2)$ | $O(1)$ |
| Manacher | 进一步利用已知回文半径 | $O(n)$ | $O(n)$ |

面试中，中心扩散是最优通用解——时间与 DP 持平，空间碾压 DP，代码简洁易写。Manacher 虽然理论最优，但实现复杂度高，在 $n = 1000$ 时优势不显著，风险远大于收益。

## 3. 直觉培养（Intuition）

### 为什么能想到中心扩散？

"回文"这个关键词本身就是最大的信号。回文的定义——正着读和倒着读一样——天然暗示了**对称性**。当一个问题的核心对象具有对称结构时，从中心出发向两侧展开几乎总是比从边界出发向内收缩更自然、更高效。在信号-模式表中，"回文"直接映射到"中心扩散"或"区间 DP"两种模式，而中心扩散在空间复杂度上占优。

如果你不知道中心扩散这个技巧，你大概率会沿着 DP 的路走。你会定义 $dp[i][j]$，写出转移方程，拿到一个可以工作的 $O(n^2)$ 方案。然后你可能会尝试优化空间，折腾滚动数组，但因为依赖方向是对角线，压缩起来并不顺畅。这时候如果你退一步，问自己**"回文的本质特征是什么？"**——对称——就会意识到：不需要枚举所有端点对，只需要枚举中心。这个视角转换打开了一条全新的路。

### 类比

中心扩散就像往平静的池塘里丢石子。石子落点是回文的中心，涟漪从落点向外扩散，直到碰到岸边（字符不匹配）才停下。你在池塘的每个位置各丢一颗石子，涟漪扩散最远的那个落点，就对应最长回文的中心。奇数长度回文是石子正中落在一滴水珠上，偶数长度回文是石子落在两滴水珠的缝隙之间——这也解释了为什么我们需要分别处理这两种情况。

### 模式关联

这道题是单一模式（中心扩散）的经典应用。但这里锻炼出的思维方式——**从结构特征出发选择枚举策略**——在更复杂的回文题目中会和其他模式组合。比如 #131 回文分割需要回溯 + 回文预处理，#214 最短回文串需要 KMP + 回文性质，#647 回文子串计数是中心扩散的直接变体。掌握了"遇到回文就想中心扩散"这条直觉通路，这些变体题都不再陌生。

## 4. 代码实现（Solution）

Step 3: [b]   a    b    a   [d]       s[0]='b' != s[4]='d' ✗

### 核心代码

```go
func longestPalindrome(s string) string {
	n := len(s)
	if n < 2 {
		return s
	}

	start, maxLen := 0, 1

	// expand 从 (l, r) 向两侧扩散，实时更新全局最优
	expand := func(l, r int) {
		for l >= 0 && r < n && s[l] == s[r] {
			if cur := r - l + 1; cur > maxLen {
				start = l
				maxLen = cur
			}
			l--
			r++
		}
	}

	for i := 0; i < n; i++ {
		expand(i, i)   // 【核心】奇数长度：以 s[i] 单字符为中心
		expand(i, i+1) // 【核心】偶数长度：以 s[i], s[i+1] 间隙为中心
	}

	return s[start : start+maxLen]
}
```

代码只做一件事：遍历每个可能的中心，向两侧扩散。`expand` 函数是整个算法的心脏——它接受一对初始位置 `(l, r)`，向外推进直到字符不匹配或越界。对于奇数长度回文，`l == r`（同一位置）；对于偶数长度，`l + 1 == r`（相邻位置）。扩散过程中实时更新全局最优的 `start` 和 `maxLen`，避免了扩散结束后反推起止点的复杂计算——这也是比"先返回长度再算 `start`"更不容易出错的写法。

变量命名遵循 Unix 哲学：`l`/`r` 简洁明了，`expand` 直白描述行为，没有过度封装。闭包捕获外部的 `start`/`maxLen` 让两次调用（奇数/偶数）自然共享状态，比传参返回值更干净。

### 复杂度证明

**时间复杂度：$O(n^2)$。** 外层循环遍历 $n$ 个位置，每个位置调用两次 `expand`。单次 `expand` 最坏扩散到字符串两端，即 $O(n)$ 次字符比较。总计 $2n$ 次 `expand` 调用，每次最多 $O(n)$，因此总时间为 $O(n^2)$。最坏情况出现在全相同字符（如 `"aaaa"`），此时每个中心都扩散到最远。平均情况下，大多数中心只扩散几步就会碰到不匹配，实际运行远快于理论上界。

**空间复杂度：$O(1)$。** 只使用了 `start`、`maxLen`、循环变量 `i` 和 `expand` 内部的 `l`、`r`、`cur`，没有分配任何额外的数组或哈希表。这比 DP 方案的 $O(n^2)$ 空间优势显著。输出的子串 `s[start : start+maxLen]` 在 Go 中是原字符串的切片引用，不产生额外拷贝。

### 易错点

1. **偶数长度遗漏**：只写 `expand(i, i)` 而忘记 `expand(i, i+1)`，会漏掉所有偶数长度回文（如 `"abba"`）。这是最高频的 bug。
2. **起止点反推公式**：另一种常见写法是让 `expand` 返回回文长度，然后用 `start = i - (len-1)/2` 反推。这个公式依赖整数除法的截断特性，对奇偶长度都成立但不直观，容易在紧张时写错。直接在 `expand` 内部更新 `start` 和 `maxLen`（如上方代码）更安全。
3. **切片边界**：Go 的 `s[start : start+maxLen]` 是左闭右开区间。如果你用 `start`/`end` 双变量记录，最终切片是 `s[start : end+1]`，不要遗漏 `+1`。
4. **`maxLen` 初始值**：必须初始化为 1（任何非空字符串至少包含一个长度为 1 的回文），`start` 初始化为 0。如果初始化为 0 会导致返回空串。

## 5. 融会贯通（Mastery）

### 变体题群

| 题目 | 变化点 | 解法调整 |
|:-----|:-------|:---------|
| **5. 最长回文子串** | 求最长回文内容 | 中心扩散，$O(n^2)$ 时间 $O(1)$ 空间 |
| **647. 回文子串** | 求回文子串总个数 | 中心扩散，每次 `expand` 匹配成功时 `count++` 而非更新最长 |
| **516. 最长回文子序列** | 子序列（不要求连续） | 中心扩散失效，必须用区间 DP：$dp[i][j] = dp[i+1][j-1] + 2$（若 $s[i]==s[j]$） |
| **131. 回文分割** | 将串切为全回文子串的所有方案 | 回溯 + 预处理回文判断表（DP 或中心扩散均可预处理） |
| **214. 最短回文串** | 前面添加最少字符使整体成回文 | 找最长前缀回文，KMP 或 Manacher |
| **336. 回文对** | 两两拼接形成回文的所有下标对 | Trie + 回文后缀/前缀判断 |

关键区分：**子串**（连续）问题用中心扩散，**子序列**（不连续）问题必须用 DP。面试时先确认题目要求的是哪一种。

### 模板沉淀

中心扩散法的通用骨架，适用于所有"枚举回文"场景：

```go
// 中心扩散通用模板
// 适用于：最长回文子串、回文子串计数、回文子串枚举
func centerExpansionTemplate(s string) {
    n := len(s)

    expand := func(l, r int) {
        for l >= 0 && r < n && s[l] == s[r] {
            // TODO: 根据题意处理当前回文 s[l..r]
            // 求最长 → 更新 start/maxLen
            // 求个数 → count++
            // 求所有 → append(results, s[l:r+1])
            l--
            r++
        }
    }

    for i := 0; i < n; i++ {
        expand(i, i)   // 奇数长度
        expand(i, i+1) // 偶数长度
    }
}
```

### 面试锦囊

- **"还有其他解法吗？"** → 三种主要解法，从简单到复杂依次递进：暴力 $O(n^3)$、DP $O(n^2)$ 时间 $O(n^2)$ 空间、中心扩散 $O(n^2)$ 时间 $O(1)$ 空间。如果面试官追求极致，还有 Manacher 算法 $O(n)$。
- **"能优化到 $O(n)$ 吗？"** → 可以。Manacher 算法利用已计算的回文半径来加速后续中心的扩散，核心思想类似 KMP 的失配跳转。但实现极为复杂，在 $n = 1000$ 时优势不显著。面试中能清晰写出 $O(n^2)$ 的中心扩散且 bug-free 才是最佳策略。
- **"如果改成最长回文子序列呢？"** → 中心扩散不再适用，因为子序列不要求连续，无法通过向两侧扩散来发现。需要转为区间 DP：$dp[i][j]$ 表示 $s[i..j]$ 的最长回文子序列长度，复杂度 $O(n^2)$。
- **"为什么不用滑动窗口？"** → 滑动窗口适用于具有**单调性**的连续子串问题（扩大窗口时条件只会从满足变为不满足，或反之）。回文不具备这种单调性——`"aba"` 是回文不意味着包含它的 `"xabax"` 不是回文，反之亦然。因此窗口无法有效伸缩。
- **"时间不够怎么办？"** → 先写暴力解拿到基础分，口述中心扩散的思路让面试官看到你的思维过程。能写多少算多少，核心是让面试官确信你理解了"枚举中心"这个洞察。
