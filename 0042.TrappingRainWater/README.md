# 42. 接雨水：从木桶效应到双指针极致优化

## 1. 审题（Problem）

### 1.1 约束解码
给定 `n` 个非负整数表示每个宽度为 1 的柱子的高度图，计算按此排列的柱子，下雨之后能接多少雨水。
数据范围：$n \le 2 \times 10^4$，这意味着 $O(n^2)$ 解法（$4 \times 10^8$）会超时，必须寻求 $O(n)$ 的解法。

### 1.2 边界陷阱
*   **高地效应**：如果两边低中间高（凸字形），接不到任何水。
*   **平原效应**：如果高度全为 0 或全相等，也接不到水。
*   **边缘效应**：数组两端的柱子（索引 0 和 n-1）因为没有更外侧的挡板，永远存不住水（除非题目假设边界无限高，但本题不是）。

### 1.3 问题归类
这是一个经典的 **数组/双指针** 问题。核心在于理解“水是如何被留住的”。
对于任意位置 `i`，它能接的水量 = $\min(\text{左边最高柱子}, \text{右边最高柱子}) - \text{它自己的高度}$。
如果结果是负数，则为 0。

## 2. 思维演化（Reasoning）

### 2.1 暴力解法：每个柱子问一遍
对每个位置 `i`，向左扫描找 `max_left`，向右扫描找 `max_right`。
复杂度：$O(n^2)$。这就是我们在 LeetCode 11 中分析过的“无脑扫描”，不可行。

### 2.2 动态规划：空间换时间
既然每次都要找 `max_left` 和 `max_right`，不如先把它们存起来？
*   `left_max[i]` = $\max(height[0 \dots i])$
*   `right_max[i]` = $\max(height[i \dots n-1])$
我们需要两次遍历生成这两个数组，然后再遍历一次计算水量。
时间 $O(n)$，空间 $O(n)$。这已经通过了，但面试官通常会问：能把空间降到 $O(1)$ 吗？

### 2.3 双指针：木桶原理的动态博弈
回顾公式：$Water[i] = \min(\text{max\_left}, \text{max\_right}) - height[i]$。
决定水桶短板的，是 `max_left` 和 `max_right` 中较小的那个。
假设我们维护两个指针 `left` 和 `right`，以及目前为止遇到的 `max_l` 和 `max_r`。
*   如果 `max_l < max_r`：说明左边是短板。对于 `left` 指针指向的位置，它的右边虽然可能有比 `max_r` 更高的柱子，但那不重要！因为它已经被当前的 `max_r`（或者更高的未知柱子）挡住了。瓶颈完全取决于 `max_l`。所以我们可以放心地结算 `left` 位置的水量。
*   反之亦然。

## 3. 直觉培养（Intuition）

### 3.1 为什么双指针是对的？
想象两堵墙从两边往中间挤。
*   左边的墙（`max_l`）比较矮，右边的墙（`max_r`）比较高。
*   站在左边墙脚下的这个柱子（`left`），它心里清楚：“虽然我不知道右边最远方是否有比 `max_r` 更高的山峰，但我知道右边至少有一堵 `max_r` 这么高的墙挡着。不仅如此，我左边这堵 `max_l` 比右边那堵墙还矮。所以，这一刻，决定我头顶水位的，只能是左边这堵矮墙。”

## 4. 代码实现（Solution）

```go
func trap(height []int) int {
	if len(height) == 0 {
		return 0
	}

	left, right := 0, len(height)-1
	maxLeft, maxRight := 0, 0
	var res int

	for left < right {
		// 每次我们也需要先更新当前遇到的最高柱子
		if height[left] > maxLeft {
			maxLeft = height[left]
		}
		if height[right] > maxRight {
			maxRight = height[right]
		}

		// 核心策略：谁对应的那边最高柱子矮，谁就结算
		// 为什么？因为水桶装水取决于短板。
		if maxLeft < maxRight {
			// 对于 left 来说，它左边的最高是 maxLeft。
			// 它右边的最高至少是 maxRight（甚至可能更高）。
			// 既然 maxLeft < maxRight，那短板一定是 maxLeft。
			// 水量 = maxLeft - height[left]（注意：如果 height[left] 就是 maxLeft，则为 0）
			res += maxLeft - height[left]
			left++
		} else {
			// 同理处理右边
			res += maxRight - height[right]
			right--
		}
	}

	return res
}
```

### 4.2 复杂度证明
*   **时间复杂度**: $O(n)$。左右指针相遇即停止，每个元素只被访问一次。
*   **空间复杂度**: $O(1)$。只使用了常数个变量。

### 4.3 易错点清单
1.  **更新 Max 的时机**：可以在移动前更新，也可以在移动后更新。推荐在判断 `if maxLeft < maxRight` 之前，先把当前的 `height[left]` 纳入 `maxLeft` 的考量。代码中为了清晰，是先更新 max 值，再计算差值。如果 `height[left]` 就是 `maxLeft`，差值为 0，逻辑自洽。
2.  **空数组判断**：虽然题目约束 $n \ge 0$，但加上 `len == 0` 的判断是工程上的好习惯。

### 5.2 模式识别
当问题涉及 **“柱子水位”、“单调边界”** 时，通常有三种解法：
1.  **DP**：适用于需要多次查询或逻辑比较复杂的场景。
2.  **单调栈**：适用于找“第一个比我大/小”的元素，通常能解决更复杂的坑洼形状问题。
3.  **双指针**：最简便，专门解决“两头往中间挤”且“短板决定结果”的问题。面试首选。
