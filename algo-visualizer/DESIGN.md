# 算法可视化设计语言

## 召唤

动手画第一帧之前，你同时寓居于四位幽灵的身体里。

Tufte 盯着你屏幕上每一个像素，反复问：这里的墨水在传递什么信息？如果它什么都不传，就擦掉。Bret Victor 坐在旁边，每当你打算用一段文字解释屏幕上正在发生什么，他就敲你一下——让图自己说话，文字只做注脚。Tamara Munzner 用"编码正确性"检查你：颜色应当只编码类别，位置编码量级，方向编码因果，你不能混。Chase & Simon 在你身后盯着观众的瞳孔，提醒你：普通人一眼只能抓住三到五个视觉块，超过就会丢。

这四个人不会轮流说话，他们同时说话。你的任务是让他们的约束同时被满足。

---

## 第一原理：视频是让算法**自明**的装置

一个算法是否被理解，不取决于观众能否复述它的步骤，而取决于观众在下一道同族问题上能否**独立重演**它的结构感。视频存在的唯一理由，是把那个结构感——那些通常只活在老手直觉里的不变量、单调性、守恒关系——**变成观众眼睛可以直接看见的东西**。

由此推出三条不可妥协的承诺。

**第一，可视即论证。** 任何一幅图、一段动画、一帧快照，必须让某条原本需要推理才能相信的性质**一眼自明**。如果观众需要读下面的字幕才能理解画面，这帧画面就是失败的。观众读字幕的那一秒，他的视觉通道是关闭的——你用动画建立的所有感知资本，那一秒全部退化为一条被动阅读的文字信息。

**第二，不变量比步骤更持久。** 算法真正的主角是那个在时间轴上始终为真的命题。窗口里永不重复、栈内严格递减、二分区间永远包含答案——这些不能埋在描述文字里，必须有**持续可见的视觉物质**。持久不变量 + 瞬时变化的组合，就是算法直觉的形状。

**第三，运动即语义。** 两帧之间的连续补间不是美化，是信息通道。瞬时切换让观众无法追踪"什么变了"——因为一切都变了。平滑运动使得观众的前额叶注意力不必重建场景，他可以**跟随**变化，而不是对比两个静止镜头。一个好的算法动画，**不关声音、不看文字，只看画面的陌生人也能说出算法大概在做什么**。这是我们检验一条动画是否合格的唯一试金石。

## 四重感官

### 信息设计之眼（Tufte）

数据墨水比应当最大化。每一个像素都在编码语义或必要的视觉结构，否则擦掉。

反例：阴影、渐变、圆角、装饰性边框、巨大的 emoji。它们不传递任何关于算法的信息，只消耗观众的注意力预算。圆角只在我们想表达"这是一个数据块的边界"时使用；阴影只在我们想表达"这个元素在另一个上层"时使用；从不为了"看起来更柔和"而使用。

### 可操纵感之眼（Bret Victor）

算法的状态应当是**可触的**。不是一张图示，而是一个物体。指针有位置，有质量，有惯性——它从 i 移动到 i+1 不应该瞬变，应该像物体一样滑过去。栈是一个真实的容器，它有底，它的元素从上面入、上面出。窗口不是一组被高亮的独立单元格，它是一个有**支架**的结构，支架跟随左右指针拉伸。

观众不该感觉自己在看一张图表，他该感觉自己在观察一台正在运行的机器。

### 视觉编码正确性之眼（Munzner）

每一种视觉变量只能编码一种语义维度。在我们的系统里这是硬约束：

- **颜色** → 类别（指针角色、元素状态），永不编码量级
- **位置** → 序关系与结构（数组下标、栈深度、树的父子）
- **大小** → 量级（数值大小、权重）
- **透明度** → 时间相关性（刚刚发生 vs 历史、活跃 vs 已失效）
- **运动方向** → 因果（a 变了→ b 随之变）
- **描边（stroke）** → 焦点（此刻正在被处理的对象）

跨越这些编码的混用是设计债务的最大来源。一个元素**只能同时承担**一种视觉角色——如果一个格子既要表达"此刻是 mid"又要表达"属于有序半区"，必须把两个语义拆到不同视觉通道上（例如位置+描边，而不是两种背景色叠加）。

### 认知负荷之眼（Chase & Simon、Sweller）

观众的工作记忆大约只能同时持有四个视觉块。这不是比喻，是硬约束。屏幕上同时可见的**独立语义单元**不得超过五个，超过就必须做分组、收纳、淡化。

对抗这个约束的武器叫**层级**：

- 主角层（primary）——此刻正在变化的对象，最高亮度、最饱和颜色
- 关系层（relational）——与主角有关的对象，次高亮度  
- 背景层（context）——其他数据，降饱和、降亮度、缩小
- 不变量层（invariant）——持久显示的结构性命题，窄条带，不抢焦点但一直存在

每一帧，观众的眼睛应当被这个层级**引导**——他看到的第一眼是主角，第二眼是主角的关系，第三眼才是背景。

## 五条视觉暗轴

在动笔画第一帧之前，先用这五条轴扫描一遍这道算法。它们决定了你的视频是否会成为**新的直觉**。

**不变量轴。** 这道算法有什么在整个执行过程中始终为真？把它用一句 6 个字以内的口令写出来（"窗口内无重复"、"栈内严格递减"、"堆顶是第 K 大"），安置在屏幕顶部的 `InvariantBand` 里。这条带子在整段视频里**不消失**，它是观众在任何时刻迷路时可以回到的锚点。

**运动主线轴。** 这段算法的"主要运动"是什么？是左右指针的相向移动？是栈的涨落？是 DP 表的自左向右填充？是递归的深入与回退？识别这条主线，让它在画面的中央、用最大的视觉面积演出。其他所有东西都是伴奏。

**结构容器轴。** 这道算法的抽象结构是什么——是一个窗口、一个栈、一棵树、一张表、一张图？结构本身应当有**视觉物质**：窗口有支架，栈有底座，表有坐标轴，树有连线，图有节点。裸的数组+高亮颜色**不够**——它把结构降级成了一堆被涂色的方块。

**残留轨迹轴。** 观众看到第 K 帧时，他能看出前面 K-1 帧走过哪里吗？一个已处理但不再是当前焦点的元素，应当保留**微弱但可辨**的视觉痕迹——通常是降低饱和度、保留微小描边。这种残留让观众任何时刻都能看出"走到哪了"、"还剩多少"，而不需要回想。

**鸣声轴。** 算法有高潮时刻（冲突出现、答案被捕获、栈第一次清空）和平凡时刻（常规推进）。这两种时刻必须有不同的视觉与节奏强度——平凡时刻用较短步长一笔带过，高潮时刻用较长步长加 callout 强调。所有步骤统一节奏的视频是**平的**，平的视频让观众大脑进入"这个我看懂了"的错觉，然后什么也没记住。

## Stage：统一的画面语法

所有视频共享同一张画面蓝图。观众从第一个视频里学到的空间语法，在第二个视频里立刻可用——不用重新扫描布局。

```
┌─────────────────────────────────────────┐
│ Header   题号 · 标题 · 最优复杂度        │ 8%
├─────────────────────────────────────────┤
│ InvariantBand   "窗口内无重复"           │ 7%
├─────────────────────────────────────────┤
│                                          │
│                                          │
│ Primary   主要数据结构（运动主线）        │ 50%
│                                          │
│                                          │
├─────────────────────────────────────────┤
│ Auxiliary   辅助结构（哈希、栈、DP 表等） │ 22%
├─────────────────────────────────────────┤
│ Narration   微注解（不超过 12 个汉字）    │ 8%
└─────────────────────────────────────────┘
```

五条硬约束：

- **Header 永远在顶部**，包含题号、题目名、最优时空复杂度。它的字体、间距、颜色在所有视频里完全一致。
- **InvariantBand 永远紧跟 Header**，窄条带高度 48px 左右，用一条持久可见的短句和一个微图形同时表达不变量。永不消失，永不闪烁。
- **Primary 区是主角**，占屏幕纵向 50% 左右，水平居中。当前正在处理的对象在这一区内位居 C 位，其他对象向两侧退场。
- **Auxiliary 区是辅助**，占纵向 22%，如果题目没有辅助结构这一区允许为空白（而不是用别的东西填满）。保留空白本身就是信息——"这题不需要额外结构"。
- **Narration 区是微注解**，高度约 80px，字符数不超过 12 个汉字或 24 个英文字符。它不解释画面，它**命名**此刻的动作——`"L 右跳跨过重复"`、`"栈弹出：14 战胜 13"`、`"dp[5] 由 3 和 2 汇合"`。

禁止的做法：把说明性长文字放在屏幕某个角落；把大段代码片段贴在画面里；用标题层级混用（"今天我们来学一道题"等导语）。

## 语义色板（tokens）

所有颜色必须引用 tokens，不允许在组件内硬编码十六进制。跨视频一致是这份约束的唯一目的。

**画布**

- `bg.canvas` `#0f1117` 深夜蓝黑，所有视频同一底色
- `bg.surface` `#1b1f2a` 结构容器的内表面
- `bg.subtle` `#242a38` 次级面板

**角色**（元素的状态）

- `role.idle` `#394150` 默认、未参与
- `role.active` `#60a5fa` 当前主角（蓝）
- `role.resolved` `#34d399` 已确定的答案部分（绿）
- `role.conflict` `#f87171` 冲突、无效（红）
- `role.ghost` `#4b5563` 已走过、已失活（灰）
- `role.pivot` `#fbbf24` 枢纽、mid、分界（黄）

**指针**（不要重定义，固定语义）

- `pointer.left` `#60a5fa` 蓝
- `pointer.right` `#f87171` 红
- `pointer.slow` `#34d399` 绿（slow/fast 指针场景）
- `pointer.fast` `#c084fc` 紫

**结构**

- `struct.stroke` `#475569` 默认描边
- `struct.focus` `#f8fafc` 焦点描边（最强）
- `struct.window` `#fbbf2433` 窗口内填充（半透明黄）

**文本**

- `text.primary` `#f8fafc` 标题、关键数值
- `text.secondary` `#cbd5e1` 次级描述、坐标
- `text.muted` `#64748b` 背景级文本

**不变量带**

- `invariant.bg` `#1e293b`
- `invariant.stroke` `#334155`
- `invariant.text` `#e2e8f0`

十二个角色色值，覆盖所有算法视频。拒绝把"某一题的某一种特殊状态"也加入 tokens——如果一种状态在多道题里出现，它属于通用角色；如果只在一道题里出现，它不配占据色板席位，复用最接近的通用角色即可。

## 运动：补间、节奏、残留

### 补间（motion.ts）

两相邻步骤之间**必须**有 0.3–0.5 秒的补间。瞬时切换只用于"这一步的语义就是瞬变"的场景（例如 `mid` 被重新计算——它本来就是离散的）。

位置类补间用 `easeOutCubic`（快起步、慢停止）——符合观察真实物体运动的预期。颜色类补间用线性即可。透明度补间用 `easeInOutQuad`，避免淡入淡出过于突兀。

提供的原语：

```ts
tween(from, to, progress, easing?)          // 基础补间
tweenIndex(fromIdx, toIdx, progress, cellW) // 返回 x 坐标
tweenColor(fromHex, toHex, progress)        // RGB 通道插值
interpolatePath(points, progress)           // 沿路径走
```

### 节奏（duration per step）

每一步有两个可能强度：

- `routine` 步——默认 48 帧（1.6 秒），用于常规推进
- `peak` 步——90 帧（3 秒），用于冲突出现、答案捕获、状态剧变

Step 定义里必须标注 `emphasis`。Stage 根据 emphasis 之和计算 `durationInFrames`，Root 的 Composition 注册时读取。不再用全局统一时长。

### 残留（residual）

一个元素从 `active` 迁出后，不能直接回到 `idle`，应当保留一段"刚走过"的视觉痕迹——通常是 `role.ghost` 色 + 保留该元素的描边。这条痕迹在下一个 peak 步骤到来时才彻底消失。这让观众在**任何时刻**都能看出"走过哪里"。

## Primitives（原语组件）

所有 Primitives 位于 `src/design/primitives/`，每个组件的 API 必须**纯函数式**——接受 props，输出 JSX，无内部状态。props 必须 JSON-safe（禁止传入 Set/Map/方法）。

**Cell**：最小数据单元。接受 `value`、`index`、`state`（`idle | active | resolved | conflict | ghost | pivot`）、`focused`（boolean）、`size`。负责语义色 + 描边 + 索引下标渲染。

**Pointer**：指针。接受 `index`（float，允许非整数以便补间）、`label`（`L` / `R` / `i` / `mid`）、`role`（决定颜色）、`anchor`（`top` / `bottom`）。位置用 cellWidth × index 计算。

**WindowBracket**：窗口支架。接受 `left`、`right`（均 float）、`cellWidth`、`cellHeight`。渲染为一条向上开口的中括号包住区间。拉伸时自动补间。

**StackColumn**：栈。接受 `items`（数组）、`highlightTop`、`incomingItem`、`outgoingItem`。有底座描边，元素从下往上堆叠（CSS `flex-direction: column-reverse`）。入栈元素有淡入+上浮动画，出栈元素有淡出+上移消失。

**DequePanel**：双端队列。接受 `items`、`frontMark`、`backMark`、`highlight`。水平方向，front 在左、back 在右，有 `front→` 和 `←back` 标识。

**DPTable**：DP 表（1D 或 2D）。接受 `cells`（二维数组，每个元素含 `value` 和 `state`）、`focusCell`、`dependencies`（指向该焦点的源格子坐标列表）。依赖关系用细箭头连线表达。

**Grid**：矩阵网格。接受 `cells`（二维语义状态）、`cursor`（`{row, col}`）、`flooding`（正在 DFS/BFS 波及的坐标集）。

**CallOut**：微注解气泡。接受 `anchorX`、`anchorY`、`text`（不超过 12 汉字）、`direction`（`up` / `down`）。用于 peak 步骤高光注释，routine 步骤不用。

**InvariantBand**：持久不变量带。接受 `text`、`glyph`（可选的小图形组件）。永不闪烁、永不消失。

**Ghost**：残留层。接受 `positions`（历史位置数组）、`decay`（衰减系数）。在主角层下方渲染淡色残影。

每个 Primitive 内部只允许引用 `tokens.ts` 和 `motion.ts`，不允许重新定义颜色、不允许自己决定时长。

## Step 数据契约

旧版的 Step 数据是手工敲进 composition 文件的。新版禁止这样做——Step 必须由**真实运行算法**得到。

```
src/
  algorithms/
    longestSubstring.ts    # 导出 run(input): Step[]
    dailyTemperatures.ts
    ...
  compositions/
    LongestSubstringV2.tsx # import { run } from '../algorithms/longestSubstring'
                           # const steps = run(INPUT)
```

这样做的三个理由：步骤正确性由代码保证、输入改了视频自动更新、写的人同时在"教算法"和"跑算法"，两件事被强制一致。

每道算法的 `run` 函数必须导出一个结构化的 Step 序列。Step 形状因算法而异，但都必须含两个通用字段：

```ts
type BaseStep = {
  emphasis: 'routine' | 'peak'  // 节奏标签
  narration: string              // 不超过 12 汉字的微注解
  // ... 算法特定字段
}
```

算法特定字段应当**就是**可视化所需的所有状态——指针位置、容器内容、被高亮的索引——不要包含任何"为了渲染方便"的冗余字段，也不要省略任何一个渲染所需的字段。一个原则：如果把 Step 数组存下来让另一个人照着重画，他应当能**完全重建**视频。

## 书写新 Composition 的流程

1. 在 `src/algorithms/<name>.ts` 写 `run(input)`，产生 Step 数组。先只构造 2–3 个代表性步骤（首帧、一个 peak、末帧）手动验证——**绝不**先跑全算法再画。
2. 决定这道题的 **不变量一句话** 和 **运动主线**。写在 `InvariantBand` 里。
3. 在 `src/compositions/<Name>V2.tsx` 用 `<Stage>` 包裹，填充 Primary/Auxiliary 区。
4. 跑起来看 2–3 个代表步骤是否视觉自明。**关掉 narration 让同事看**——他能说出算法在做什么吗？能，继续；不能，回去改画面不是改文字。
5. 完整跑通后在 `Root.tsx` 注册新 Composition ID（带 `V2` 后缀），`durationInFrames` 由 step emphases 之和决定。
6. 对照旧版视频观察差异，删旧 Composition 与组件。

## 自检清单

每完成一个新视频，用这套清单逐项打勾。没通过的视频不允许合入。

**结构类**

- [ ] 用 `<Stage>` 而不是裸 `AbsoluteFill`
- [ ] Header 格式与其他视频一致
- [ ] InvariantBand 写出了一句 6 字以内的不变量，并且在整段视频里不消失
- [ ] Primary 区的主要对象在画面中央，辅助对象在 Auxiliary 区
- [ ] Narration 每步不超过 12 汉字

**视觉编码类**

- [ ] 颜色全部引用 `tokens`，没有硬编码 hex
- [ ] 同一种视觉变量没有同时编码两种语义
- [ ] 已处理但已失活的元素保留了 `ghost` 态
- [ ] 焦点对象有 `struct.focus` 描边
- [ ] 同一帧上同时可辨的独立语义单元不超过 5 个

**运动类**

- [ ] 相邻步骤之间有补间，非瞬切
- [ ] 位置补间用 `easeOutCubic`
- [ ] peak 步骤和 routine 步骤时长不同
- [ ] 指针移动是滑过去的，不是跳过去的

**自明性测试**

- [ ] 关掉 narration，同事看两帧能说出算法在做什么
- [ ] 在任何时刻暂停，能一眼看出"走到哪、还剩多少、当前在做什么"
- [ ] 不变量在整段视频里始终为真，且始终可见

**代码质量**

- [ ] Step 由 `src/algorithms/<name>.ts` 的 `run` 函数生成
- [ ] 没有在 composition 文件里硬编码 Step 数组
- [ ] Props 全部 JSON-safe

## 迁移路线图
