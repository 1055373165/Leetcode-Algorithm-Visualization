# 93. 复原 IP 地址：固定段数的序列分割回溯

## 面试解题思路

一个纯数字字符串最长 20 个字符，你要在里面恰好插入 3 个点，把它切成 4 段，每段是一个 0 到 255 之间的整数，而且不能有前导零——"01" 不行，"0" 可以。乍一看选择空间不大：3 个点，每个点最多 3 种位置选择，总共也就 $3^3 = 27$ 种切法。但实际上这道题的价值不在于搜索空间的大小，而在于它是"序列分割回溯"这个模板的最佳练习场——约束条件足够丰富（段数固定、数值范围、前导零禁令），剪枝条件足够明确（剩余字符太多或太少都可以提前终止），而搜索规模又小到你可以在脑子里跑完整棵树。

面试时这样说：这道题是固定段数的字符串分割问题，我用回溯在每个位置尝试切出 1 到 3 个字符作为一段 IP 数字，只有满足 0-255 范围且无前导零时才递归处理剩余部分。当凑齐 4 段且字符串恰好用完时收集答案。额外加入"剩余字符数不够或太多"的剪枝。时间复杂度 $O(3^4) = O(81)$ 即常数级，空间复杂度 O(1)（不计输出）。

## 审题

题目给定一个仅包含数字的字符串 s，返回所有可能的有效 IP 地址。有效 IP 地址由 4 个整数组成，每个整数在 0 到 255 之间，用 '.' 分隔，且不能有前导零（"0" 本身合法，"00"、"01"、"001" 不合法）。约束 $1 \le s.length \le 20$，s 仅包含数字。

数据范围 n ≤ 20 看上去很小，但更关键的约束是"恰好分成 4 段"。每段最少 1 个字符、最多 3 个字符，所以合法输入的长度范围是 4 到 12。如果 s.length < 4 或 > 12，直接返回空。这道题的搜索空间是固定的——最多做 3 次切割选择，每次最多 3 种选择，总分支数不超过 $3^3 = 27$。所以这道题的复杂度是常数级的，优化的重点不在降低时间复杂度，而在于正确地处理所有约束条件和边界情况。

题目要求返回"所有"合法 IP，指向搜索穷举。约束条件（段数、数值范围、前导零）足够丰富，指向带剪枝的回溯。这道题和 131. 分割回文串共享同一个回溯框架——"从 start 位置出发，尝试合法前缀，递归处理剩余"——只是"合法"的定义不同。

边界陷阱：字符串长度小于 4 或大于 12 时无解；单个 "0" 合法但 "00" 不合法（前导零的判断必须是"长度大于 1 且首字符为 '0'"，而非"首字符为 '0'"）；数值 256 不合法但 255 合法，需要做字符串到数值的转换并比较；全零 "0000" 只有一个答案 "0.0.0.0"。

## 思维演化

暴力思路很直白：用三重循环枚举三个切割点的位置，把字符串分成四段，逐一检查每段是否是合法 IP 数字。三重循环每层最多 n 次，总共 $O(n^3)$，再加上每段的合法性检查 O(1)（转整数比较），暴力解的复杂度是 $O(n^3)$。对于 n ≤ 20 来说，这完全跑得动。

但暴力法的问题不在速度，而在结构。三重循环的写法把"分成 4 段"这个需求硬编码了——如果题目改成分成 k 段，你就需要 k-1 重循环。更重要的是，三重循环无法优雅地集成剪枝：如果第一段就不合法，你理论上应该跳过后面两层循环的所有迭代，但在嵌套循环中做这件事需要 break 加标签或者提前 continue，代码会变得难以维护。

**如果你没见过回溯模板，你会卡在哪里？** 你会试图用三重循环 + 条件过滤来写，代码冗长且容易漏掉边界。回溯的价值在于把"固定段数的分割"抽象成递归，每层处理一段，约束检查和剪枝自然嵌入递归结构中。

关键思维转折：把"插入 3 个点"转化为"依次切出 4 段"。每一段从当前位置 start 开始，长度 1 到 3，只有满足合法性时才递归处理剩余字符串。递归的终止条件是"已经切出 4 段且 start 恰好到达字符串末尾"。这个框架天然支持剪枝：如果已切出的段数加上剩余字符能凑出的最大段数不够 4，提前返回；如果剩余字符即使每段只取 1 个字符都超过剩余段数，也提前返回。

**正确性论证**：每层递归尝试长度 1、2、3 三种切法，覆盖了所有可能的段长。合法性检查确保每段都在 0-255 且无前导零。终止条件要求恰好 4 段且字符串用完，保证不会漏解也不会多解。不同递归路径的切割位置序列必然不同，所以不会产生重复方案。

## 代码实现

```go
func restoreIpAddresses(s string) []string {
	var result []string
	var segments [4]string

	var backtrack func(start, seg int)
	backtrack = func(start, seg int) {
		// 已凑齐 4 段
		if seg == 4 {
			if start == len(s) {
				result = append(result, segments[0]+"."+segments[1]+"."+segments[2]+"."+segments[3])
			}
			return
		}

		// 【核心】剪枝：剩余字符数必须在合理范围内
		remaining := len(s) - start
		minNeed := 1 * (4 - seg) // 每段至少 1 个字符
		maxNeed := 3 * (4 - seg) // 每段至多 3 个字符
		if remaining < minNeed || remaining > maxNeed {
			return
		}

		for length := 1; length <= 3 && start+length <= len(s); length++ {
			sub := s[start : start+length]
			// 前导零检查：长度 > 1 时首字符不能是 '0'
			if length > 1 && sub[0] == '0' {
				break // 更长的也必然有前导零，直接终止
			}
			// 数值范围检查
			val := 0
			for _, c := range sub {
				val = val*10 + int(c-'0')
			}
			if val > 255 {
				break // 更长的数值只会更大，直接终止
			}
			segments[seg] = sub
			backtrack(start+length, seg+1)
		}
	}

	backtrack(0, 0)
	return result
}
```

## 复杂度分析

**时间复杂度：$O(3^4 \cdot n) = O(n)$，实际为常数级。**

搜索树最多 4 层，每层最多 3 个分支，所以节点总数不超过 $3^4 = 81$。但由于剪枝的存在（剩余字符数范围检查、数值超 255 后 break），实际访问的节点数远小于 81。每个节点内的操作（子串提取、数值计算）都是 O(1) 到 O(3) 的常数。拼接最终 IP 字符串是 O(n)。合法 IP 数量不超过几十个。所以总时间是 O(n) 级别，但 n 本身被限制在 [4, 12]，所以实质上是常数。

**空间复杂度：O(1)（不计输出）。**

segments 数组固定 4 个元素。递归栈深度固定 4 层。没有额外的辅助数据结构。输出空间取决于合法 IP 的数量，最坏情况下也是常数级（对于 n ≤ 12 的输入，合法 IP 数量有上界）。

## 思路验证

用 s = "0000" 推演，这是一个容易出错的边界用例。

backtrack(0, 0)：尝试切 "0"（length=1），合法。进入 backtrack(1, 1)。尝试切 "00"（length=2），首字符为 '0' 且 length>1，**break**——这里是前导零剪枝的关键：不是 continue 而是 break，因为 "000" 也必然有前导零，没必要继续尝试更长的切法。

backtrack(1, 1)：切 "0"，合法。backtrack(2, 2)：切 "0"，合法。backtrack(3, 3)：切 "0"，合法，start=4==len(s)，seg=4，收集 "0.0.0.0"。

回溯到 backtrack(2, 2)，尝试切 "00"，前导零 break。回溯到 backtrack(1, 1)，尝试切 "00"，前导零 break。回溯到 backtrack(0, 0)，尝试切 "00"，前导零 break。搜索结束。

结果 ["0.0.0.0"]，正确。这个用例验证了两件事：单独的 "0" 被正确接受，而 "00"、"000" 被前导零规则正确拒绝。

再用 s = "101023" 推演关键路径。这个用例的价值在于它包含嵌入的 "0"，考验前导零处理和段数拼接。

backtrack(0,0) 切 "1" → backtrack(1,1) 切 "0" → backtrack(2,2) 切 "1" → backtrack(3,3) 切 "023"，首字符 '0' 且 length=3，break。切 "02"，首字符 '0'，break。切 "0"，val=0 合法，backtrack(4,4)：remaining=2，need 0，但 start≠len(s)，不收集。

回溯，backtrack(2,2) 切 "10" → backtrack(4,3) 切 "2" → backtrack(5,4)：start=5≠6，不收集。切 "23" → backtrack(6,4)：start=6==len(s)，收集 "1.0.10.23"。

继续搜索可以找到其他解如 "1.0.102.3"、"10.1.0.23"、"10.10.2.3"、"101.0.2.3" 等。每条路径都是通过不同的切割点组合到达的，不会重复。

## 易错点与边界

**前导零用 break 而非 continue**：当 sub[0]=='0' 且 length>1 时，不仅当前 length 不合法，更长的 length 也必然有前导零。用 break 终止循环比 continue 跳过当前迭代更高效也更正确。同理，val>255 时更长的子串数值只会更大，也应该 break。

**seg==4 时必须同时检查 start==len(s)**：如果只检查 seg==4 而不检查 start，会收集到没有用完所有字符的"短" IP。如果只检查 start==len(s) 而不检查 seg==4，会收集到段数不够的"长"段 IP。两个条件缺一不可。

**拼接字符串的方式**：用固定大小数组 `[4]string` 存四段，比用 slice 的 path+回溯更简洁。因为段数固定为 4，不需要动态 append/pop，直接 `segments[seg] = sub` 覆盖即可，天然支持回溯（下次写入会覆盖上次的值）。

**长度预检查**：s 长度小于 4 或大于 12 时无解，可以在入口处直接返回。虽然回溯中的剩余字符数剪枝也能处理这些 case，但前置检查更清晰。

## 核心洞察

IP 地址的四段结构把搜索空间压缩到了常数级——无论输入多长，搜索树的深度固定为 4、宽度固定为 3。这道题的真正考点不是算法效率，而是约束处理的完备性：前导零判定、数值上界检查、段数与剩余字符的匹配缺一不可，且三者的交互（前导零 break 而非 continue、val>255 也 break）是大多数实现 bug 的来源。
