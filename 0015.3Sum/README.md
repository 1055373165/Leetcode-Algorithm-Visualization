# 15. 三数之和：排序是秩序的起源

## 1. 审题（Problem）

### 1.1 约束解码
题目要求在数组 `nums` 中找到所有满足 `nums[i] + nums[j] + nums[k] == 0` 的 **不重复** 三元组。
数据范围：$0 \le nums.length \le 3000$。
这意味着 $O(n^2)$ 解法（$9 \times 10^6$）是安全的，但 $O(n^3)$（$2.7 \times 10^{10}$）绝对会超时。

### 1.2 边界陷阱
这是 LeetCode 中通过率极低的一道题（通常在 20%-30%），坑点全在 **“不重复”** 上。
*   **输入重复**：数组里可能有 `[-1, -1, -1, 2]`。
*   **结果去重**：输出不能包含 `[-1, -1, 2]` 和 `[-1, -1, 2]`（如果它们来自不同索引）。
*   **指针跳过**：在移动指针时，如果遇到相同的数字，必须连续跳过，否则会产生重复解。

### 1.3 问题归类
乍一看是 **哈希表** 问题（两数之和的升级版），但由于要求“不重复结果”，哈希表处理去重会非常麻烦（需要对结果排序再 Set 去重）。
更优的选择是 **排序 + 双指针**。排序是解决“去重”和“逼近目标”的基石。

## 2. 思维演化（Reasoning）

### 2.1 暴力解法：三层循环
略。$O(n^3)$，直接 Pass。

### 2.2 降维打击：化三为二
如果我们固定一个数 `nums[i]`，问题就变成了：在剩下的数中，找到两个数 `sum = 0 - nums[i]`。
这不就是 **“两数之和”** 吗？
现在我们有了 $O(n^2)$ 的框架：一层循环遍历 `i`，内部用 $O(n)$ 解决两数之和。

### 2.3 为什么必须排序？
两个原因：
1.  **便于去重**：相同的元素挨在一起，`if nums[i] == nums[i-1] continue` 就能轻松去重。无需 Set。
2.  **双指针逼近**：只有数组有序，我们才能通过“和大了往左移，和小了往右移”的策略来查找。如果是乱序，指针移动毫无章法。

## 3. 直觉培养（Intuition）

### 3.1 宏观视角
想象你在玩天平。左边放了一个重球（固定 `nums[i]`）。你需要在右边的球堆里找两个球，让天平平衡。
因为球堆是有序的：
*   你选了最小的（`L`）和最大的（`R`）。
*   如果太重了，说明最大的那个球太重，`R` 必须换个轻点的（`R--`）。
*   如果太轻了，说明最小的那个球太轻，`L` 必须换个重点的（`L++`）。

## 4. 代码实现（Solution）

```go
import "sort"

func threeSum(nums []int) [][]int {
	// 1. 排序：这是去重和双指针的前提
	sort.Ints(nums)
	var res [][]int
	n := len(nums)

	for i := 0; i < n-2; i++ {
		// 剪枝：如果当前数大于 0，后面都是正数，和不可能为 0
		if nums[i] > 0 {
			break
		}
		
		// 去重 A：跳过重复的 i
		if i > 0 && nums[i] == nums[i-1] {
			continue
		}

		// 双指针寻找
		left, right := i+1, n-1
		target := -nums[i]

		for left < right {
			sum := nums[left] + nums[right]
			if sum == target {
				res = append(res, []int{nums[i], nums[left], nums[right]})
				
				// 去重 B & C：跳过重复的 left 和 right
				// 注意：必须先移动一次，再判断是否重复
				left++
				right--
				for left < right && nums[left] == nums[left-1] {
					left++
				}
				for left < right && nums[right] == nums[right+1] {
					right--
				}
			} else if sum < target {
				left++
			} else {
				right--
			}
		}
	}
	return res
}
```

### 4.2 复杂度证明
*   **时间复杂度**: $O(n^2)$。排序 $O(n \log n)$ + 外层循环 $n$ 次 $\times$ 内层双指针 $O(n)$。
*   **空间复杂度**: $O(\log n)$。主要是排序的栈空间。如果不算返回结果的空间。

### 4.3 易错点清单
1.  **去重逻辑**：`i` 的去重是 `nums[i] == nums[i-1]`（和前一个比），而不是 `nums[i+1]`。
2.  **指针移动**：找到答案后，`L` 和 `R` 都要动，并且要循环跳过重复值。
3.  **剪枝**：`nums[i] > 0` 直接 break 能够显著提升运行效率（从 30ms -> 20ms）。

### 5.2 模式识别
当看到 **“数字之和”** + **“数组”** + **“去重”** 这几个关键词组合时，**排序 + 双指针** 往往是比哈希表更好的选择。哈希表擅长查找“存在性”，但在处理“去重”和“范围逼近”时显得力不从心。
