# 56. Merge Intervals：时间线的秩序者

## 1. 审题（Problem）

### 1.1 约束解码
题目的核心输入是一个区间数组 `intervals`，其中每个区间由 `[start, end]` 组成。我们的目标是合并所有重叠的区间，输出一个不重叠的区间列表。数据规模方面，`intervals` 的长度通常在 $10^4$ 级别。这就暗示了我们需要寻找一个时间复杂度在 $O(N \log N)$ 或者 $O(N)$ 的解法。如果是 $O(N^2)$ 的暴力解法，面对万级的数据量极有可能会超时。

### 1.2 边界陷阱
在处理区间问题时，有几个常见的陷阱需要特别注意：首先是区间的输入顺序，题目并没有保证输入是有序的，乱序的输入（如 `[2,6]` 在 `[1,3]` 之前）会极大地增加处理难度；其次是包含关系，例如 `[1,4]` 完全包含了 `[2,3]`，这种情况下合并后的结果应该直接是 `[1,4]`；最后是相切的情况，如 `[1,2]` 和 `[2,3]`，根据题目定义这也算作重叠，需要合并为 `[1,3]`。

### 1.3 问题归类
这道题属于典型的**区间合并（Interval Merging）**问题。由于需要处理大量的区间关系，且区间之间存在可比较的顺序（开始时间和结束时间），这类问题通常可以通过**排序（Sorting）**将其转化为线性扫描的问题。因此，我们可以将其归类为**排序 + 贪心（Sorting + Greedy）**的组合模式。

## 2. 思维演化（Reasoning）

### 2.1 暴力解法
最直观的想法是，我们需要比较每两个区间，看它们是否重叠。如果重叠，就将它们合并，然后再去和剩下的区间比较。我们可以构建一个图，如果不相交就是不连通，如果相交就是连通的，最后求连通分量。或者简单地两两比较，直到没有可以合并的区间为止。

### 2.2 瓶颈分析
暴力解法的核心瓶颈在于**无序性**。当我们不知道区间在时间轴上的相对位置时，对于任意一个区间，我们都不得不去扫描所有其他区间来确认是否有重叠。这种重复的、盲目的扫描导致了 $O(N^2)$ 甚至更高的时间复杂度。如果我们能让区间按某种顺序排列，是不是就不需要回过头去检查了呢？

### 2.3 优化演化链
观察区间在数轴上的分布，我们可以发现一个重要的性质：如果按照**左端点（Start Time）**从小到大排序，那么所有可能与当前区间重叠的区间，一定紧随其后。排序后，我们只需要关注相邻的区间关系。
1.  **提出假设**：先将所有区间按左端点排序。
2.  **验证优化**：排序后，对于两个相邻区间 `prev` 和 `curr`，如果 `curr.start <= prev.end`，说明它们一定重叠（因为 `curr.start >= prev.start` 是排序保证的）。此时我们只需要更新 `prev.end = max(prev.end, curr.end)` 即可完成合并。
3.  **复杂度提升**：通过引入排序，我们将寻找重叠区间的过程从“全量搜索”变成了“线性扫描”。虽然排序本身需要 $O(N \log N)$，但之后的合并只需要 $O(N)$，整体复杂度被成功降低到了 $O(N \log N)$。

## 3. 直觉培养（Intuition）

### 3.1 为什么能想到这个方法？
“重叠”这个词在几何或时间轴上，往往意味着一种连续性。当我们面对杂乱无章的线条时，人的本能是先理顺它们——也就是**排序**。一旦线条按起点排好了队，我们只需要像贪吃蛇一样，从头吃到尾：如果下一条线跟当前这条有接触，就把它吞并（延长尾部）；如果没有接触，说明当前的“贪吃蛇”已经长到了极限，该由下一条线开始变成新的贪吃蛇了。

### 3.2 类比心智模型
想象你在管理一间只有一个房间的会议室预订系统。
*   桌子上堆满了各种会议的预定单（区间），有早上的，有下午的，乱七八糟。
*   你首先做的，肯定是把这些单子按**开始时间**排个序。
*   然后你拿起第一张单子（比如说 9:00-10:00），看第二张单子（9:30-11:00）。
*   你发现第二张单子的开始时间（9:30）早于第一张的结束时间（10:00），说明这两场会冲突了，或者说它们的时间段连在一起了。于是你把它们合并成一个大时间段（9:00-11:00）。
*   接着看第三张（13:00-14:00）。它的开始时间（13:00）比你目前合并后的结束时间（11:00）要晚，说明中间断开了。于是你把（9:00-11:00）这个大单子存档，开始处理新的（13:00-14:00）。

## 4. 代码实现（Solution）

### 4.1 核心代码（Go）

```go
package main

import (
	"sort"
)

// merge 合并重叠的区间
// 核心思想：排序后线性扫描，贪心策略从左向右合并
func merge(intervals [][]int) [][]int {
	// 【防御性编程】处理空输入或单元素，直接返回
	if len(intervals) <= 1 {
		return intervals
	}

	// 1. 预处理：按区间的左端点（Start Time）进行升序排序
	// 为什么？排序将二维的相交判断转化为一维的相邻比较，消除无序性
	sort.Slice(intervals, func(i, j int) bool {
		return intervals[i][0] < intervals[j][0]
	})

	// 2. 初始化结果集，先将第一个区间放入
	var merged [][]int
	merged = append(merged, intervals[0])

	// 3. 线性扫描后续区间
	for i := 1; i < len(intervals); i++ {
		// last 指向结果集中最后一个已合并的区间（引用语义需注意，这里可以直接修改切片元素）
		last := merged[len(merged)-1]
		curr := intervals[i]

		// 【核心决策】判断是否重叠
		// 因为已排序，所以 curr.start >= last.start 恒成立
		// 只需要检查 curr.start 是否在 last 的覆盖范围内（即 <= last.end）
		if curr[0] <= last[1] {
			// case 1: 重叠 -> 合并
			// 更新 last 的右边界，取两者右边界的最大值，以此吞噬当前区间
			// 注意：这里需要直接修改 merged 切片中的内容
			if curr[1] > last[1] {
				merged[len(merged)-1][1] = curr[1]
			}
		} else {
			// case 2: 不重叠 -> 断开
			// 说明产生了一个新的独立区间，直接加入结果集
			merged = append(merged, curr)
		}
	}

	return merged
}
```

### 4.2 复杂度分析

*   **时间复杂度**：$O(N \log N)$
    *   主要的开销在于 `sort.Slice`，其平均时间复杂度为 $O(N \log N)$。
    *   随后的每一次遍历和合并操作都是常数时间的，总共遍历一次数组，耗时 $O(N)$。
    *   总复杂度由排序决定，为 $O(N \log N)$。
*   **空间复杂度**：$O(\log N)$
    *   这里特指排序所需要的栈空间，通常为 $O(\log N)$。
    *   如果我们不计算存储结果的 `merged` 数组（这通常被视为输出空间），则只需要常数级的额外空间来存储变量。

### 4.3 易错点与边界处理
1.  **引用陷阱**：在此时 `last := merged[len(merged)-1]` 获取的是切片内元素的拷贝（如果是 struct 或数组），修改 `last` 可能不会影响 `merged`。但在 Go 中，如果是直接修改 `merged[i][1]` 是安全的。代码中直接操作 `merged` 下标是最稳妥的。
2.  **右边界更新**：合并时，右边界不是简单地取 `curr` 的右边界，而是取 `max(last.end, curr.end)`。因为有可能 `last` 完全包含了 `curr`（如 `[1, 10]` 和 `[2, 3]`）。
3.  **空数组**：输入为空时需要提前判断，避免下标越界。

### 5.2 模板沉淀

```go
// 区间合并通用模板
func mergeTemplate(intervals [][]int) [][]int {
    if len(intervals) == 0 { return nil }
    
    // 1. 排序：这是处理区间问题的万能起手式
    sort.Slice(intervals, func(i, j int) bool {
        return intervals[i][0] < intervals[j][0]
    })
    
    res := [][]int{intervals[0]}
    
    for i := 1; i < len(intervals); i++ {
        last := res[len(res)-1]
        curr := intervals[i]
        
        // 2. 检查重叠条件
        if curr[0] <= last[1] {
            // 3. 合并逻辑：通常是更新右边界
            if curr[1] > last[1] {
                res[len(res)-1][1] = curr[1]
            }
        } else {
            // 4. 不重叠逻辑：通常是加入新区间
            res = append(res, curr)
        }
    }
    return res
}
```

### 5.3 面试应答指南
*   **关于排序**：如果面试官问“能不能不排序？”，可以提及如果区间范围很小（比如在 $[0, 10000]$ 内），可以使用**桶排序**或**差分数组**的思想，将复杂度降到 $O(N + Range)$。但在通用情况下，排序是最优解。
*   **关于原地算法**：如果面试官要求 $O(1)$ 空间（不输出新数组），可以在原数组上操作，利用一个 `writeIndex` 指针记录当前合并写的进度，最后裁减切片。
