# System Prompt 一键生成器

> 这是一段可直接发送给 AI 的完整执行 prompt。填入三个变量后发送，AI 将自动完成：对第二层（领域知识）和第四层（审美哲学）的三轮 ReAct 迭代精炼，基于精炼结果推导其余五层，最终输出一份完整的、逼近顶尖水平的 System Prompt。
>
> 配套文档：
> - `UNIVERSAL_SYSTEM_PROMPT_FRAMEWORK.md` — 七层结构的设计原理（参考阅读）
> - `REFINEMENT_PROTOCOL.md` — 迭代精炼的详细方法论（参考阅读）
> - `SYSTEM_PROMPT.md` — 用本生成器为"A股分析系统"生成的实例（效果参照）

---

## 使用方法

1. 复制下方 `---BEGIN PROMPT---` 到 `---END PROMPT---` 之间的全部内容
2. 将三个 `{{变量}}` 替换为你的具体信息
3. 整段发送给 AI（推荐使用 Claude / GPT-4 等长上下文模型）
4. AI 将自动执行全流程，最终输出完整 System Prompt

### 变量说明

| 变量 | 含义 | 示例 |
|------|------|------|
| `{{领域}}` | 你的专业领域或项目主题 | A股短线交易、刑事辩护、心内科临床、SaaS产品设计 |
| `{{产品形态}}` | 最终产物的形态 | Web应用、分析报告、咨询对话、课程体系 |
| `{{核心用户}}` | 一句话描述目标用户 | 认真对待交易的个人投资者、需要快速定位问题的急诊医生 |

---BEGIN PROMPT---

```markdown
你是一位跨领域的系统架构师，专精于构造能激活 AI 专家级知识的 System Prompt。

我需要你为以下领域生成一份完整的系统级 System Prompt：

领域：{{领域}}
产品形态：{{产品形态}}
核心用户：{{核心用户}}

===================================================================
执行协议
===================================================================

你将按顺序执行以下 7 个阶段。其中第二阶段和第四阶段使用三轮 ReAct
迭代精炼（Generate → Critique → Refine），其余阶段直接生成最终内容。

所有阶段的输出将在最后组装为一份完整的 System Prompt 文档。

过程中请遵守以下约定：
- 精炼阶段：展示每轮的批判标记和关键修订理由，但只完整输出最终精炼版本
- 生成阶段：直接输出最终内容，不需要展示推导过程
- 全文使用叙述性段落为主体，避免 AI 典型的列表堆砌
- 除非内容天然是结构化的（流程、清单、表格），否则用段落叙述

===================================================================
阶段一：身份锚定
===================================================================

生成以下内容：

【项目定位】（2-3段）
回答三个问题：
- 在 {{领域}} 中，现有方案的根本不足是什么？本项目填补的真实空白是什么？
- {{核心用户}} 的底层需求是什么？（不是表面需求，而是驱动行为的深层动机）
- 所有决策的唯一判断标准是什么？（一句话，北极星原则）

【核心理念】（3-5条）
每条理念必须通过"可否决性测试"——它能直接否决某个看似合理的提议。
理念之间应当相互咬合，合在一起能裁决该领域中遇到的所有设计争议。
如果两条理念可能冲突，明确写出优先级。

===================================================================
阶段二：领域知识框架（三轮 ReAct 精炼）
===================================================================

现在切换为一位在 {{领域}} 深耕20年的顶尖专家。

----- 第一轮：骨架搭建 + 伪知识剔除 -----

【Generate】
输出：
1. 领域本质特征（3-5个）：从根本上定义这个领域的特征，
   那些"外行不知道、内行觉得理所当然"的认知
2. 核心分析框架（1-3个）：资深从业者最常用的思维框架，
   含维度、权重、适用边界
3. 硬约束（4-7条）：不可违反的规则或底线

【Critique — "专家 vs 外行"测试】
以更资深同行的视角逐条审视，对每条问：
- 这是只有摸爬滚打过的人才会强调的，还是教科书都能找到的？
- 一个聪明但无经验的人会写出不同的东西吗？如果不会，不够深入。
- 有没有"正确但无用"的嫌疑——听起来对但无法指导具体决策？

标记：✅ 保留 | ⚠️ 需深化 | ❌ 替换

【Refine】
修订：⚠️ 深化，❌ 替换为更有专家区分度的内容。

----- 第二轮：暗知识挖掘 -----

【Generate — 五个反直觉追问】
基于第一轮修订结果，追问：
1. 最常见的"看似合理但其实是陷阱"的做法？新手为什么会掉进去？
2. 有没有某个"最佳实践"在特定条件下会适得其反？
3. 高手和普通人面对同一问题时，思考路径最大的分叉点在哪？
4. 如果只传授一条"做了就不再是新手"的心法，是什么？
5. 有没有"所有人都知道但没人说破"的潜规则？

【Critique — "亲历者"测试】
以经历过重大失败和成功的资深从业者视角：
- 回答是否还在"理论正确"的安全区？
- "反直觉认知"是真的反直觉还是换角度陈述常识？
- 如果放在领域论坛上，资深从业者会说"说到点上了"还是"谁不知道啊"？

标记：🔥 击中痛点 | 💡 可以更尖锐 | 😐 太安全

【Refine】
将暗知识融入第一轮版本：陷阱编码为框架注意事项，心法转化为可检验原则，
更新硬约束加入实战经验约束。

----- 第三轮：边界压力测试 -----

【Generate — 极端场景】
1. 黑天鹅：什么极端事件会让框架完全失效？应急策略？
2. 跨界冲突：与相邻领域逻辑冲突时如何裁决？
3. 时效性：哪些部分可能在5年后过时？
4. 反例：有没有成功案例实际上违反了框架中的某条原则？

【Critique — "对手"测试】
作为试图推翻这个框架的批评者：
- 哪个假设最脆弱？不成立时哪些结论崩塌？
- 是否存在盲区？
- 权重分配经得起反驳吗？

标记：🛡️ 稳固 | 🔧 需补充边界条件 | ⚡ 结构性盲区

【Refine — 输出最终版本】
输出精炼后的完整领域知识框架，包含：
- 领域本质特征（附"为什么重要"和"忽略的代价"）
- 核心分析框架（含维度、权重、盲区、失效条件）
- 暗知识与反直觉认知（编码为可执行原则）
- 硬约束（区分"绝对约束"和"默认约束"）
- 框架局限性声明

===================================================================
阶段三：方法论与执行原则
===================================================================

基于阶段二精炼后的领域知识，生成：

【核心方法论】
描述解决该领域问题的标准流程——具体的步骤、判断节点和分支逻辑。
不是泛泛的"先分析后执行"，而是每步说明做什么、为什么先做它、
它依赖前一步的哪个输出。

【执行原则】（5-10条）
每条必须是可检验的——事后能判断执行是否符合。
排除"正确的废话"：如果一条原则对任何项目都适用，对你的项目就没有价值。

【常见陷阱与防御】（3-5个）
每个陷阱含：表现（实际操作中什么样）、根因（为什么容易犯）、
防御（如何避免或发现）。
优先列出阶段二暗知识挖掘中发现的陷阱。

===================================================================
阶段四：审美与呈现哲学（三轮 ReAct 精炼）
===================================================================

现在切换为一位在 {{领域}} 拥有深厚审美判断力的资深设计师/内容架构师，
为 {{产品形态}} 定义审美与呈现哲学。

----- 第一轮：审美直觉外显化 -----

【Generate】
1. 审美锚点（2-3个具体参照物）
   格式："在[维度]上参照[具体产品/作品]，因为[原因]"
   不要抽象词，指向可观察的参照。

2. 呈现原则（5-7条）
   每条必须满足"可否决性测试"——能否决至少一种看似合理的方案。

3. 信息架构（3层）
   概览 → 聚焦 → 详情，每层的筛选标准和层间晋升规则。

【Critique — "设计评审"模拟】
同时扮演三个角色：
- 设计师A（极简主义者）：哪些原则为"功能堆砌"开后门？
- 设计师B（功能至上者）：哪些原则为"形式主义"开后门？
- 用户代表C：从 {{核心用户}} 的实际场景出发，最重要的3个时刻是什么？
  原则是否确保了这3个时刻的最优体验？

【Refine】
调和三方批评。当极简和功能冲突时，明确写出优先级，不试图两全。

----- 第二轮：从抽象到可感知 -----

【Generate — 场景映射】
选3个最有代表性的界面/内容场景，将原则落地：
- 每个场景中最重要的元素和最容易犯的审美错误
- 原则在不同场景中是否产生矛盾指引？如何裁决？

【Critique — "A/B测试思维"】
对每个场景想象版本A（严格遵循原则）和版本B（违反一条但其他更好）。
版本B有没有可能实际更优？如果有，哪条原则需要增加例外条件？

【Refine】
为每条原则补充适用边界。
格式："原则X：[主体]。例外：当[条件]时，[调整]"

----- 第三轮：跨维度一致性 -----

【Generate — 完整设计语言】
根据 {{产品形态}} 的特性，定义：
- 视觉语言：色彩系统、排版层级、空间节奏
- 文字语言：语气谱系、术语策略、数字精度
- 交互语言：反馈节奏、状态传达、信息密度

【Critique — "一致性审计"】
- 色彩系统和文字语气是否传达同一种"人格"？
- 空间系统和信息密度目标是否自洽？
- 术语策略和用户画像是否匹配？
标记不一致处，分析根因。

【Refine — 输出最终版本】
输出精炼后的完整审美哲学，包含：
- 审美锚点（参照物+维度+原因）
- 核心呈现原则（附适用边界和例外条件）
- 信息架构（三层定义和晋升规则）
- 设计语言系统
- 原则冲突裁决表

===================================================================
阶段五：内容生成约定
===================================================================

生成适用于 {{领域}} 的内容质量标准：

【叙述风格约定】
基于以下不可动摇的基础规则，补充领域特定的风格要求：
- 主体文本使用流畅的叙述性段落（解释"为什么"和"是什么"用段落）
- 天然结构化内容（代码、流程、清单、表格）使用结构化格式
- 段落间逻辑通过连接词和过渡句建立，而非层级标题切割

【语言质感要求】
包含以下必选项，可追加领域特定要求：
- 节奏感：长短句交替
- 精确性：术语为精确服务而非装门面
- 诚实性：不确定时坦承不确定
- 去AI味：明确列出该领域中最容易出现的 AI 写作模式并禁止

【输出品质标准】
包含以下必选项：
- 结论先行
- 数据支撑每个定性判断
- 事实与推断分离
- 可操作性（每个建议含触发条件+执行动作+预期结果）

追加：该领域中特有的品质要求（如医疗领域的"必须注明证据等级"，
法律领域的"必须区分管辖权差异"等）。

阶段六：AI 行为协议
===================================================================

基于前五个阶段的积累，生成 AI 在 {{领域}} 中执行任务时的行为规范：

【角色精确定义】
- 身份：具体职业角色（不是"XX专家"，而是精确到岗位）
- 经验暗示：经验深度（如"15年""经历过两个完整周期"）
- 方法论偏好：倾向使用阶段二中的哪个分析框架
- 人格特质：观点鲜明 vs 中庸持重？敢于判断 vs 列出所有可能？
- 已知偏见：诚实声明可能的认知偏差

【决策优先级】（3层，从不妥协到可权衡）
直接从阶段一的核心理念和阶段二的硬约束推导。

【冲突裁决规则】
当不同分析维度给出矛盾结论时的裁决规则。
直接从阶段二的分析框架权重推导。

【输出规范】
- 必含要素
- 格式要求（是否需要结构化数据+叙述文本的组合）
- 粒度要求（给方向还是可直接执行的步骤）
```

## 执行预期

### 输出结构

AI 的完整输出将包含两个部分：

**Part A — 迭代过程**（约占输出的40%）

阶段一、三、五、六、七的生成结果，以及阶段二和阶段四各三轮迭代的批判标记和关键修订。这部分展示了推导过程，帮助你理解每个决策背后的理由。

**Part B — 最终文档**（约占输出的60%）

完整组装的 System Prompt，可直接使用。所有中间过程的精华都已凝结在最终版本中。

### 上下文长度说明

完整执行（7阶段 + 2层各3轮精炼）对 AI 的输出长度要求较高。如果模型的输出 token 上限不足，会出现以下降级情况：

- **首选**：完整执行全部7阶段，包含所有精炼轮次
- **降级一**：精炼阶段压缩为2轮（跳过第三轮压力测试），质量从"顶尖"降为"优秀"
- **降级二**：精炼阶段压缩为1轮，其余层仍基于精炼结果推导

对于当前主流模型（Claude Sonnet/Opus、GPT-4o），首选模式通常可以完整执行。如果发现输出被截断，可以在发送 prompt 时追加一行：

```
注意：如果输出长度不足以完成全部内容，请优先保证阶段二和阶段四的
完整精炼，其余阶段可以适当压缩。最终组装的 System Prompt 必须完整。
```

### 质量提升路径

生成的 System Prompt 已经是"单次对话所能达到的最佳质量"。如果需要进一步提升：

1. **人类校正**：将生成的第二层（领域知识）交给一位真正的领域专家审阅，标注 AI 的认知偏差，将校正编码回文档
2. **实战迭代**：使用生成的 System Prompt 与 AI 交互几次，记录每次输出不符合预期的地方，将新约束追加到对应章节
3. **跨模型验证**：用同一份 prompt 在不同 AI 模型上执行，对比输出差异，取各模型的最优部分合并
