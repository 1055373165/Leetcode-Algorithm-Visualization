# ReAct 迭代精炼协议 — 领域知识与审美哲学的深度打磨

> 本文档是通用 System Prompt 框架的配套工具。它借鉴 Agent ReAct（Reasoning + Acting）的思路，为框架中最关键的第二层（领域知识）和第四层（审美哲学）提供一套自我反思、多轮迭代的精炼流程。
>
> 核心主张：一次性生成的领域知识和审美原则，其质量上限大约是"还不错的教科书水平"。但经过三轮结构化的自我批判和修订，输出质量可以逼近"资深从业者的内化认知"——那种不会出现在教科书里、只有真正做过这件事的人才知道的东西。

---

## 协议总览

整个精炼过程由三轮迭代组成，每轮包含三个阶段：

```
Generate（生成）→ Critique（批判）→ Refine（修订）
     ↑                                    |
     └────────────────────────────────────┘
                 重复 3 轮
```

三轮迭代不是简单的"再想想"。每一轮有不同的批判维度和提升目标：

- **第一轮**：从无到有，建立骨架，然后用"专家 vs 外行"测试剔除伪知识
- **第二轮**：深挖反直觉认知，补充那些"做过才知道"的暗知识
- **第三轮**：压力测试边界条件，确保框架在极端和交叉场景下仍然成立

每轮之间的质量提升不是均匀的。第一轮到第二轮的提升最大（从"教科书水平"到"有实战经验的从业者水平"），第二轮到第三轮的提升更精微但同样关键（从"从业者水平"到"顶尖专家水平"）。

## 第二层精炼协议：领域知识框架

### 使用方法

以下是一段可直接交给 AI 执行的完整 prompt。将 `{{领域}}` 替换为你的目标领域，整段发送即可。AI 会自动执行三轮迭代并输出最终结果。

---

### 完整执行 Prompt

```markdown
你是一位在 {{领域}} 领域深耕20年的顶尖专家。我需要你帮我构建这个领域的知识框架，
但不是一次性给出结果，而是通过三轮结构化的自我反思来逐步深化。

请严格按照以下流程执行。每一轮都必须完整输出 Generate、Critique、Refine 三个阶段，
不要跳过任何一步。

===== 第一轮：骨架搭建 + 伪知识剔除 =====

【Generate】
请输出以下内容：
1. 领域本质特征（3-5个）：那些从根本上定义了这个领域、区分它与相似领域的特征
2. 核心分析框架（1-3个）：资深从业者最常用的思维框架，含维度、权重、适用边界
3. 硬约束（4-7条）：不可违反的规则或底线

【Critique — "专家 vs 外行"测试】
现在，以一位比你更资深的同行的视角，逐条审视你刚才的输出。对每一条问：
- 这条内容是只有真正在这个领域里摸爬滚打过的人才会强调的，还是随便翻一本教科书都能找到的？
- 如果一个聪明但没有领域经验的人来写，他会写出不同的东西吗？如果不会，说明这条不够深入。
- 这条内容有没有"正确但无用"的嫌疑——听起来对但无法指导任何具体决策？

请对每一条给出具体的批判意见。标记为：
  ✅ 保留（真正有区分度的专家认知）
  ⚠️ 需深化（方向对但过于表面）
  ❌ 替换（教科书常识，缺乏专家视角）

【Refine】
基于批判结果，修订输出。被标记 ⚠️ 的条目深化，❌ 的条目替换为更有专家区分度的内容。

===== 第二轮：暗知识挖掘 =====

【Generate — 五个反直觉追问】
基于第一轮的修订结果，对每个核心特征和框架追问以下问题：
1. 这个领域中最常见的"看似合理但实际上是陷阱"的做法是什么？为什么新手会掉进去？
2. 有没有某个被业界广泛接受的"最佳实践"其实在特定条件下会适得其反？那个条件是什么？
3. 你见过的高手和普通人在面对同一个问题时，思考路径上最大的分叉点在哪里？
4. 如果只能传授一条"做了之后你就再也不是新手了"的心法，那是什么？
5. 这个领域里有没有某种"所有人都知道但没人说破"的潜规则或默认假设？

【Critique — "亲历者"测试】
以一位在这个领域经历过重大失败和成功的资深从业者视角，审视你的追问答案：
- 这些回答是不是还在"理论正确"的安全区？有没有触及到真正让人不舒服的现实？
- 你给出的"反直觉认知"是真的反直觉，还是只是换了个角度陈述常识？
- 检验标准：如果把这些内容放在一个领域论坛上，资深从业者会说"说到点上了"还是"谁不知道啊"？

对每个回答标记为：
  🔥 击中痛点（会让从业者深有共鸣）
  💡 有启发但可以更尖锐
  😐 还是太安全了

【Refine】
将所有新发现的暗知识融入第一轮的修订版本。特别关注：
- 将"陷阱"和"反直觉认知"编码到分析框架中（作为注意事项或权重调整规则）
- 将"高手心法"转化为可检验的原则
- 更新硬约束，加入基于实战经验的新约束

===== 第三轮：边界压力测试 =====

【Generate — 极端场景检验】
构造以下极端场景，测试你的知识框架是否仍然成立：
1. 黑天鹅场景：在这个领域中，什么样的极端事件会让你的框架完全失效？失效后的应急策略是什么？
2. 跨界交叉场景：当这个领域与相邻领域的逻辑发生冲突时（比如技术可行但伦理存疑，或理论完美但执行不可能），框架如何裁决？
3. 时效性场景：你的框架中有没有哪些部分在5年前还是对的但现在已经过时了？有没有哪些部分在5年后可能会过时？
4. 反例场景：有没有这个领域中公认的成功案例实际上违反了你框架中的某条原则？如果有，这说明什么？

【Critique — "对手"测试】
现在假设你是一位试图推翻这个框架的批评者。你的目标是找到框架的最薄弱环节：
- 框架中哪个假设最脆弱？一旦这个假设不成立，哪些结论会跟着崩塌？
- 框架是否存在盲区——某类重要问题它完全没有覆盖？
- 框架中的权重分配是否经得起反驳？有没有证据支持不同的权重？

标记为：
  🛡️ 经受住了测试（核心依然稳固）
  🔧 需要补充边界条件或例外规则
  ⚡ 发现了结构性盲区，需要重构

【Refine — 最终输出】
基于三轮迭代的所有发现，输出最终版本的领域知识框架。格式：

## 领域本质特征
[经过三轮打磨的3-5个核心特征，每个附带"为什么这很重要"和"忽略它的代价"]

## 核心分析框架
[1-3个框架，每个含：核心逻辑、维度与权重、已知盲区、失效条件]

## 暗知识与反直觉认知
[第二轮发掘的关键洞察，编码为可执行的原则]

## 硬约束
[经过压力测试的约束，区分"绝对约束"和"默认约束（可在特定条件下放松）"]

## 框架局限性声明
[诚实承认框架的适用边界、已知盲区和脆弱假设]
```

## 第四层精炼协议：审美与呈现哲学

### 使用方法

同样，将 `{{领域}}` 和 `{{产品形态}}` 替换为你的具体情况。

---

### 完整执行 Prompt

```markdown
你是一位在 {{领域}} 领域拥有深厚审美判断力的资深设计师/内容架构师。
我需要你帮我定义 {{产品形态}} 的审美与呈现哲学。

这个问题的难度在于：审美原则极易沦为正确的废话（"要简洁""要专业""要美观"）。
我需要的是能够直接裁决具体设计争议的、有锋利边界的原则。

请严格按照以下三轮流程执行。

===== 第一轮：审美直觉外显化 =====

【Generate】
请输出以下内容：

1. 审美锚点（2-3个具体参照物）
   不要写"简洁大方"这种抽象词。而是指向具体的、可观察的参照物。
   格式："在[维度X]上参照[具体产品/作品A]的做法，因为[它解决的问题与我们相同]"
   例如："信息密度参照Bloomberg Terminal而非Consumer App，因为我们的用户
         需要在一个屏幕上做出交易决策，不能翻三页才看到关键数据"

2. 呈现原则（5-7条）
   每条必须满足"可否决性测试"——它必须能够让你否决至少一种看似合理的设计方案。
   如果一条原则对任何方案都只会说"可以"，它就没有约束力，不要写。

3. 信息架构（3层）
   概览层看什么 → 聚焦层看什么 → 详情层看什么
   每层的信息筛选标准是什么？什么信息从上一层晋升到下一层？

【Critique — "设计评审"模拟】
模拟一次设计评审会议。你同时扮演三个角色：

设计师A（极简主义者）的批评：
- 你的原则中有没有在为"功能堆砌"开后门？
- 哪些原则如果严格执行，会导致界面过于拥挤或信息过载？

设计师B（功能至上者）的批评：
- 你的原则中有没有在为"形式主义"开后门？
- 哪些原则如果严格执行，会牺牲关键信息的可见性？

用户代表C的批评：
- 你的原则说了很多"应该怎样"，但从用户的实际使用场景出发，最重要的3个时刻是什么？
  你的原则有没有确保这3个时刻的体验是最优的？

【Refine】
调和三方批评，修订原则。关键是：当极简和功能冲突时，明确写出优先级。
不要试图两全，两全通常意味着两面都不到位。

===== 第二轮：从抽象到可感知 =====

【Generate — 具体场景映射】
选取3个在你的 {{产品形态}} 中最常见、最有代表性的界面或内容场景，
将你的审美原则"落地"到每个场景中：

场景1：[描述场景]
- 这个场景中最重要的视觉元素是什么？为什么？
- 这个场景中最容易犯的审美错误是什么？
- 应用你的原则后，这个场景的理想状态是什么样的？

场景2：...
场景3：...

然后回答一个关键问题：
- 你的审美原则中有没有在这三个场景中产生相互矛盾的指引？如果有，如何裁决？

【Critique — "A/B测试思维"】
对每个场景，想象两个版本：
- 版本A：严格遵循你的审美原则
- 版本B：违反了其中一条原则，但在其他方面做得更好

问：版本B有没有可能在用户体验上实际优于版本A？如果有，这说明你的哪条原则需要增加例外条件？

这个步骤的目的不是推翻你的原则，而是识别原则的适用边界。
没有例外条件的原则往往是还没被真正测试过的原则。

【Refine】
为每条原则补充适用边界或例外条件。格式：
"原则X：[主体内容]。例外：当[条件]时，[调整方式]"

===== 第三轮：跨感官一致性 =====

【Generate — 完整审美语言定义】
将你的审美哲学扩展为一套完整的"设计语言"，覆盖以下维度（根据你的产品形态选择适用项）：

视觉语言：
- 色彩系统：主色、辅色、语义色（成功/警告/错误/中性）的具体定义和使用规则
- 排版系统：字体层级（标题/正文/辅助/代码）、行距、段距的比例关系
- 空间系统：间距的节奏感——什么时候紧凑、什么时候留白、留白的语义是什么

文字语言：
- 语气谱系：从最正式到最轻松，分别在什么场景使用
- 术语策略：行业术语的使用门槛——什么时候用术语、什么时候用白话
- 数字呈现：精度规则（小数几位）、单位、对比基准

交互语言：
- 反馈节奏：操作后多久给反馈、什么级别的操作需要确认、什么可以直接执行
- 状态传达：加载中、空状态、错误状态、成功状态各自的表达方式
- 信息密度：每屏信息量的上限和下限

【Critique — "一致性审计"】
检查以上定义中的一致性：
- 你的色彩系统和文字语气是否传达了同一种"人格"？
  （比如：如果色彩系统是冷静克制的，文字语气却是活泼热情的，就不一致）
- 你的空间系统（留白vs紧凑）和信息密度目标是否自洽？
- 你的术语策略和用户画像是否匹配？

标记不一致之处，分析根因——通常是因为不同维度在服务不同的目标，
而这些目标之间存在未被显式解决的张力。

【Refine — 最终输出】
输出最终版本的审美与呈现哲学。格式：

## 审美锚点
[2-3个具体参照物，每个说明参照的维度和原因]

## 核心呈现原则
[5-7条经过三轮打磨的原则，每条附带适用边界和例外条件]

## 信息架构
[三层结构的定义和层间晋升规则]

## 设计语言系统
[色彩/排版/空间/语气/交互的完整定义]

## 原则冲突裁决表
[当原则A和原则B冲突时，在什么条件下优先哪个]
```

## 组合使用指南

### 标准工作流

当你需要为一个新领域生成 System Prompt 时，推荐的执行顺序是：

第一步，用第二层精炼协议生成领域知识框架。这通常需要一轮完整的对话（让 AI 执行完整的三轮迭代）。

第二步，用第四层精炼协议生成审美与呈现哲学。同样需要一轮完整的对话。

第三步，将两份精炼后的输出嵌入通用框架的对应章节，再补充其他层（身份锚定、方法论、内容约定等），组装成完整的 System Prompt。

### 轻量工作流

如果时间有限，可以只执行每份协议的前两轮（跳过第三轮的压力测试）。两轮迭代已经能将输出从"教科书水平"提升到"有实战经验的从业者水平"，对于大多数场景已经足够。

### 超深度工作流

对于你最核心的领域（比如本项目的 A 股分析），可以在三轮迭代之后追加一步"真人校验"——将 AI 的最终输出交给一位真正的领域专家审阅，标注出 AI 的认知偏差，然后将这些校正反馈编码回 System Prompt。这种"AI 生成 + 人类校正"的循环，能达到单靠 AI 或单靠人类都无法达到的质量上限。

## 为什么是三轮，不是两轮或五轮

三轮不是一个随意的数字。它来自一个关于信息增益的经验观察：

第一轮迭代的信息增益最大。从零到有，建立基本结构，剔除最明显的低质量内容。这一轮大约贡献了总质量提升的50%。

第二轮迭代挖掘隐性知识。那些"做过才知道"的暗知识、反直觉认知和实战经验，是区分"教科书AI"和"专家级AI"的关键。这一轮大约贡献了30%的质量提升。

第三轮迭代做边界校验。通过极端场景和对抗性思考，确保框架不是一个只在理想条件下成立的"温室理论"。这一轮贡献了剩余的20%——看似最少，但这20%恰恰是"顶尖"和"优秀"之间的差距。

第四轮以后的边际收益急剧递减。AI 在同一个上下文窗口中的自我批判能力有天花板——到第三轮时，它已经穷尽了从训练数据中能提取的大部分专家级知识。继续迭代更可能产生"过拟合"（越改越窄）而非真正的深化。如果需要进一步提升，更有效的方式是引入外部信息（真人专家、新的参考资料），而非继续让 AI 自我对话。
