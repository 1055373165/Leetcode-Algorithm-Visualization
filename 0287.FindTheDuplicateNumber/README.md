# 287. Find the Duplicate Number：数组中的隐形链表

![寻找重复数动画](animation.mp4)

## 1. 审题（Problem）

### 1.1 约束解码
题目给定一个包含 $n + 1$ 个整数的数组 `nums`，所有数字都在 $[1, n]$ 范围内。由**鸽巢原理（Pigeonhole Principle）**可知，至少有一个数字重复。
我们的目标是找出这个重复数，但题目附加了三个极具挑战性的“硬约束”：
1.  **只读**：不能修改数组（意味着不能用排序或原地哈希）。
2.  **空间**：只能使用 $O(1)$ 的额外空间（意味着不能用哈希表/集合）。
3.  **时间**：如果不受限，暴力 $O(N^2)$ 可解。但通常面试要求 $O(N)$ 或 $O(N \log N)$。

### 1.2 边界陷阱
*   **重复次数**：重复的数字可能出现多次，不一定只是两次。
*   **数据范围**：数字是从 $1$ 到 $n$，这意味着数组下标 $0$ 永远不会被指向（因为没有值为 $0$ 的元素），这保证了我们从下标 $0$ 出发一定能进入环，而不会被卡死。

### 1.3 问题归类
乍一看这是**数组（Array）**问题。
如果允许修改，是**原地哈希（Index Mapping）**问题。
如果允许空间，是**哈希表（Hash Table）**问题。
但在严格约束下，这其实是一个伪装成数组的**链表环检测（Linked List Cycle Detection）**问题，即**快慢指针（Two Pointers）**。

## 2. 思维演化（Reasoning）

### 2.1 暴力解法
最朴素的方法是双重循环：对每个 `nums[i]`，检查是否存在 `nums[j] == nums[i]`。
*   时间复杂度 $O(N^2)$，显然会超时。

### 2.2 瓶颈分析 & 优化尝试
*   **尝试 1：排序**。如果数组有序，重复元素必相邻。
    *   代价：$O(N \log N)$ 时间，且修改了数组（违反约束）。
*   **尝试 2：哈希表**。遍历并记录出现过的数字。
    *   代价：$O(N)$ 空间（违反约束）。
*   **尝试 3：二分查找（值域二分）**。
    *   思路：我们在 $[1, n]$ 的**数值范围**内二分。例如猜一个数 $mid$，统计数组中 $\le mid$ 的数有多少个。如果数量 $> mid$，说明重复数在 $[1, mid]$ 区间；否则在 $[mid+1, n]$。
    *   代价：$O(N \log N)$ 时间，$O(1)$ 空间。这是一个符合所有约束的有效解法，但不是 $O(N)$ 的最优解。

### 2.3 终极优化：思维跳跃
我们需要 $O(N)$ 时间且 $O(1)$ 空间。这通常指向**双指针**。
观察数组的性质：值域 $[1, n]$ 恰好对应数组索引的子集。如果我们把 `index` 看作节点，把 `nums[index]` 看作 `next` 指针，这就构成了一个**链表**。
因为有重复数（例如 $x$ 出现了两次），意味着有两个不同的索引 $i$ 和 $j$，使得 `nums[i] == x` 且 `nums[j] == x`。也就是说，有两个节点指向了同一个节点 $x$。
在链表中，这意味着什么？**环（Cycle）**！而且 $x$ 就是**环的入口（Cycle Entrance）**。
于是，问题转化为了：**已知一个链表有环，求环的入口节点**。这正是 LeetCode 142. Linked List Cycle II。

## 3. 直觉培养（Intuition）

### 3.1 为什么能想到链表？
当看到“数组内容是数组下标的索引”这种映射关系（$index \to value$，$value$ 又是有效的 $index$）时，由于这一条映射链可以无限进行下去（$i \to nums[i] \to nums[nums[i]] \to \dots$），我们应该本能地联想到**图（Graph）**或**链表（Linked List）**的遍历。
又因为每个节点只有一个出度（每个位置只有一个值），所以这就形成了一个简单的线性结构，最终必然进入一个环（因为节点有限）。

### 3.2 类比心智模型
想象你在在一个只有 $1$ 到 $n$ 房间号作为路标的迷宫里。
*   你站在房间 $0$（起点）。该房间里写着“去房间 $nums[0]$”。
*   你按指示走，到了下一个房间，里面又写着下一个目的地。
*   因为肯定有重复的数字，意味着有两个不同的房间都指示你去同一个房间 $X$。
*   这就好比两条路汇合了。一旦汇合，之后的路径就是完全一样的，这就形成了一个圈。
*   从起点出发，你最终会陷入这个圈里无限循环。那个汇合点（环入口），就是我们要找的重复数。

### 3.3 弗洛伊德龟兔赛跑（Floyd's Tortoise and Hare）
这是一个寻找链表环的经典双指针算法。
1.  **相遇**：乌龟一次走一步，兔子一次走两步。如果有环，它们必然在环内某处相遇。
2.  **找入口**：相遇后，把其中一只动物放回起点，另一只留在相遇点。然后两只都一次走一步。它们再次相遇的地方，就是环的入口。

## 4. 代码实现（Solution）

### 4.1 核心代码（Go）

```go
func findDuplicate(nums []int) int {
	// 【核心转化】将数组问题转化为链表找环入口问题
	// index: 当前节点
	// value: next 指针指向的节点
	
	// Step 1: 快慢指针初始化
	slow, fast := 0, 0
	
	// Step 2: 寻找相遇点（Floyd's Cycle Finding Phase 1）
    // 因为必定有环，所以无限循环直到 break
	for {
		// slow 走一步: slow = nums[slow]
		slow = nums[slow]
		// fast 走两步: fast = nums[nums[fast]]
		fast = nums[nums[fast]]
		
		// 找到了环内的相遇点
		if slow == fast {
			break
		}
	}
	
	// Step 3: 寻找环入口（Floyd's Cycle Finding Phase 2）
	// 将快指针重置回起点，慢指针保持在相遇点
	// 此时两指针同速前进，相遇点即为环入口（即重复数）
	fast = 0
	for slow != fast {
		// 每次只走一步
		slow = nums[slow]
		fast = nums[fast]
	}
	
	return slow
}
```

### 4.2 复杂度分析
*   **时间复杂度**：$O(N)$。
    *   第一阶段（找相遇点）：快慢指针在环内相遇，步数不会超过链表长度。
    *   第二阶段（找入口）：只需要走“起点到入口”的距离，也不会超过链表长度。
    *   总体线性遍历。
*   **空间复杂度**：$O(1)$。只用了两个指针变量 `slow` 和 `fast`。

### 4.3 易错点与边界处理
1.  **数组越界**：题目保证了数字在 $[1, n]$，而数组长度是 $n+1$。这意味着索引范围是 $[0, n]$，所有值都是合法的跳转索引，不会越界。
2.  **死循环**：如果不包含重复数（不成环）怎么办？题目保证“至少一个重复数”，所以必定有环，不需要额外判空或判无环。
3.  **找错了点**：第一次相遇点**不是**重复数，必须要进第二阶段再次相遇才是。

### 5.2 核心思想沉淀
*   **数组即链表**：当数组元素的值域恰好在索引范围内时，数组可以看作是静态链表。
*   **时空权衡**：
    *   允许修改数组 $\to$ 原地哈希 $O(N)$。
    *   只读 + $O(1)$ 空间 $\to$ 二分查找 $O(N \log N)$ 或 快慢指针 $O(N)$。
    *   只读 + $O(N)$ 空间 $\to$ 哈希表 $O(N)$。

### 5.3 面试应答指南
如果面试官问“为什么快慢指针能找到入口？”，不要只背结论。简单证明：
设起点到入口距离为 $a$，入口到相遇点为 $b$，环剩余部分为 $c$。环长 $L = b + c$。
相遇时：
*   Slow 走了 $a + b$
*   Fast 走了 $a + b + kL$ （多走了 $k$ 圈）
*   Fast 速度是 Slow 两倍 $\to 2(a + b) = a + b + kL$
*   化简得 $a + b = kL \to a = kL - b$
*   $kL - b$ 也就是 $(k-1)L + (L-b)$，即“$k-1$ 圈加剩下的一段 $c$”。
*   结论：从相遇点走 $a$ 步（即 $c + (k-1)L$），恰好回到入口。同时从起点走 $a$ 步，也恰好到入口。所以相遇即入口。
